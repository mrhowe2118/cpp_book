# 洛谷提交与评测结果

**写完代码只是第一步，提交之后要能看懂评测机在说什么。**

这一节把九个评测结果和它们的排查方向讲清楚。

## 本节学会什么

- 知道完整的提交步骤和注意事项
- **看懂九个评测结果**，并知道每个该往哪查
- 会判断"本地对、洛谷错"的原因
- 会用洛谷的几个实用功能

## 为什么需要它

先看一个场景：

> 本地跑样例全对，提交后显示 **WA**。
> 于是盯着代码看半小时——什么也没看出来。

**问题在于：你不知道"WA 通常意味着什么"。**

::: exam 每个评测结果都指向一类问题
| 结果 | 你该先查 |
| --- | --- |
| WA | 输出格式 → 边界 → 类型溢出 |
| RE | 数组大小 / 下标 / 除零 |
| TLE | 复杂度 / 死循环 |
| CE | 报错第一条 |

**知道"往哪查"，比"再看一遍"有效得多。**
:::

## 提交步骤

```text
① 注册洛谷账号
② 找到题目 → 点"提交"
③ 语言选【C++17】（重要！）
④ 粘贴完整代码  ← 注意：不要只粘函数，要有 #include 和 main
⑤ 提交 → 看结果
```

::: pitfall 三件最容易出错的事
| 错误 | 后果 |
| --- | --- |
| 语言选成 C++98 / C++11 | 用了 C++17 语法就 **CE** |
| 只粘了部分代码 | **CE**（少 `#include` 或 `main`） |
| 把本地调试用的 `system("pause")` 一起提交 | **TLE**（程序卡住） |

**提交前扫一眼：语言是不是 C++17、代码是不是完整的、有没有调试语句。**
:::

## 九个评测结果

### 完整对照表

| 缩写 | 全称 | 含义 |
| --- | --- | --- |
| **AC** | Accepted | 通过 ✅ |
| **WA** | Wrong Answer | 答案不对 |
| **CE** | Compile Error | 编译失败 |
| **RE** | Runtime Error | 运行时崩溃 |
| **TLE** | Time Limit Exceeded | 超时 |
| **MLE** | Memory Limit Exceeded | 内存超限 |
| **OLE** | Output Limit Exceeded | 输出超限 |
| **UKE** | Unknown Error | 未知错误 |
| **PC** | Partially Correct | 部分正确（洛谷特有） |

::: exam 先分清"三类"再查
```text
① 程序没跑起来：  CE
② 程序跑了但崩了：RE / MLE / OLE
③ 程序跑完了但不对：WA / TLE / PC
```

**分类之后，要查的方向就窄了。**
:::

### 每个结果的排查方向

::: range CE —— 编译失败
**先看编译器给的第一条错误。**

| 常见原因 | 见哪一节 |
| --- | --- |
| 少分号、括号不配对、全角标点 | [常见编译错误速查](/appendix/compile-errors) |
| 缺 `#include` | 同上 |
| **变量名撞标准库**（`y1`/`next`/`time`…） | [编译关](/practice/five-gates/compile) |
| 用了 Windows 专有的 `conio.h` / `getch()` | 同上 |
| 语言标准选得太老 | 提交时选 C++17 |
:::

::: range WA —— 答案不对
**按这个顺序查**（从最常见的开始）：

| 顺序 | 查什么 | 怎么做 |
| --- | --- | --- |
| ① | **输出格式** | 末尾空格？换行？大小写？用 `diff` 对样例 |
| ② | **边界** | 测 `n=1`、全相同、含 0/负数 |
| ③ | **类型溢出** | 求和/乘法用了 `int`？ |
| ④ | **多组数据没清空** | 每组开头清了吗？ |
| ⑤ | **局部变量没初始化** | 每个变量声明时有初值吗？ |

**详见的排查清单：[结果关](/practice/five-gates/result)。**
:::

::: range RE —— 运行时崩溃
| 常见原因 | 症状 |
| --- | --- |
| **数组开小了** | 大测试点崩，小数据正常 |
| 下标越界（差一） | 偶尔崩、偶尔错 |
| 除以 0 | 特定数据崩 |
| 递归太深 | 大数据崩 |
| 栈溢出（大数组开在函数里） | 一跑就崩 |

**"有时崩有时不崩"基本可以断定是越界。**

**详见[资源关](/practice/five-gates/resource)。**
:::

::: range TLE —— 超时
**先分清是哪一种**：

| 类型 | 表现 | 原因 |
| --- | --- | --- |
| 复杂度不达标 | 大数据超时、小数据秒过 | 算法选错了 |
| 死循环 | 连样例都跑不出 | 循环变量不推进 |
| 常数太大 | 都慢一点 | `cin` 没加速、`memset` 太大 |

**判断"复杂度够不够"用[数据范围表就是给分表](/practice/data-range)的标尺。**

**详见[资源关](/practice/five-gates/resource)。**
:::

::: range MLE / OLE / UKE
| 结果 | 原因 | 怎么做 |
| --- | --- | --- |
| **MLE** | 数组开太大（**按声明算**） | 算内存：`sizeof × 个数` |
| **OLE** | 输出太多 | 检查调试输出、死循环输出 |
| **UKE** | 评测系统问题 | 重新提交；仍失败则反馈 |

**MLE 的关键：按你"声明"的空间算，不是按实际用的**（见[资源关](/practice/five-gates/resource)）。
:::

### PC：洛谷特有的"部分正确"

洛谷会把测试点**分组**，如果有一部分通过、一部分不通过，就显示 **PC**。

**这是好事**——说明你的程序在大方向上是对的，只是某些情况没考虑到。

**点进去看哪些测试点错了**，通常能发现规律（比如"都是大数据的点"→ 复杂度或溢出）。

## 关键过程与易错点

### 一、"本地对、洛谷错"的五个原因

::: exam 这是最让人困惑的一类，按概率排序
| 原因 | 怎么验证 |
| --- | --- |
| **① 样例太弱**（没测边界） | 自己造 `n=1`、最大、全相同 |
| **② 溢出** | 本地改小数据不会暴露，要用大数据测 |
| **③ 未初始化的局部变量** | 本地"恰好"是 0，评测机不是 |
| **④ 多组数据没清空** | 造**两组**数据本地测 |
| **⑤ 本地编译器更宽容** | 加 `-Wall -Wextra` 就能看到警告 |

**②③④ 都是"本地环境掩盖了问题"**——
**这就是为什么[测试与调试](/guide/testing-and-debugging)强调"手造边界数据"。**
:::

### 二、本地测试和在线评测的差别

| | 本地 | 洛谷 |
| --- | --- | --- |
| 编译标准 | 你自己定（**一定要用 C++17**） | 你选（**选 C++17**） |
| 数据 | 只有样例 | 完整测试数据（含边界、大数据） |
| 编译器宽容度 | MinGW 较宽容 | Linux g++ 较严格 |
| 时间限制 | 看你电脑 | 固定（通常 1 秒） |

**结论：本地通过 ≠ 提交通过。** 所以：

```text
本地测样例 → 本地测边界（五组） → 提交 → 看结果 → 定位
```

### 三、洛谷的实用功能

| 功能 | 用途 |
| --- | --- |
| **题目难度标签** | 入门/普及-/普及/提高-… 用来选难度合适的题 |
| **题单** | 别人整理的成体系题单（按专题刷题很有用） |
| **提交记录** | 看你以前所有提交，方便回顾 |
| **讨论区** | 看别人的思路（**但要先自己想**） |
| **题解** | 卡住 30 分钟之后再来看 |
| **公开赛** | 模拟比赛环境，练限时做题 |

::: pitfall 讨论区和题解的用法
**它们是好东西，但用法很关键：**

| ✅ 正确用法 | ❌ 错误用法 |
| --- | --- |
| 卡住 30 分钟后看思路 | 一上来就看 |
| 看完**合上重写一遍** | 看完就过 |
| 看"为什么"而不是"抄代码" | 直接复制粘贴 |

**详见[学习建议：怎么刷题](/appendix/learning-advice)。**
:::

### 四、提交前自查

::: exam 30 秒检查清单
```text
□ 语言选了 C++17
□ 代码完整（有 #include 和 main）
□ 没有 system("pause") / getch() / conio.h
□ 结尾有换行
□ 四道题都提交了（比赛时）
□ 看过一眼样例输出格式
```

**这 30 秒能挡掉相当一部分无效提交。**
:::

## 动手检查

1. 注册洛谷账号，提交 [P1001 A+B Problem](https://www.luogu.com.cn/problem/P1001)，确认显示 **AC**。
2. 故意把语言选成 C++98，提交一份用了 C++11 语法的代码，看 CE 信息。
3. 故意写一个数组越界的程序，提交看是不是 **RE**。
4. 故意写一个 O(n²) 去跑 `n = 10⁵`，提交看是不是 **TLE**。
5. 找一道你做过的题，点开提交记录，看每个测试点的用时和内存。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 提交一道入门题，拿到 AC | 走通流程 |
| 基础 | 故意制造 CE、WA、RE、TLE 各一次 | 认识四个结果 |
| 基础 | 点开一道题的测试点详情，看用时和内存 | 建立"数据量"的直觉 |
| 巩固 | 找一道 WA 的题，按本节的顺序逐条排查 | 系统化查错 |
| 巩固 | 参加一场洛谷公开赛 | 模拟比赛环境 |
| 挑战 | 用[对拍](/practice/stress-testing)找出一道 WA 的题的真实原因 | 自己定位问题 |

::: pitfall 建议：把"排查顺序"抄成卡片
```text
WA → ① 输出格式  ② 边界  ③ 溢出  ④ 多组数据清空  ⑤ 未初始化
RE → ① 数组开小  ② 下标越界  ③ 除零  ④ 递归太深
TLE → ① 复杂度  ② 死循环  ③ 常数太大
CE → ① 第一条报错
```

**考试时贴在显示器上。** 它把"瞎猜"变成了"按顺序查"。
:::
