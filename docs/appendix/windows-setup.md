# Windows 环境搭建

**第一件事是让代码跑起来。** 这一节给你两条路线：一条"5 分钟能用"，一条"长期专业"。

## 本节学会什么

- 在 Windows 上装好编译器，跑通第一个程序
- 知道几种常见方案的取舍
- 遇到"g++ 不是内部或外部命令"这类问题时能自己解决
- 知道**本地环境和考场环境（NOI Linux）的差别**

## 为什么需要它

[开始编程](/guide/getting-started)要求你：

```bash
g++ -std=c++17 -Wall -Wextra main.cpp -o main
```

**但在 Windows 上，默认是没有 `g++` 的。**

所以第一步是装一个。有三条路，先看对比：

| 方案 | 优点 | 缺点 | 适合 |
| --- | --- | --- | --- |
| **小熊猫 C++** | 一键安装、中文界面、内置编译器 | 功能相对简单 | ✅ **初学者首选** |
| Dev-C++ | 老牌、体积小 | **版本老旧**，默认标准可能太老 | 不推荐 |
| **VSCode + MinGW** | 专业、可扩展到任何规模 | 要配环境变量、配置稍麻烦 | ✅ 长期使用 |

::: exam 建议：先用小熊猫，再换 VSCode
**不要一上来就折腾 VSCode。**

- 小熊猫 C++ 装完就能写代码、编译、运行，**5 分钟**
- VSCode 要装编译器、配 PATH、装插件，**第一次可能要一小时**

**先用简单的把"写代码 → 跑起来"这条路走通**，
等你能独立写程序了，再花时间配 VSCode 也不迟。
:::

## 路线一：小熊猫 C++（推荐入门）

### 步骤

```text
① 搜索"小熊猫 C++"，进官网下载 Windows 版安装包
② 一路"下一步"安装（它自带编译器，不用另外装）
③ 打开软件 → 新建源文件 → 写代码 → 按 F11 编译并运行
```

**验证是否成功**：写下面这段，按 F11：

<!-- expect

---
Hello, Tom!
-->
```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "Hello, Tom!" << '\n';
    return 0;
}
```

看到 `Hello, Tom!` 就通了。

::: pitfall 检查编译标准是不是 C++17
小熊猫 C++ 默认的标准可能不是 C++17。**在设置里找到编译选项，确认是 C++17**。

**为什么重要**：本书和评测机都用 C++17。
如果你的本地标准更老，会出现"本地编不过但书写的是对的"这种困惑
（见[编译关](/practice/five-gates/compile)）。
:::

## 路线二：VSCode + MinGW（长期使用）

### 步骤概览

```text
① 装 MinGW-w64（提供 g++）
     - 搜索 "MinGW-w64" 或 "winlibs"，下载解压到某个目录（比如 C:\mingw64）
     - 注意：路径里不要有空格和中文

② 把 C:\mingw64\bin 加到系统环境变量 Path 里

③ 验证：打开 PowerShell，输入 g++ --version，能显示版本就成功

④ 装 VSCode，再装 C/C++ 扩展

⑤ 写代码 → 用命令编译运行（或配置调试）
```

**本书只需要你会这一条命令**：

```bash
g++ -std=c++17 -Wall -Wextra main.cpp -o main
.\main.exe
```

::: pitfall 三个最常见的坑
**① `g++ 不是内部或外部命令`**
→ `Path` 没配好，或者配完**没重启终端**。
检查：`echo $env:Path` 里有没有 `mingw64\bin`。

**② 编译报错但代码没错**
→ 检查文件扩展名。Windows 默认**隐藏扩展名**，所以你建的 `main.cpp`
实际可能叫 `main.cpp.txt`。**打开"显示文件扩展名"**。

**③ 中文输出乱码**
→ 源文件编码和终端编码不一致。**把源文件保存成 UTF-8**，
或者在程序开头加 `system("chcp 65001");`（但**交卷前一定要删掉**）。
:::

## 关键过程与易错点

### 一、本地环境和考场的差别

::: range 这几条差别会直接影响分数
| | 你的 Windows | 考场 NOI Linux |
| --- | --- | --- |
| 编译器 | MinGW 的 `g++` | Linux 的 `g++` |
| **文件名大小写** | **不区分** | **严格区分** |
| 路径分隔符 | `\` | `/` |
| 可执行文件 | `main.exe` | `main` |
| 运行方式 | `.\main.exe` | `./main` |
| 扩展名 | **默认隐藏**（危险） | 通常显示 |
| 专有函数 | 有 `conio.h`、`getch()` | **没有** |

**其中三条会直接导致 0 分**（大小写、扩展名、专有函数）——
详见[编译关](/practice/five-gates/compile)和[收录关](/practice/five-gates/collection)。
:::

### 二、编译命令的含义

```bash
g++ -std=c++17 -Wall -Wextra main.cpp -o main
```

| 部分 | 含义 |
| --- | --- |
| `g++` | 调用 C++ 编译器 |
| `-std=c++17` | 使用 C++17 标准（**必须写**） |
| `-Wall -Wextra` | 打开大部分警告（**强烈建议**） |
| `main.cpp` | 源文件 |
| `-o main` | 输出的可执行文件名 |

::: exam 把这条命令固定下来
**每次编译都用它**，包括 `-Wall -Wextra`。

`-Wall` 会指出"评测机会报错、而你本地被放过"的地方——
**这是零成本的保险**（见[编译关](/practice/five-gates/compile)）。

建议在编辑器/IDE 里把它设成默认编译选项，省得每次手打。
:::

### 三、用什么写代码

| 工具 | 适合 |
| --- | --- |
| 小熊猫 C++（自带编辑器） | 入门 |
| VSCode | 长期、多语言 |
| 记事本 | ❌ **不要用**（没有行号、没有高亮、容易存成 `.txt`） |

**不管用什么，记住两条**：

1. 保存成 `.cpp`（**打开"显示文件扩展名"确认**）
2. 用 `g++ -std=c++17 -Wall -Wextra` 编译

### 四、调试输出只在本地用

```cpp
system("pause");          // 本地调试时防止窗口一闪而过
system("cls");            // 清屏
```

::: pitfall 这些是 Windows 专有，交卷前必须删
| 写法 | 在评测机上 |
| --- | --- |
| `system("pause")` | 程序会卡住直到超时（**TLE**） |
| `#include <conio.h>` | **编译错误**（没有这个头文件） |
| `getch()` / `kbhit()` | **编译错误** |

**纪律：交卷前全局搜索 `system`、`conio`、`getch`、`kbhit`，全部删掉。**
:::

## 动手检查

1. 装好环境，跑通 `Hello, Tom!`。
2. 运行 `g++ --version`，确认编译器版本。
3. 在文件资源管理器里**打开"显示文件扩展名"**，确认你的源文件是 `.cpp`（不是 `.cpp.txt`）。
4. 故意把 `main.cpp` 改成 `Main.cpp`，看本地能不能编译（Windows 可以，Linux 不行）。
5. 用 `-Wall -Wextra` 编译一段有隐患的代码，看它会给出什么警告。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 装好环境并跑通第一个程序 | 走通流程 |
| 基础 | 故意删掉一个分号，读一遍报错 | 学会看报错 |
| 基础 | 用 `-Wall -Wextra` 编译一个未初始化变量的程序 | 看警告 |
| 巩固 | 按照[开始编程](/guide/getting-started)的步骤，完成一次洛谷提交 | 完整闭环 |
| 挑战 | 装一个 WSL 或 NOI Linux 虚拟机，在真正的 Linux 环境里编译一次 | 提前适应考场 |

::: pitfall 最后一条最值得做
**考场用的是 NOI Linux**，和你平时用的 Windows 差别不小。

如果条件允许，**提前装一个 Linux 环境练几次**（WSL 最省事）。
至少要知道：

- 文件名**区分大小写**
- 用 `./main` 运行（不是 `.\main.exe`）
- 编译命令一样，但 `-o` 出来的文件没有 `.exe`

**见过一次，考场上就不会慌。**
:::
