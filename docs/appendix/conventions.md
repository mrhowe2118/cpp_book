# 本书约定与符号

**阅读时遇到不认识的写法，翻到这里。** 这一节也是这本"书"的说明书。

## 本书的技术约定

### 语言与工具

| 项 | 约定 |
| --- | --- |
| 语言标准 | **C++17**（所有章节统一） |
| 编译器 | `g++` |
| 编译命令 | `g++ -std=c++17 -Wall -Wextra main.cpp -o main` |
| 目标赛事 | CSP-J/S（以及以它为基础的 NOIP 系列）入门阶段 |

::: range 为什么强调 C++17
1. 评测机可能默认按 **C++14** 编译（见[编译关](/practice/five-gates/compile)）
2. 本书示例用了 C++17 特性（如结构化绑定 `auto [x, y] = p;`）
3. **本地和评测机用同一个标准，才能保证行为一致**

**如果你在别处看到 `#include <bits/stdc++.h>`**，
那是常见的竞赛写法，本书**故意不用**（原因见下）。
:::

::: pitfall 本书为什么统一用显式 `#include`
`bits/stdc++.h` 能一次包含几乎所有头文件，很省事。但本书不用它，理由有三：

1. **它把标准库全部拉进来，撞名的机会大幅增加**（见[编译关](/practice/five-gates/compile)）
2. **编译更慢**
3. **某些版本下它自身可能有缺陷**

**显式 `#include` 还能让你记住"每个工具来自哪里"**，这对初学者更有价值。

**你自己写题时用不用它都行**，只要知道代价。
:::

## 代码风格约定

| 项 | 约定 | 说明 |
| --- | --- | --- |
| 缩进 | **4 个空格** | 不用 Tab |
| 大括号 | 左括号跟在 `)` 后，右括号独占一行 | |
| 数组下标 | **推荐 `1 ~ n`** | 一节之内只用一种 |
| 数组定义 | 开在**全局**，用 `const int MAXN` | 避免栈溢出 |
| 变量名 | 竞赛风格短名（`n` `m` `cnt` `ans` `mx`） | **不用标准库名字** |
| `using namespace std;` | 写在 `#include` 之后 | 本书统一使用 |

::: exam 为什么推荐下标从 1 开始
```cpp
const int MAXN = 100005;
int a[MAXN];

for (int i = 1; i <= n; i++) cin >> a[i];        // 下标 1 ~ n
```

理由：

1. **下标和"第几个"直接对应**，读代码时不用做 `+1` 转换
2. **前缀和、差分从 1 开始不用特判边界**（`s[i-1]` 在 `i=1` 时也能正常跑）

代价是 `a[0]` 空着不用——**完全值得**。
:::

## 常用符号

| 符号 | 含义 | 例子 |
| --- | --- | --- |
| `≤` `≥` | 小于等于 / 大于等于 | `n ≤ 10⁵` |
| `×` | 乘 | `10⁵ × 4 字节` |
| `10⁵` | 十万（上标表示幂） | 等价于 `100000` |
| `O(n)` | 时间复杂度 | 见[复杂度直觉](/guide/complexity-intuition) |
| `→` | 推导 / 指向 | `n 的量级 → 目标复杂度` |
| ✅ ❌ ⚠️ | 正确 / 错误 / 注意 | |
| ⭐ | 重点 | |

::: range 复杂度记号的读法
| 写法 | 读作 | 含义 |
| --- | --- | --- |
| `O(1)` | 常数复杂度 | 和数据量无关 |
| `O(log n)` | 对数复杂度 | 每次减半（二分） |
| `O(n)` | 线性复杂度 | 和数据量成正比 |
| `O(n log n)` | | 排序级别 |
| `O(n²)` | 平方复杂度 | 双重循环 |
| `O(2ⁿ)` | 指数复杂度 | 枚举所有子集 |

**本书里的"复杂度"都指时间复杂度**，空间复杂度会明确说"空间"。
:::

## 术语表

::: range 赛事与评测
| 术语 | 含义 |
| --- | --- |
| **CSP-J / CSP-S** | 入门级 / 提高级认证（本书面向的范围） |
| **初赛 / 复赛** | 第一轮笔试 / 第二轮机试 |
| **洛谷** | 常用的在线评测平台 |
| **评测机** | 判你代码的机器 |
| **AC** | Accepted，通过 |
| **WA / CE / RE / TLE / MLE** | 各种不通过（见[洛谷提交与评测结果](/appendix/luogu-judge)） |
| **测试点** | 一组输入数据 + 标准答案 |
| **Subtask** | 一组测试点，通常按数据规模分档给分 |
:::

::: range 做题相关
| 术语 | 含义 |
| --- | --- |
| **暴力** | 能过小数据、但复杂度不够的写法 |
| **正解** | 出题人期望的、能拿满分的算法 |
| **骗分 / 部分分** | 在不会正解时按数据档拿分（见[骗分与部分分](/practice/partial-score)） |
| **打表** | 把答案硬编码进程序 |
| **对拍** | 用暴力验证正解（见[对拍与随机数据](/practice/stress-testing)） |
| **边界** | 最小/最大/特殊的数据情况 |
| **溢出** | 数值超出类型的表示范围（见[数据类型与溢出](/guide/data-types)） |
:::

::: range 代码相关
| 术语 | 含义 |
| --- | --- |
| **栈** | 后进先出的结构；也指内存里存放局部变量的区域 |
| **爆栈** | 栈空间不够，程序崩溃 |
| **迭代器** | 遍历容器的"通用指针"（见[迭代器与区间](/stl/iterators)） |
| **区间** | 一对迭代器 `[begin, end)`，左闭右开 |
| **严格弱序** | 比较函数必须满足的规则（见[sort](/stl/sort)） |
| **记忆化** | 把算过的结果存下来（见[递归](/guide/recursion)） |
| **恢复现场** | 回溯时撤销标记（见[递归与枚举](/guide/recursion-enumeration)） |
:::

## 关于书中的示例代码

::: exam 本书示例是真的跑过的
**每个完整的示例程序都经过编译和运行验证。**

具体保证是（由 `npm run examples` 自动检查）：

| 保证 | 说明 |
| --- | --- |
| ① **完整程序必须编译通过** | 有 `main` 的代码块，必须能用 `g++ -std=c++17 -Wall -Wextra` 编译 |
| ② **带期望输出的示例必须真跑出那个输出** | 逐字符比对 |
| ③ 正文示意片段**尽力编译** | 编不过只登记，不阻断（它们是片段，不是完整程序） |
| ④ 有意写错的代码**标出来** | 比如"`void main()` 会报错"，这类标记为不编译 |

**所以你可以放心照着示例敲——它们不是伪代码。**
:::

::: range 示例里的几个约定
| 约定 | 含义 |
| --- | --- |
| `// ✗` | 错误写法（**不要这么写**） |
| `// ✅` / `// ✓` | 正确写法 |
| `...` 出现在代码里 | 表示"这里省略了一些代码" |
| `输入` / `输出` 标记的代码块 | 分别是样例输入和期望输出 |

**看到 `...` 的代码块是"示意片段"，不要直接复制去编译。**
:::

## 反馈与勘误

::: range 发现错误怎么办
这本书的内容会持续更新。如果你发现：

| 类型 | 例子 |
| --- | --- |
| **示例代码跑不通** | 编译报错、输出和书上不一致 |
| **说法有误** | 概念讲错了、规则过时了 |
| **链接失效** | 洛谷题号找不到 |
| **前后矛盾** | 两节说法不一致 |

**欢迎反馈。** 尤其是"示例代码跑不通"这类——它最影响学习体验。

**特别提醒**：涉及**具体认证规则**的内容（目录结构、提交方式、文件名要求）
**各省不同、逐年可能变**，**一律以你所在省份当年的官方须知为准**。
:::
