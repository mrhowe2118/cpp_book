# 学习路线与节奏

**"我该先学什么、学多久、怎么知道可以往下走"**——这一节回答这三个问题。

## 本节学会什么

- 拿到一条从零到 CSP-J 的分阶段路线
- 知道每个阶段的**目标**和**验收标准**
- 知道每个阶段大概要多久
- 遇到"学不动了"时知道该检查哪里

## 为什么需要它

初学信奥最常见的问题不是"不努力"，而是**顺序错了**：

| 常见错误 | 后果 |
| --- | --- |
| 语法还没熟就学动态规划 | 代码写不出来，误以为"DP 太难" |
| 一路往前学，从不回头复习 | 学了后面忘前面 |
| 一直做简单题，不碰难题 | 考试一遇到就懵 |
| 一直做难题，不巩固基础 | 基础题丢分，总分不高 |

::: exam 学算法不是"收集知识点"
**它是盖楼：每一层都压在前一层上。**

```text
语法不熟 → 写不出代码 → 学算法时把"写不出来"误判成"算法难"
```

**所以路线的意义是：让你知道现在站在第几层，以及下一步该干什么。**
:::

## 五个阶段

### 阶段一：语法基础（第 1～11 节）

| 项 | 内容 |
| --- | --- |
| **目标** | 能独立写出"读入 → 计算 → 输出"的完整程序 |
| **内容** | 环境、变量、类型、输入输出、分支、循环、数组 |
| **验收** | [基础语法单元练习](/guide/syntax-exercises)的过关门槛 |
| **预计** | 4～8 周（每周 3～5 次，每次 1～2 小时） |

::: pitfall 这一阶段最常见的错误是"跳步"
"循环我懂了" → 跳过练习 → 直接学数组。

**结果是数组题写不出来，还以为是数组难。**

**这一阶段唯一的验收方式：不看资料，独立写出程序。**
:::

### 阶段二：数据组织（第 12～20 节）

| 项 | 内容 |
| --- | --- |
| **目标** | 能处理"一批数据"和"文本" |
| **内容** | 二维数组、前缀和、结构体、排序、字符串 |
| **验收** | [控制与数据单元练习](/guide/control-and-data-exercises)的过关门槛 |
| **预计** | 4～6 周 |

**这一阶段的标志性能力**：写一道题时知道该开几个数组、该不该用结构体、
排序要不要自定义规则。

### 阶段三：函数与算法思维（第 21～28 节）

| 项 | 内容 |
| --- | --- |
| **目标** | 会把逻辑封装，能用递归枚举所有情况 |
| **内容** | 函数、参数与引用、递归、递归与枚举 |
| **验收** | [递归练习](/guide/recursion-exercises)的过关门槛（全排列 + 汉诺塔） |
| **预计** | 3～5 周 |

**这一阶段是"分水岭"**：过了它，你就能学真正的算法了。

### 阶段四：STL 与算法（STL 部分 + 基础算法）

| 项 | 内容 |
| --- | --- |
| **目标** | 用现成工具写题，掌握 CSP-J 的核心算法 |
| **内容** | STL 全套 + 排序、二分、前缀和差分、贪心、搜索、简单 DP |
| **验收** | 能独立做出 CSP-J 第二轮的 T1、T2 |
| **预计** | 2～4 个月 |

::: range 这一阶段的算法学习顺序建议
```text
① 排序与二分      ← 最常用，先学
② 前缀和与差分    ← 一次学会两个
③ 贪心            ← 思辨性强，多做题
④ 搜索（DFS/BFS）  ← 承接递归
⑤ 简单动态规划    ← 最后学，前面都熟了才顺
⑥ 基础数据结构    ← 栈、队列、并查集、堆
```

**不要跳着学。** 尤其是动态规划，它对前面的要求最高。
:::

### 阶段五：考前冲刺

| 项 | 内容 |
| --- | --- |
| **目标** | 把已经会的分全部拿到手 |
| **内容** | [考前实战](/practice/)整段 |
| **验收** | 限时 4 小时做完一套完整卷，五道关全部自检通过 |
| **预计** | 考前 2～4 周 |

**这一阶段不学新算法**（除了查漏补缺），重点是**减少失误**。

## 时间预算参考

::: range 从零到 CSP-J 一等大概要多久
| 起点 | 大概时间 | 说明 |
| --- | --- | --- |
| 完全零基础 | **6 个月～1 年** | 每周稳定投入 6～10 小时 |
| 学过一点编程 | 3～6 个月 | 语法阶段可以压缩 |
| 已有算法基础 | 1～3 个月 | 主要补 CSP-J 的题型和考前实战 |

**注意"稳定"两个字比"总量"更重要。**

每周 3 小时坚持一年，远好过暑假每天 8 小时然后停三个月。
:::

## 每个阶段的"可以往下走"信号

::: exam 不要凭"感觉懂了"往下走
| 阶段 | 可以往下走的信号 |
| --- | --- |
| 一 → 二 | 不看资料能默写出**程序骨架、分支、循环、数组**；[单元练习①](/guide/syntax-exercises)过关 |
| 二 → 三 | 能独立写出**多关键字排序**和**前缀和**；[单元练习②](/guide/control-and-data-exercises)过关 |
| 三 → 四 | 能独立写出**全排列**和**汉诺塔**；[递归练习](/guide/recursion-exercises)过关 |
| 四 → 五 | 能独立做出**CSP-J 第二轮 T1 和 T2** |
| 五 → 考试 | 限时模拟卷能稳定拿到目标分数，且**五道关自检全部通过** |

**每个信号都是"动手能验证"的，不是"我觉得"。**
:::

## 卡住了怎么办

| 症状 | 真正的原因 | 怎么办 |
| --- | --- | --- |
| 算法看不懂 | 前置语法/思维不熟 | **回退一个阶段** |
| 题做不出来 | 练得太少，或跳过了基础题 | 降难度，先做 20 道能独立做出来的 |
| 学了就忘 | 没有复习 | 建立错题本，每两周回头做一遍 |
| 越学越烦 | 强度太大 / 没有正反馈 | **降低单位强度**，多做"能过"的题 |
| 代码总出错 | 环境或习惯问题 | 见[Windows 环境搭建](/appendix/windows-setup)、[测试与调试](/guide/testing-and-debugging) |

::: pitfall "每天刷 10 道题"可能是有害的
如果那 10 道题里有 8 道是**看题解做出来的**，你练的是"看懂题解"，不是"做题"。

**正确比例**（大致）：

- 60% 能独立做出来（巩固）
- 30% 要想一会儿但能推出（成长）
- 10% 完全不会，看题解学习（拓展）

**详见[学习建议：怎么刷题](/appendix/learning-advice)。**
:::

## 动手检查

1. 判断自己现在在哪个阶段（用"可以往下走的信号"逐条自测）。
2. 写出你这一周的**固定学习时段**（不是"有空就学"）。
3. 找一个卡住你的知识点，判断是"这个知识点难"还是"前置不熟"。
4. 定一个**两周后的验收目标**（具体到"能独立做出 XX 题"）。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 用上面的信号表给自己定位 | 认清起点 |
| 基础 | 写下接下来 4 周的学习计划（每周学哪几节 + 做多少题） | 计划能力 |
| 巩固 | 回头做一遍上一阶段的"过关门槛"，确认真的过关了 | 查漏 |
| 巩固 | 定一个"两周后我能独立做出 XX 题"的目标，两周后验证 | 用验收代替感觉 |

::: exam 一句话总结这一节
**别问"我学到哪了"，问"我能独立做出什么了"。**

前者是感觉，后者可以验证。
:::
