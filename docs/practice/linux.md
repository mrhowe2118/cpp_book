# 评测环境与 Linux 命令

考场不是 Windows。**你熟悉的那些操作，在 NOI Linux 上有些能用，有些完全不成立。**

这一节把"上了考场会用到的命令"过一遍——**不要到了考场才开始学 `ls`。**

## 本节学会什么

- 认清 Windows 和 NOI Linux 的关键差异（有几种会直接导致 0 分）
- 掌握建目录 → 写代码 → 编译 → 运行 → 比对输出这五个动作的命令
- 会用 `diff` 自己比对输出，不用一条一条肉眼核对
- 知道 Linux 下最容易踩的几个坑

## 为什么需要它

一个真实的场景：

> 学生平时在小熊猫 C++ 上写代码，一切顺利。
> 进了考场，打开 NOI Linux 的终端，第一件事就卡住了——**不知道怎么建文件夹。**

::: exam 这类失分和算法完全无关，但代价一样大
Linux 命令不是知识点，是**工具**。工具不熟，你的算法能力就传达不出去。

好消息是：**这一节需要的命令只有十几个**，练两个小时就够用了。
:::

## Windows 与 NOI Linux 的关键差异

| | Windows（你的电脑） | NOI Linux（考场） | 会不会导致 0 分 |
| --- | --- | --- | --- |
| 文件名大小写 | **不区分**（`Apple.cpp` = `apple.cpp`） | **严格区分** | ✅ **会** |
| 路径分隔符 | `\` | `/` | ✅ 会（编译错误） |
| 换行符 | CRLF（`\r\n`） | LF（`\n`） | ⚠️ 有时会 |
| 文件名长度 | 宽松 | 严格 | ❌ 不会 |
| 可执行文件 | `main.exe` | `main`（无后缀） | ❌ 不会，但会困惑 |
| 运行方式 | 双击 / 点运行 | `./main` | ❌ 不会 |
| 扩展名隐藏 | 默认隐藏 | 通常显示 | ✅ **会**（`x.cpp.txt`） |

::: pitfall "大小写不区分"是 Windows 给你埋的雷
在 Windows 上，你写 `freopen("Apple.in", ...)` 而实际文件叫 `apple.in`——**照样能跑**。

到了 Linux，它**打不开文件**：程序读到空数据，输出错误答案，单题 0 分。

**这就是"本地全过、评测机 0 分"的经典成因之一。**
:::

## 最小可运行示例：五个动作

假设题目要求读 `apple.in`、写 `apple.out`，文件名必须是小写。

### ① 建目录并进入

```bash
mkdir -p ~/test/apple      # 建目录（-p 表示父目录不存在也一起建）
cd ~/test/apple            # 进入目录
pwd                        # 显示当前在哪
```

### ② 写代码

```bash
nano apple.cpp             # 打开编辑器（最简单，推荐考场用）
```

在 `nano` 里：直接打字 → `Ctrl + O` 保存 → 回车确认 → `Ctrl + X` 退出。

### ③ 编译

```bash
g++ -std=c++17 -Wall -Wextra apple.cpp -o apple
```

**没有输出就是成功。** 有输出说明编译失败，读第一条报错。

### ④ 造一个输入文件并运行

```bash
echo "3 4" > apple.in      # 把 "3 4" 写进 apple.in
./apple                    # 运行（./ 表示当前目录）
cat apple.out              # 看输出文件的内容
```

### ⑤ 和正确答案比对

```bash
echo "7" > answer.txt      # 手工写下正确答案
diff apple.out answer.txt  # 比对：没有输出 = 完全一致
```

::: range 这五个动作，就是你在考场上的全部操作
```text
mkdir → cd → nano → g++ → ./程序 → diff
```

**练熟这一条链，你在考场上的效率会和在家一样。**
:::

## 关键过程与易错点

### 常用命令速查

| 想干什么 | 命令 | 说明 |
| --- | --- | --- |
| 看当前目录有什么 | `ls` | `ls -l` 看详细信息 |
| 看当前路径 | `pwd` | 迷路了就用它 |
| 进目录 / 回上级 | `cd 名字` / `cd ..` | `cd ~` 回主目录 |
| 建目录 | `mkdir 名字` | `-p` 一次建多层 |
| 复制 / 改名 | `cp a b` / `mv a b` | `mv` 也可用来移动 |
| 删除文件 | `rm 文件` | **删了就没了，没有回收站** |
| 删除目录 | `rm -r 目录` | ⚠️ 危险，确认路径再敲 |
| 看文件内容 | `cat 文件` | 短文件用；长文件用 `less` |
| 分页看文件 | `less 文件` | `q` 退出 |
| 编辑文件 | `nano 文件` | 考场首选 |
| 编译 | `g++ -std=c++17 a.cpp -o a` | |
| 运行 | `./a` | 前面的 `./` 不能省 |
| 比对文件 | `diff a b` | 无输出 = 一致 |

::: pitfall 三条安全纪律
1. **`rm` 没有回收站。** 敲之前先 `pwd` 和 `ls` 确认自己在哪、要删什么。
   尤其别敲 `rm -r *`。
2. **`-o` 后的名字不要和源文件同名。** `g++ a.cpp -o a.cpp` 会**覆盖掉你的源代码**。
3. **路径里不要用空格和中文。** 空格要转义，中文可能编码不一致，都是不必要的麻烦。
:::

### 编辑器：考场用 `nano` 就够了

| 编辑器 | 学习成本 | 适合 |
| --- | --- | --- |
| **`nano`** | 5 分钟 | ✅ **考场推荐**：底部有快捷键提示，不会"进去出不来" |
| `vim` | 几小时 | 熟练的话很快，但**不熟练会拖垮你** |
| `gedit` | 接近记事本 | 有图形界面时最舒服 |

::: pitfall 不要为了"显得专业"在考场上用 vim
如果你不熟练，会出现这种情况：**打开了文件，打不了字，也退不出去。**

考场上的每一分钟都很贵。**用你最熟的那个**，nano 完全够用。
:::

### `diff`：比肉眼可靠得多

题目给的样例输出通常是这样的：

```text
7
```

你自己 `cat apple.out` 看到 `7`，觉得对了——但如果实际输出是 `7 `（多一个空格）
或者 `7` 后面多了一行空行，**你肉眼看不出来，评测机会判 WA**。

```bash
diff apple.out answer.txt
```

- **没有任何输出** = 完全一致 ✅
- 输出 `<` 和 `>` 的行 = 不一致，`<` 是你的，`>` 是标准答案 ❌

::: exam 养成"用 diff 对样例"的习惯
不要用眼睛比对输出。**眼睛会漏掉末尾空格和多余空行**，`diff` 不会。

**这是零成本、高收益的一个动作。**
:::

### 换行符的坑

Windows 的文本文件用 `\r\n` 换行，Linux 用 `\n`。

如果你在 Windows 上写好代码，拷到 Linux 编译，**通常没问题**（编译器能处理）。
但如果报出莫名其妙的错误，或者输出文件莫名多了 `^M`，可以用：

```bash
sed -i 's/\r$//' apple.cpp      # 去掉行尾的 \r
```

**更省事的办法：直接在 Linux 环境里写代码。** 别在 Windows 和 Linux 之间来回拷。

### 考场上的非技术准备

这些和代码无关，但同样影响成绩：

- **每 10 分钟存盘一次**（`Ctrl + O`）。考场电脑可能死机或被还原
- **知道自己在哪个盘、哪个目录**。有些考场会把数据盘还原，确认你的答题盘位置
- **遇到电脑故障立刻举手**，不要自己重启折腾——**时间损失是自己的**
- **不要依赖考场电脑上"上次留下的"文件**，那是别人的

1. 如果你有 Linux 环境（NOI Linux 虚拟机、WSL 都行），
   把上面"五个动作"完整敲一遍，不看资料。
