# 结果关：答案对了，分数没来

::: gate 第 4 关 · 结果关
**算法没错、文件没错、程序也正常跑完了，分数还是没了。**

这一关的失败形式是**部分测试点 0 分**：你有分，但拿不满。
:::

## 本节学会什么

- 认出"看似正确"的六类结果错误
- 学会用一台真实的漏洞演示理解**多组数据没清空**
- 知道边界该测哪些情况
- 拿到一份结果关自查清单

## 为什么需要它

前三关是"全有或全无"：交了才有分，编译过才有分，读到文件才算数。

这一关不一样——**程序会正常跑完、打印出结果、甚至样例全过**，只是结果不对。

最要命的地方在于：

> **样例太小，看不出错误。**

样例往往是 `n = 3`、`n = 5`，你的代码在这些小数据上完全正确。
真正的数据是 `n = 10⁵`，边界情况全在角落里等着。

::: exam 结果关的判断标准
不要问"样例过了吗"，要问这三个问题：

1. **多组数据**时，第二组会不会被第一组污染？
2. **边界**（`n = 1`、全相同、最大）我测过吗？
3. **输出格式**（空格、换行、大小写）和题目要求一字不差吗？
:::

## 最小可运行示例：一个真实的漏洞

先看这段代码。它要统计**每组数据里有多少个不同的数**：

<!-- expect
2
3
1 2 3
3
4 5 6
---
3
6
-->
```cpp
#include <iostream>
#include <cstring>
using namespace std;

const int MAXN = 105;
int cnt[MAXN];     // 标记桶：cnt[x] 表示 x 出现过

int main() {
    int T;
    cin >> T;
    while (T--) {
        int n;
        cin >> n;
        // ✗ 这里少了一行：忘了清空 cnt
        for (int i = 0; i < n; i++) {
            int x;
            cin >> x;
            cnt[x]++;
        }
        int ans = 0;
        for (int i = 0; i < MAXN; i++)
            if (cnt[i]) ans++;
        cout << ans << '\n';
    }
    return 0;
}
```

输入两组数据，每组都是 `1 2 3` 和 `4 5 6`，正确答案应该是 `3` 和 `3`。
**程序输出的是 `3` 和 `6`。**

::: pitfall 为什么第二组变成了 6
第一组结束后，`cnt` 里还留着 `1 2 3` 的标记。
第二组只加了 `4 5 6`，于是桶里一共有 **六个** 数——程序"诚实"地数了六个。

**局部变量不会自动清零，全局数组也不会。** 只有 `main` 外的全局变量会初始化为 0，
但**它们只在程序启动时初始化一次**，多组数据之间不会重置。
:::

### 修好它

<!-- expect
2
3
1 2 3
3
4 5 6
---
3
3
-->
```cpp
#include <iostream>
#include <cstring>
using namespace std;

const int MAXN = 105;
int cnt[MAXN];

int main() {
    int T;
    cin >> T;
    while (T--) {
        memset(cnt, 0, sizeof(cnt));   // ✓ 每一组开始前清空
        int n;
        cin >> n;
        for (int i = 0; i < n; i++) {
            int x;
            cin >> x;
            cnt[x]++;
        }
        int ans = 0;
        for (int i = 0; i < MAXN; i++)
            if (cnt[i]) ans++;
        cout << ans << '\n';
    }
    return 0;
}
```

**两段代码只差一行，得分是 0 分和满分的区别。**

## 关键过程与易错点

### 一、输出格式

这是最"冤"的一类：你的答案每个数都对，但因为格式判 WA。

| 问题 | 例子 | 说明 |
| --- | --- | --- |
| 多输出空格 | 输出 `1 2 3 `（末尾多一个空格） | 有些题严格比对，末尾空格也算错 |
| 少/多换行 | 结尾没换行、或者多打一行 | `'\n'` 结尾是安全习惯 |
| 大小写 | 要求 `Yes`，输出 `YES` | **逐字符比对，大小写敏感** |
| 中文标点 | 输出 `答案：5` 而不是 `5` | 只输出题目要求的数字 |
| 多余提示语 | 输出 `请输入n：` | 评测机只读取答案部分之外的内容会判错 |

::: pitfall 别输出任何"给人看"的东西
`cout << "请输入n：";`、`cout << "答案是：" << ans;` 这类都不行。

**评测机不是人，它只会逐字符比对。** 只输出题目要求的内容，一个字符都不多。
:::

### 二、多组数据没清空

就是上面演示的那个问题。需要注意清空的东西：

| 要清空的 | 用什么 |
| --- | --- |
| 整数数组、标记桶 | `memset(a, 0, sizeof(a))` |
| 计数、累加变量 | 重新赋初值 |
| 数组的有效长度 | 重新读入时覆盖 |
| `vector` | `v.clear()` |
| 答案变量 | 每轮重新初始化 |

::: range 一开始就写对，比事后检查更省事
**把清空放在每组数据的开头**，而不是结尾。理由：

- 放在开头，`T` 组数据一律清空，不会漏
- 放在结尾，最后一组之后白白清一次，而且容易漏掉"第一组之前"

<!-- no-compile -->
```cpp
while (T--) {
    memset(cnt, 0, sizeof(cnt));   // ← 先清空，再处理
    ...
}
```
:::

### 三、局部变量未初始化

```cpp
int n;
cin >> n;
int sum;              // ✗ 里面是垃圾值
for (int i = 0; i < n; i++) sum += a[i];
```

`sum` 的值是**内存里恰好残留的东西**，可能是 0，也可能是几百万。
它在你的电脑上可能是 0，在评测机上不是。

**纪律：变量声明时就赋初值。**

```cpp
int sum = 0;          // ✓
```

### 四、溢出

这一类在 [数据类型与溢出](/guide/data-types) 里已经展开讲过，这里只列症状：

| 症状 | 原因 | 改法 |
| --- | --- | --- |
| 小数据对、大数据错 | 求和溢出 `int` | 累加变量用 `long long` |
| 差一个数量级 | 两个 `int` 相乘 | 乘之前先转 `long long` |
| 输出一个"毫无规律的数" | 有符号整数溢出 | 同上 |

**看到"小数据对、大数据错"，先怀疑溢出。**

### 五、浮点比较

```cpp
double a = 0.1 + 0.2;
if (a == 0.3) { }        // ✗ 永远不成立
```

浮点数有精度误差。**要比较就用容差：**

<!-- no-compile -->
```cpp
if (fabs(a - 0.3) < 1e-8) { }   // ✓
```

::: pitfall 输出浮点数要按题目要求控制位数
题目要求"保留 2 位小数"，就写：

<!-- no-compile -->
```cpp
printf("%.2f\n", ans);
```

`cout` 默认只输出 6 位有效数字，大数会变成科学计数法（`1e+06`），直接判错。
**能用 `printf("%.2f")` 就用它**，输出格式最可控。
:::

### 六、边界情况

这是**最容易被忽略、也最好补**的一类。每道题写完，至少测这些：

| 边界 | 为什么危险 |
| --- | --- |
| `n = 1` | 循环、相邻比较、去重常在这里挂 |
| 全部相同 | 去重、排序、统计 |
| 全部不同 | 同上 |
| 最大值 | 溢出、数组越界、超时 |
| 空输入 / 空集合 | 输出格式、特殊分支 |
| 只有一个元素的一组数据 | 多组数据 + 边界叠加 |

::: exam 写完先别交，花两分钟测边界
把样例改成 `n = 1` 跑一遍，改成全相同跑一遍，改成最大跑一遍。

**这三跑通常能提前发现一半的错误**，而且只需要两分钟。
:::

### 七、死循环

<!-- no-compile -->
```cpp
while (l <= r) {
    int mid = (l + r) / 2;
    if (check(mid)) l = mid;      // ✗ l 没往前走，死循环
    else r = mid - 1;
}
```

二分、双指针、`while` 循环都是死循环高发区。症状是 **TLE**（超时），但原因其实在结果关。

**写循环时问自己一句：循环变量一定会收敛吗？**

### 八、取模

题目要求"答案对 10⁹+7 取模"时：

- **每一步都要取模**，不能只在最后取（中间就溢出了）
- 减法取模要 `(a - b + MOD) % MOD`，否则可能出现负数

## 动手检查

1. 把上面那段"没清空"的代码真的跑一遍，确认输出是 `3` 和 `6`。
   然后只加 `memset` 一行，确认输出变成 `3` 和 `3`。
2. 找出你以前做过的一道**多组数据**的题，检查每组开头有没有清空。
3. 拿你最近写的一道题，只测三种边界：`n = 1`、全部相同、最大值。
   记录你发现了什么。
4. 检查你所有输出小数的地方，是不是都用了 `printf("%.Nf")`。

| 基础 | [洛谷 P2141 珠心算测验](https://www.luogu.com.cn/problem/P2141) | 桶 + 计数，容易重复计数 |
| 基础 | [洛谷 P1046 陶陶摘苹果](https://www.luogu.com.cn/problem/P1046) | 最简单的边界：一个都不够高 |
| 巩固 | [洛谷 P1308 统计单词数](https://www.luogu.com.cn/problem/P1308) | 输出格式 + 大小写 + 找不到时的特殊输出 |
| 巩固 | 自选一道多组数据的题，故意不清空数组 | 亲手复现"第二组被污染" |

::: pitfall P1308 是格式陷阱的典型
它要求在找不到时输出 `-1`，找到时输出"出现次数 首次出现位置"，**两者格式不同**。
很多人只测了能找到的情况，交上去丢一半分。

**每道题都要想：题目有没有"另一种情况"？**（找不到 / 无解 / 空 / 唯一）
:::

## 下一节

结果对了，是不是就稳了？还差最后一关：

**时间、内存、栈**——这三个限制不达标，一样 0 分。
而且其中有一条**完全违反直觉**：内存是按你"声明"的空间算的，不是按你实际用的。
