# 申诉不是安全网

这一节不教你写代码，它做两件事：**把"出了问题还能申诉"这个幻想堵死**，
然后把**清单和模板**交到你手上。

## 本节学会什么

- 知道哪些情况**申诉一律不予受理**
- 拿到考前一周 / 考前一晚 / 交卷前 30 分钟**三份清单**
- 拿到一份可以直接背的**复赛代码模板**
- 建立"最后 30 分钟只检查、不改逻辑"的纪律

## 为什么需要它

大多数学生心里有一个默认假设：

> 出问题了可以申诉，大不了申诉回来。

这个假设是错的。看这几条规则：

::: exam 不予受理的情形（值得逐字读）
- 以**操作系统、语言环境的具体差异**为由提出的申诉，**不予受理**
- 因**答案文件名错误**或**源文件存放目录结构不规范**提出的申诉，**不予受理**
- 因认证者**个人失误**提出的申诉，**不予受理**

还有一条硬约束：

> **申诉过程中不允许修改任何文件名或文件内容。**
:::

换句话说：

| 你犯的错 | 能不能申诉回来 |
| --- | --- |
| 文件名写错了 | ❌ 不能 |
| 目录结构不对 | ❌ 不能 |
| "我的电脑上能跑，评测机不能" | ❌ 不能 |
| 自己编译时忘了改回来 | ❌ 不能 |
| 程序算法写错了 | ❌ 不能（这是能力问题，不是申诉问题） |

**结论：唯一的安全网是考前的检查习惯。**

::: pitfall 这一节为什么必须单独讲
因为"有申诉"会**削弱检查的动机**。

只要学生觉得"出了问题还能救"，他就不会认真做检查。
把这条路明确堵死，检查习惯才有理由建立起来。

**这也是本书把五道关放在考前的全部理由**：这些分不是靠聪明拿的，是靠习惯拿的。
:::

## 关键动作：三份清单

### 清单 A｜考前一周：练习期

这一周不做新题也可以，但必须完成这些：

- [ ] 在**真实环境**下（限时、用文件输入输出）完整做过**至少一套**四题完整卷
- [ ] 确认自己用的编译标准是 **C++17**，不是 C++14
- [ ] 手写并**默打**过一遍 `freopen` 标准模板（两行，一次都不能错）
- [ ] 检查自己的模板里没有和标准库重名的变量
- [ ] 检查模板里没有 `conio.h`、`getch()`、`system("pause")`
- [ ] 确认自己会算内存（`int` 4 字节）和复杂度（1 秒 ≈ 10⁸）
- [ ] 练过"先把暴力交上去，再想正解"
- [ ] 检查过自己的 `#define` / 宏有没有副作用

### 清单 B｜考前一晚：准备期

- [ ] 熟悉**本省**的目录结构要求：准考证号文件夹、题目文件夹、源文件名的大小写
- [ ] 把必背模板**抄一遍**（不是背，是抄——手写一遍记忆更牢）
- [ ] 确认文件资源管理器**显示扩展名**
- [ ] 确认自己知道申诉不受理的那几条
- [ ] 准备两支笔、准考证、身份证
- [ ] **睡够。** 考场上算法想不出来还能拿分，脑子不清楚什么都拿不到

::: pitfall 考前一晚不要做这三件事
1. **不要学新算法。** 收益接近于零，还会打乱已建立的熟练度。
2. **不要熬夜刷题。** 第二天的注意力比多做十道题值钱。
3. **不要只背模板不检查环境。** 模板对了，扩展名隐藏，一样全卷 0 分。
:::

### 清单 C｜交卷前 30 分钟：收尾期

这是价值最高的 30 分钟。**逐条打勾，不要凭印象。**

- [ ] 每一题都**重新编译**一遍（确认没有编译错误）
- [ ] 每一题都用**题目给的样例**跑一遍，比对输出
- [ ] 每一题的 `freopen` 文件名，与题目要求**逐字符**核对
- [ ] 检查**目录层级**：答题盘 → 准考证号 → 题目名 → 源文件
- [ ] 检查**准考证号文件夹名**：减号不是下划线、不能有空格、数字个数正确
- [ ] 确认**没有交错题**（文件名、读的文件、输出格式三处都对上）
- [ ] 确认每个题目文件夹里**只有一个源文件**
- [ ] 确认**每道题都真的提交成功**（看得到字节数）
- [ ] 收卷**签字前**再核对一次回收字节数

::: exam 这 30 分钟只做检查，不改逻辑
**这是本节最重要的一条纪律。**

交卷前改算法是**负收益**：

- 你可能把一个能过 60 分的程序改成 0 分
- 改完**没时间再验证**
- 而且慌乱状态下改出来的代码，出错概率远高于平时

**宁可带着 60 分离开，也不要赌一个可能变成 0 分的满分。**
:::

## 必背模板

考前必须能**不看键盘打字**地默写出这一段。用的时候只改三处：文件名、题目逻辑、输出格式。

```cpp
#include <cstdio>
#include <cstring>
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
int a[MAXN];

int main() {
    // ---- 复赛必写：两行成对，文件名改成题目要求的 ----
    freopen("apple.in", "r", stdin);
    freopen("apple.out", "w", stdout);
    // 调试阶段可以加返回值检查：
    // if (freopen("apple.in", "r", stdin) == NULL) { cerr << "open fail\n"; return 1; }

    // 加速（不用 freopen 时可加；两者混用有风险，见文件关）
    // ios::sync_with_stdio(false);
    // cin.tie(0);

    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];

    long long sum = 0;
    for (int i = 1; i <= n; i++) sum += a[i];

    cout << sum << '\n';
    return 0;
}
```

::: range 模板里每一行都在防什么
| 那一行 | 防的是哪一关 |
| --- | --- |
| `freopen` 两行 | 文件关 |
| `freopen` 返回值检查 | 文件关（调试期定位） |
| `const int MAXN` + 全局数组 | 资源关（栈溢出） |
| `using namespace std;` + 短变量名 | 编译关（重名） |
| `long long sum` | 结果关（溢出） |
| `#include` 显式列出 | 编译关（缺头文件） |
| `return 0;` | 编译关（`int main`） |

**这就是为什么模板要背——它把五道关的习惯固化成了肌肉记忆。**
:::

::: pitfall 模板不是拿来抄的，是拿来默写的
考场上你**不能带任何资料**。所以平时练习时：

- 新建文件后**不看任何东西**，先默打一遍模板
- 打完再对照，看哪里漏了

默打三遍就能记住。这 10 行代码，能保住的分数比多做十道题更多。
:::

## 考场上的时间分配

一份参考节奏（4 小时）：

| 阶段 | 时间 | 做什么 |
| --- | --- | --- |
| 通读 | 前 10 分钟 | 四道题全读一遍，**标出每题的数据范围和可分档** |
| 拿分 | 第 10～70 分钟 | 先把**每题的最低档暴力**写完交上去 |
| 主攻 | 第 70～180 分钟 | 攻 T1/T2 的更高档，或 T3 的中间档 |
| 保底 | 第 180～210 分钟 | 检查 T3/T4 有没有能补的特殊情况（小数、无解） |
| 收尾 | **最后 30 分钟** | **只做清单 C，不改逻辑** |

**原则：先把能拿的分拿到手，再去争取不确定的分。**

## 动手检查

1. 把"清单 C"（交卷前 30 分钟）抄成一张卡片，压在键盘下面。
2. **默打一遍**上面的模板，然后对照，记录你漏了几处。
3. 检查你现在用的模板，逐条对照"模板里每一行都在防什么"那张表——你还缺哪几行？
4. 用你自己的话把"三种 0 分"和五道关讲给一个同学听。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 默打复赛模板三遍 | 肌肉记忆 |
| 基础 | 把三份清单抄成一张纸，贴起来 | 让清单真的被用上 |
| 巩固 | 限时 4 小时做一套完整模拟卷，最后 30 分钟只检查 | 完整走一遍流程 |
| 挑战 | 给同学当一次"监考"，检查他的目录结构和文件名 | 检查别人的时候，你会发现自己也会犯 |

## 最后一句话

这本书里所有的技巧，最后都指向同一件事：

> **把你会做的题，一分不少地变成分数。**

算法决定你的上限，**五道关决定你能拿到多少**。
上限需要几个月去抬，而这五道关，**两天就能补上**。
