# 收录关：代码压根没交上去

::: gate 第 1 关 · 收录关
**这一关决定的不是一道题，而是整张卷子。**

五道关里，只有它失败时会导致**全卷 0 分**——四道题一起归零，和你的水平没有任何关系。
:::

## 本节学会什么

- 搭出正确的三层目录结构：**答题盘 → 准考证号 → 题目名 → 源文件**
- 认出那些"看起来交对了、其实没交上"的情况
- 学会交卷前用**字节数**确认提交成功
- 拿到一份可以贴在显示器上的检查清单

## 为什么需要它

前面四种 0 分，都还讲道理——代码写错了、算法不对、内存超了。
这一关不讲道理：

> **你的程序完全正确、样例全过、算法最优。它只是不在评测机要找的地方。**

结果是**全卷 0 分**。四道题一起归零，和你的水平没有任何关系。

::: exam 这一关是唯一会拖垮整张卷子的
- 编译关、文件关、结果关、资源关失败 → **单题**丢分
- **收录关失败 → 全卷 0 分**

这就是为什么它排在第一关，也为什么它值得你花 10 分钟读完。
:::

## 正确的目录结构

各省的细节要求不同，但**三层结构**基本一致：

```text
答题盘（例如 D:\ 或 E:\）
└── HN-J0001/              ← 准考证号文件夹（大小写按本省要求，常见为大写）
    ├── apple/             ← 题目文件夹，用题目规定的英文名（常见为小写）
    │   └── apple.cpp      ← 源文件：文件名与题目名一致，扩展名 .cpp（常见为小写）
    ├── banana/
    │   └── banana.cpp
    ├── cherry/
    │   └── cherry.cpp
    └── dragon/
        └── dragon.cpp
```

三个要点，每一个都可能单独导致全卷 0 分：

1. **层级不能多也不能少。** 多一层（比如 `HN-J0001/HN-J0001/apple/`）就找不到。
2. **准考证号文件夹名逐字符正确。** 大小写、减号、数字的个数，都要对。
3. **源文件名与题目名一致。** 题目要求 `apple.cpp`，你交 `Apple.cpp` 或 `apple.c` 都不行。

::: range 三个最容易错的位置
| 位置 | 要求 | 常见错误 |
| --- | --- | --- |
| 准考证号文件夹 | 例如 `HN-J0001` | 写成 `HN_J0001`（下划线）、`HN-J-0001`、`HN-J00001`（多一个 0）、末尾带空格 |
| 题目文件夹 | 常见为小写 | 写成 `Apple`、`APPLE` |
| 源文件 | 常见为小写，扩展名 `.cpp` | 写成 `apple.CPP`、`apple.cpp.txt` |

**⚠️ 以上为示例。大小写和层级要求各省不同，一律以本省当年须知和监考老师说明为准。**
:::

## 演示错误：六个真实现场

这一节的做法是：**先看错误长什么样，再学怎么避免。**
下面每一组都是"症状 → 原因 → 改法"。

### 错误 1：文件其实叫 `apple.cpp.txt`

**症状**：你在 IDE 里明明保存成了 `apple.cpp`，编辑器标题栏也显示 `apple.cpp`，但评测结果是全卷 0 分。

**原因**：Windows 默认**隐藏已知文件的扩展名**。你新建文本文件时，系统自动加了 `.txt`；
你手动改名成 `apple.cpp`，实际文件名变成了 `apple.cpp.txt`。

**改法**：在文件资源管理器的"查看"里**勾选"文件扩展名"**，让它一直显示。
然后盯着看一眼——真正的文件名必须是 `apple.cpp`，不是 `apple.cpp.txt`。

::: pitfall 这是最冤、最常见的一条
它满足所有"危险特征"：**本地测不出来**（IDE 照样能编译运行）、**肉眼看不出来**（隐藏扩展名）、
**代价最大**（全卷 0 分）。

**考前必须打开"显示文件扩展名"。** 这不是建议，是纪律。
:::

### 错误 2：准考证号里的减号写成了下划线

**症状**：全卷 0 分。目录结构看着完全正确。

**原因**：`HN-J0001` 中的 `-` 是**减号**（键盘上 `0` 右边那个键），不是下划线 `_`（`Shift + -`）。

**症状放大**：这两个字符在小字号下**几乎看不出区别**（`HN-J0001` vs `HN_J0001`）。

**改法**：**不要手打准考证号。** 用复制粘贴，或者对着准考证逐字符核对。
如果规定里专门写了"`-` 是减号不是下划线"，说明每年都有人栽在这上面。

### 错误 3：数字的个数对不上

**症状**：全卷 0 分。

**原因**：准考证号是 `HN-J0001`，你打成了 `HN-J00001` 或 `HN-J001`。
**多一个 0、少一个 0，文件夹名就不匹配。**

**改法**：数一遍。别嫌蠢，**这是唯一可靠的办法**。

::: pitfall 末尾空格
从别处复制准考证号时，很容易带一个**末尾空格**。文件夹名末尾带空格，肉眼完全看不出来。

复制之后，把光标移到名字末尾按一下 `End`，看光标有没有多走一格。
:::

### 错误 4：存到了桌面，而不是答题盘

**症状**：全卷 0 分。你的代码在桌面上，一切正常。

**原因**：评测机只从**指定的答题目录**回收文件。桌面、U 盘、`C:\Users\...\` 都不在回收范围内。

**改法**：**第一件事就是建目录**，在建好的目录里写代码。
不要"先在桌面写完，最后再拷过去"——最后那一步最容易被时间压力吃掉。

### 错误 5：交错题 / 目录里留了两份源文件

**症状**：单题 0 分，或者拿到的是你**改到一半**的那一版。

**原因**：两种情况：
- 你复制上一题的代码框架改这一题，**目录放对了但文件名/`freopen` 没改**
- 你在题目文件夹里先建了 `apple.cpp`，后来又在别处写了一份拷进来，**目录里有两份**

**改法**：
1. 从上一题复制代码后，**逐字符**改文件名、`freopen` 里的文件名、题目要求的输出格式。
2. 交卷前，**每个题目文件夹里只能有一个源文件**。多余的一律删掉。

::: exam 收卷前必须做的一件事
打开每个题目文件夹，**数一下源文件个数**。看到两个，就是隐患。
:::

### 错误 6：以为"保存了"就是"提交了"

**症状**：全卷 0 分，但你的程序明明写完了。

**原因**：保存到本地文件 ≠ 提交到评测系统。有些考场需要**额外一步提交/上传操作**，
有些是收卷统一回收，**各考场流程不同**。

**改法**：
1. **进场后先问清楚**：是收卷统一回收，还是需要自己提交？
2. 如果需要自己提交，**提交后确认能看到字节数**——看不到字节数，说明没交上去。
3. **离场前核对回收字节数**，签字确认。**签字之前你还有机会发现"程序没交上"。**

## 关键动作：交卷前 10 分钟

::: exam 收录关自查清单（逐条打勾，不要凭印象）
- [ ] 文件资源管理器**已显示扩展名**，每个源文件都是 `.cpp` 结尾
- [ ] 顶层只有一层**准考证号文件夹**，名字逐字符正确（减号、数字个数、无空格）
- [ ] **四个题目文件夹**都在，名字与题目要求一致（大小写）
- [ ] 每个题目文件夹里**只有一个源文件**，文件名与题目名一致
- [ ] 每个题目文件夹的源文件**内容对应正确**（没有交错题）
- [ ] 确认提交/回收方式，**看得到字节数**
- [ ] **收卷签字前**核对回收字节数
:::

## 动手检查

1. **手工搭一遍目录。** 用你真实的（或模拟的）准考证号，建出三层结构，放四个源文件进去。
   **不要查资料，凭记忆搭。** 搭完再对照上面的清单——错的地方就是你的考点。
2. **检查你的扩展名设置。** 现在就去"查看"里确认扩展名是显示的。如果你的文件真的叫 `x.cpp.txt`，立刻改。
3. **说给同桌听。** 把"三种 0 分"和"收录关的六个错误"讲一遍给别人听。
   讲不流畅的地方，就是你没真正记住的地方。
