# 爆零五道关（总纲）

复赛的分数，**一半来自算法，一半来自工程**。

算法那部分要长期训练，短期提不上去；而工程这部分，**两天就能养成习惯，保住的分数往往比多刷十道题还多**。

## 本节学会什么

- 分清三种 0 分，学会拿到分数后**自诊断**"我卡在哪一层"
- 记住一份代码要过哪五道关才变成分数
- 知道为什么"申诉"不是安全网
- 拿到一份可执行的考前清单框架

::: exam 这一节要先泼一盆冷水
很多同学默认"出问题了可以申诉"。**先把这条路堵死，检查习惯才有动机建立。**
下面的规则值得逐字读：

- 以操作系统、语言环境的具体差异为由提出的申诉，**不予受理**
- 因**答案文件名错误**或**源文件存放目录结构不规范**提出的申诉，**不予受理**
- 因认证者**个人失误**提出的申诉，**不予受理**
- 申诉过程中**不允许修改任何文件名或文件内容**

**唯一的安全网是考前的检查习惯。**
:::

## 为什么需要它

先算一笔账。假设你四道题都不会正解：

| 题 | 做法 | 得分 |
| --- | --- | --- |
| T1 | 正常做出来 | 100 |
| T2 | 会一半，写对 | 80 |
| T3 | 暴力枚举 | 30 |
| T4 | 输出特殊情况 | 30 |
| **合计** | **没有一道正解** | **240** |

对照一下你所在省份的一等分数线——**很多年份，240 分已经足够进一等。**

结论很清楚：**你不需要四道正解。** 你需要的是"会做的题一分不丢，不会的题尽量拿分"。

而这笔账里最脆弱的，恰恰是那些**和算法毫无关系**的部分：文件没交上去、编译不过、
`freopen` 写错、多组数据没清空、数组开小。**它们中的任何一条，都能让一道题直接变成 0 分。**

::: pitfall 复赛的"0 分"不止一种
- 有些 0 分是"这题真不会"——不可惜，本来就是能力边界
- 有些 0 分是"**代码写对了但没交对**"——这才是我们要消灭的对象

本书的目标不是让你多会一个算法，而是**让你已经会的每一分都落到成绩单上**。
:::

## 三种 0 分：先学会自诊断

出了成绩之后，第一件事不是难过，是**判断自己是哪一层的 0 分**。三种 0 分的成因和补救难度完全不同：

| 类型 | 表现 | 常见成因 | 能申诉吗 |
| --- | --- | --- | --- |
| **全卷 0 分** | 四题全 0，页面甚至看不到代码字节数 | 目录层级错、准考证号文件夹名错、**没交到指定位置**、没提交成功 | 基本不能 |
| **单题 0 分** | 某一题 0，其余正常 | `freopen` 缺失或写错、编译错误、题目与代码对错、该题全点 MLE/RE | 不能 |
| **部分测试点 0 分** | 该题有分但很低 | 复杂度不达标、边界未处理、溢出、多组数据未重置 | 不能 |

::: range 这张表的用法：对号入座
- **全卷 0 分** → 问题出在**收录关**，和你的代码一个字都没关系
- **单题 0 分** → 出在**编译关**或**文件关**
- **部分点 0 分** → 出在**结果关**或**资源关**

**"全卷 0 分"只有一个来源：收录关。** 这是唯一一种会拖垮整张试卷的失误，
所以它排在第一位，也最该被消灭。
:::

## 五道关总览

一份代码从写完到变成分数，要依次通过五道关：

```text
写好的代码
   │
   ├─ 1. 收录关   文件交到了正确的位置吗？
   ├─ 2. 编译关   评测机能把你的代码编译出来吗？
   ├─ 3. 文件关   程序读的是这道题的输入吗？写的是正确的输出吗？
   ├─ 4. 结果关   结果正确吗？
   └─ 5. 资源关   时间、内存、栈都在限制内吗？
   │
   └──→ 分数
```

| 关 | 一句话 | 失败的后果 | 本书章节 |
| --- | --- | --- | --- |
| **1 收录关** | 代码压根没交上去 | **全卷 0 分** | [收录关](/practice/five-gates/collection) |
| **2 编译关** | 评测机不认识你的代码 | 单题 0 分 | [编译关](/practice/five-gates/compile) |
| **3 文件关** | `freopen` 读错了文件 | 单题 0 分 | [文件关](/practice/five-gates/file) |
| **4 结果关** | 答案对了，分数没来 | 部分点 0 分 | [结果关](/practice/five-gates/result) |
| **5 资源关** | MLE / RE / TLE | 部分点或全题 0 分 | [资源关](/practice/five-gates/resource) |

### 每一关为什么这样排

1. **收录关必须排第一。** 它是唯一会拖垮整张卷子的失误，代价最大，而且**学生最没有防备**——
   大家以为"写对代码就够了"，实际上"没交上去"的代码等于零。
2. **编译关排第二。** 编译不过，后面四关一个都轮不到。它也是**本地就能完全验证**的一关
   （只要你用对编译参数和标准）。
3. **文件关是真正的第一大现场。** 复赛要求文件输入输出，`freopen` 写错、文件名拼错、
   代码与题目错位——这一关吃掉的分最多，所以要给足篇幅。
4. **结果关最"传统"。** 输出格式、多组数据、局部变量、浮点比较、边界条件，
   这些都是"算法对了但分没了"。
5. **资源关最容易违反直觉。** MLE 是按**声明的空间**算的，不是按实际使用的；
   栈空间就等于题目的内存限制。不专门讲，很难自己想到。

::: pitfall 这五关是**顺序**关系，不是并列关系
第 3 关不过，第 4 关写得再漂亮也没用。

所以检查的顺序必须是**从第 1 关往第 5 关走**：
先确认交对了位置，再确认能编译，再确认文件读对了，最后才谈结果和效率。

**反过来检查（先纠结算法）是考场上的典型浪费。**
:::

## 三阶段清单

把五道关摊到考前的时间轴上，就是三份清单：

### A. 考前一周：练习期清单

- [ ] 在**真实环境**里完整做过至少一套完整卷（四题、限时、文件输入输出）
- [ ] 确认自己用的编译器标准是 **C++17**（不是 C++14）
- [ ] 手写过并**默打过**一遍 `freopen` 的标准模板
- [ ] 确认自己的模板里没有和标准库重名的变量（`y1`、`next`、`time`、`hash`、`index`、`kill` 等）
- [ ] 练习过"先把暴力交上去，再想正解"

### B. 考前一晚：准备期清单

- [ ] 熟悉本省的**目录结构要求**（准考证号文件夹、题目文件夹、源文件名的大小写）
- [ ] 把**必背模板**抄在一张纸上（不夹带进场，只作记忆训练）
- [ ] 确认**扩展名可见**（Windows 默认隐藏扩展名，这是重灾区）
- [ ] 睡够。**考场上算法想不出来还能拿分，脑子不清楚什么都拿不到。**

### C. 交卷前 30 分钟：收尾清单

- [ ] 每一题都**重新编译**一遍
- [ ] 每一题都用**题目给的样例**跑一遍，比对输出
- [ ] 每一题的 `freopen` 文件名，与题目要求的**逐字符**核对
- [ ] 检查**目录层级**和**准考证号文件夹名**（减号不是下划线、不能有空格、`0` 的个数）
- [ ] 确认**没有交错题**，目录里**没有多余的源文件**
- [ ] 确认**每道题都真的提交成功**了（看得到字节数）
- [ ] 收卷**签字前**再核对一次回收字节数

::: pitfall 最后 30 分钟不要用来改算法
交卷前改算法是**负收益**：你可能把一个能过 60 分的程序改成 0 分，而且没时间再验一遍。

**最后 30 分钟只做检查，不改逻辑。** 这一条纪律本身就值几十分。
:::

## 关于具体规定：三条纪律

::: exam 引用规则时必须注意
1. **省份差异很大，不要说成"全国统一"。**
   目录结构、提交方式、大小写要求在各省之间并不一致。
   **以你所在省份当年的须知和监考老师说明为准，不要凭去年的记忆操作。**

2. **规则会变。** 目录结构、提交方式、语言标准逐年可能调整。
   本书涉及具体规定的章节，请以**当年**的官方须知为准。

3. **不要迷信"经验"。** 考场上唯一可靠的依据是：本省须知 + 监考老师现场说明 + 试卷首页的明文要求。
:::

## 动手检查

1. 打开你**最近一次**模拟赛的成绩，对号入座：你是哪一层的丢分？用"三种 0 分"表定位到具体的关。
2. 把你的**默认代码模板**贴出来，逐条比对三阶段清单，找出至少两处隐患。
3. 现在就在本地建一个空目录，按你所在省份的要求，把"准考证号 → 题目 → 源文件"的目录结构**手工搭一遍**。
   不要查资料，凭记忆搭——搭错的地方就是你考场上会错的地方。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 把三种 0 分抄成一张卡片，贴在自己的书桌前 | 建立"先自诊断，再谈算法"的反应 |
| 基础 | 用真实准考证号手工搭一遍三层目录结构 | 收录关的肌肉记忆 |
| 巩固 | 把五道关逐条对照自己的代码模板，标出隐患位置 | 把这五关接进自己的模板 |
| 巩固 | 限时 4 小时做一套完整模拟卷，**必须用文件输入输出** | 完整跑一遍五道关 |
| 挑战 | 给同桌讲一遍"三种 0 分"，讲到他听懂 | 讲得清才算真懂 |
