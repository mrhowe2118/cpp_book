# 编译关：评测机不认识你的代码

::: gate 第 2 关 · 编译关
**本地能编过，不代表评测机能编过。**

这一关失败 = 单题 0 分。而且它的成因非常具体，几乎全都能在考前一次性消灭。
:::

## 本节学会什么

- 认出"Windows 上只是警告、Linux 上直接报错"的那类写法
- 记住一批**和标准库重名的变量名**，从此不再用它们
- 知道为什么必须显式写 `-std=c++17`
- 拿到一份编译关自查清单

## 为什么需要它

这是最让人想不通的一种 0 分：

> 我在自己电脑上跑得好好的，样例全过，一交上去就是 **CE**。

原因在于**两个环境不一样**：

| | 你的电脑 | 评测机 |
| --- | --- | --- |
| 系统 | Windows | NOI Linux |
| 编译器 | MinGW / 小熊猫 C++ | `g++` |
| 语言标准 | 编译器默认（往往较新） | **可能是 C++14** |
| 对不规范写法 | 警告，照常编译 | **直接报错** |
| 扩展函数 | `conio.h`、`getch()` 都有 | **根本没有** |

**你的电脑宽容，评测机不宽容。** 关掉这份宽容，才能看清自己的代码到底合不合规。

::: exam 一个立刻能用的办法
本地编译时**把警告打开**：

```bash
g++ -std=c++17 -Wall -Wextra main.cpp -o main
```

`-Wall -Wextra` 会把那些"评测机会报错、而你本地被放过"的地方提前指出来。
**每次编译都带上它**，这是零成本的保险。
:::

## 关键过程与易错点

### 最常见的编译错误

| # | 症状 | 真正的原因 | 改法 |
| --- | --- | --- | --- |
| 1 | `error: 'y1' cannot be used as a function` 之类**莫名其妙的报错** | **变量名和标准库重名** | 换名字（见下一节） |
| 2 | `error: 'void main' must return 'int'` | 用了 `void main()` | 写 `int main()` 并 `return 0;` |
| 3 | 结构化绑定、`if constexpr` 报错 | 评测机按 **C++14** 编译 | 本地固定 `-std=c++17`，不用太新的语法 |
| 4 | `conio.h: No such file or directory` | 用了 Windows 专有头文件 | 删掉，改用标准写法 |
| 5 | `error: expected ';'`，位置看着完全正常 | **中文全角标点**（`；` `（）` `，`） | 切回英文输入法重打这一行 |
| 6 | 提示找不到文件 / 编译了一个空文件 | 扩展名被隐藏，实际是 `main.cpp.txt` | 打开"显示文件扩展名" |
| 7 | `'sort' was not declared` | 缺头文件 | 补 `#include <algorithm>` |
| 8 | 提示源文件过大 | 源文件超过 **100 KiB** 上限 | 检查是不是把测试数据贴进去了 |

### 最隐蔽的一类：和标准库重名

这是本关最值钱的一条，因为它满足三个"看不见"：

- **本地看不出来**：Windows 上往往只是警告，照样编译
- **报错看不懂**：错误信息会指向别的行，甚至指向标准库内部
- **想不到**：没人会觉得"我把变量叫 `y1`"是个问题

<!-- no-compile -->
```cpp
// 在 Windows 上多半只是警告；在 NOI Linux 的 g++ 下直接编译失败
#include <bits/stdc++.h>
using namespace std;

int main() {
    int y1 = 0;        // ✗ y1 是 <math.h> 里的贝塞尔函数
    int time = 10;     // ✗ time 是 <ctime> 里的函数
    int next = 1;      // ✗ next 是 <iterator> 里的函数
    int hash = 0;      // ✗ hash 是 <functional> 里的类模板
    int index = 0;     // ✗ index 是 <strings.h> 里的函数
    return 0;
}
```

::: range 变量名黑名单（逐个编译实测出来的，不是凭印象）
下面每一个名字都**真的编译验证过**：全局作用域实测冲突 **53 个**，函数内部冲突 **0 个**。

**第一梯队：全局作用域一定冲突 —— 不要用**

| 类别 | 不要用 | 实测报错 |
| --- | --- | --- |
| 数学 | `pow` `abs` `div` `exp` `log` | `redeclared as different kind of symbol` |
| 时间 | `time` `clock` `difftime` | 同上 |
| 迭代 | `next` `prev` `begin` `end` `advance` | `reference to … is ambiguous` |
| 容器名 | `map` `set` `queue` `stack` `list` `vector` | 同上 |
| 算法名 | `sort` `count` `find` `copy` `swap` `fill` `unique` `reverse` `lower_bound` `upper_bound` `min` `max` `rank` `size` | 同上 |
| 输入输出 | `cin` `cout` `cerr` `endl` `flush` `hex` `dec` `left` `right` | 同上 |
| C 函数 | `printf` `scanf` `remove` `system` `exit` `free` `malloc` | `redeclared as different kind of symbol` |
| 其他 | `data` `pair` `string` `hash` | `ambiguous` |

**第二梯队：函数内合法，但仍然不要用**

实测结论有点出乎意料：把 `int max;` 写在 `main` **里面**是**能编过**的——
局部声明会遮蔽（hide）库里的名字。

但它的坑在后面：你在同一个作用域里想调用 `max(a, b)` 时，
`max` 已经变成你的 `int` 了，**报错点离声明很远**。

**Linux 上还会多出这几个**（本机 MinGW 不冲突，glibc 会冲突）：

`y0` `y1` `j0` `j1`（贝塞尔函数）、`index`（BSD 字符串函数）、`kill` `signal`（信号处理）。

**所以这张表在评测环境上只会更长，不会更短。**

**安全的名字（实测全部可用）**

`n` `m` `k` `cnt` `ans` `sum` `a` `b` `i` `j` `idx` `mp` `st` `q` `pos` `nxt` `t` `x` `y`
`res` `mx` `mn` `fa` `dp` `vis` `head` `dep` `val` `len` `tot` `num` `cur` `key` `col`
`node` `tmp` `flag` `ok` `buf` `str` `edge` `tree` `dist` `root`

**规律：越"像个英文单词"越危险，缩写和短名全部安全。**

> 所以"竞赛代码爱用短变量名"不只是风格问题——**它同时是一道防重名的保险。**
:::

::: exam 这张表是可复现的，不是经验之谈
本书用一个脚本逐个标识符生成小程序、真的调用 `g++` 编译，然后记录结果。

- 完整实测表格：随书仓库根目录的 `变量名实测报告.md`（由脚本自动生成，请勿手改）
- 复现命令：`npm run identifiers`

**你也可以自己验一遍**——把某个名字写进上面两段模板，编译看看。
:::

::: pitfall 一个诚实的提醒：不要过度使用这份表
实测是在 **MinGW g++ 8.1.0** 上做的，**不是** NOI Linux 的 g++。
两者标准库实现不同，**Linux 上的冲突集合是这份结果的超集**。

所以：

- ✅ 把它当"**不要用**"的清单 → 安全（超集意味着只会更严格）
- ❌ 拿它当"**可以用**"的保证 → 不安全

**不确定的名字，就换成缩写。** 这是零成本的规避方式。
:::

::: pitfall 为什么评测机报的错"对不上行号"
编译器看到 `int y1 = 0;` 时，它认为你在**重新声明一个已有的函数**。
于是它会在这一行报错，接着在**所有用到 `y1` 的地方**连锁报错，
甚至跑到标准库头文件里去报错。

**看到一堆莫名其妙的报错时，第一反应应该是"我是不是撞了标准库的名字"。**
:::

### `void main()` 与 `return`

老教材里常见 `void main()`，但：

- C++ 标准要求 `main` 返回 `int`
- 试卷首页的明文要求和评测环境都按标准来
- 有的评测机会直接判 CE

<!-- no-compile -->
```cpp
// ✗ 老教材写法
void main() { }

// ✓ 标准写法
int main() {
    return 0;
}
```

`return 0;` 严格来说可以省略（`main` 会隐式返回 0），但**写上**：
它是给读代码的人看的，也是给"万一评测机不认"兜底的。

### 语言标准：为什么必须写 `-std=c++17`

评测机的 `g++` 可能**默认按 C++14 编译**。这意味着：

| 写法 | C++14 | C++17 |
| --- | --- | --- |
| `auto [x, y] = p;`（结构化绑定） | ❌ | ✅ |
| `if constexpr` | ❌ | ✅ |
| `for (auto& [k, v] : mp)` | ❌ | ✅ |

**两条纪律：**

1. **本地编译固定加 `-std=c++17`**，让你看到的就是评测机看到的
2. **别现学新语法**。考前一周不要去用刚学会的 C++17 特性——你还没到能用稳的时候

::: pitfall 别用 Windows 专有的东西
这三样在评测机上**一定编不过**：

| 写法 | 问题 | 换成 |
| --- | --- | --- |
| `#include <conio.h>` | Linux 没有这个头文件 | 不需要，删掉 |
| `getch()` / `kbhit()` | 同上 | 不需要，删掉 |
| `system("pause")` | 评测机没有交互界面 | 删掉，只在本地调试时用 |

**本地调试用的 `system("pause")` 交卷前必须删掉。** 留着它，程序会在评测机上卡到超时。
:::

### 中文全角标点是"看不见"的杀手

中文输入法下打出的标点，和英文标点在屏幕上**差别极小**：

| 看着一样 | 实际是 | 后果 |
| --- | --- | --- |
| `；` | 全角分号 | 编译报错 |
| `（ ）` | 全角括号 | 编译报错 |
| `，` | 全角逗号 | 编译报错 |
| `“ ”` | 全角引号 | 编译报错 |

**可靠的判断方法：把那一行删掉，切到英文输入法重打一遍。**
或者注意光标宽度——全角标点占两个字符宽。

- [ ] 每一题都**重新用 `-std=c++17 -Wall -Wextra` 编译过一遍**
- [ ] 看不到 `warning`（尤其是"重名""未初始化"这类）
- [ ] 没有 `conio.h`、`getch()`、`system("pause")`
- [ ] 变量名不在黑名单里
- [ ] 源文件是 `.cpp` 结尾，体积正常（没有把测试数据贴进去）

:::

### 头文件：另一种"编不过"

代码本身合规，但**头文件没包含**。典型：

| 用了什么 | 必须包含 |
| --- | --- |
| `sort` `lower_bound` `min` `max` | `<algorithm>` |
| `memset` | `<cstring>` |
| `printf` `scanf` | `<cstdio>` |
| `sqrt` `fabs` | `<cmath>` |
| `string` | `<string>` |
| `queue` `stack` `set` `map` `vector` | 各自的头文件 |

::: pitfall 不要靠 `bits/stdc++.h` 赌运气
它确实能一次包含几乎所有头文件，**在 NOI Linux 上通常可用**，但有三个问题：

1. 它把标准库全部拉进来，**撞名的机会大幅增加**
2. 编译更慢
3. 某些版本下它自身可能有缺陷

本书示例一律用**显式 `#include`**：既安全，又能让你记住每个工具来自哪里。
:::

## 动手检查

1. 把上面那段"重名"代码**真的编译一次**（`g++ -std=c++17 -Wall -Wextra`），
   数一数报了几条错、分别指向哪一行。体会一下"报错和真正的错误不在同一行"。
2. 打开你**最近一次**提交的代码，用黑名单逐行搜一遍变量名。
3. 故意把某个分号换成全角 `；`，编译看报错；再把某个 `"` 换成全角 `“`，对比报错有什么不同。
4. 在你的编译命令或 IDE 设置里**永久加上** `-Wall -Wextra`。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 用 `g++ -std=c++17 -Wall -Wextra` 编译你以前写的任意一题 | 看你会冒出多少条警告 |
| 基础 | 把一段代码里的变量分别改名为 `time`、`next`、`hash` | 记住"重名"到底长什么样 |
| 巩固 | 写一个用 `void main()` 的程序，本地编译并观察 | 明白为什么试卷要求 `int` |
| 巩固 | 整理一份自己的"变量名黑名单"，贴在显示器旁边 | 把这条纪律变成习惯 |
