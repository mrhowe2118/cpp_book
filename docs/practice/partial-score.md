# 骗分与部分分

**复赛不是"要么满分要么零分"。** 每道题都按测试点给分，你写不出正解，照样能把大部分分拿到手。

这一节讲的就是这门手艺。

## 本节学会什么

- 建立"按测试点拿分"的思路，而不是"要么正解要么放弃"
- 学会三种最实用的拿分手段：**暴力、特判、分档**
- 知道哪些"骗分"是正当策略、哪些是无效甚至危险的
- 拿到一个可执行的做题顺序

## 为什么需要它

先看一个很多学生的真实反应：

> 这题我只会 O(n²)，但数据范围是 10⁵……算了，写个正解吧。
> （30 分钟后）写不出来，交个空程序吧。

**这是最亏的做法。** O(n²) 在那道题上往往能过前几个测试点，
那就是 30～50 分——比空程序的 0 分多得多。

::: exam 关键认知：分数是按测试点发的
出题人把测试点按数据规模分成几档，**每一档单独给分**。

所以你的目标不是"写出正解"，而是：

> **在有限的时间里，让尽可能多的测试点输出正确答案。**

写出正解只是达成这个目标的**一种**手段，不是唯一手段。
:::

## 最小可运行示例：暴力拿分

题目：给平面上 n 个点，求**最近两点之间的距离**。
数据范围分两档：`n ≤ 100`（30 分）、`n ≤ 100000`（100 分）。

正解是分治，很难写。但第一档用**暴力**就够了：

<!-- expect

-->
```cpp
#include <cstdio>
#include <cmath>
using namespace std;

const int MAXN = 100005;
int x[MAXN], y[MAXN];

int main() {
    int n;
    scanf("%d", &n);
    for (int i = 0; i < n; i++) scanf("%d %d", &x[i], &y[i]);

    double best = 1e18;
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            double dx = x[i] - x[j];
            double dy = y[i] - y[j];
            double d = sqrt(dx * dx + dy * dy);
            if (d < best) best = d;
        }
    }
    printf("%.2f\n", best);
    return 0;
}
```

**这段 20 行的暴力，就是 30 分。** 而它会写的人比其他任何做法都多。

::: range 一道题你能拿多少分，看这几档
| 你会什么 | 大概能拿 |
| --- | --- |
| 什么都不写 | 0 |
| 会写暴力 + 特判 | 30～50 |
| 暴力 + 一档优化 | 50～70 |
| 正解 | 100 |

**不会正解的人拿到 50 分，比死磕正解最后交白卷的人强得多。**
:::

## 关键过程与易错点

### 一、暴力：性价比最高的手段

**能写出暴力就先写暴力，交上去，再想优化。**

| 题目类型 | 暴力做法 | 通常能过的档 |
| --- | --- | --- |
| 区间求和 | 每次从头扫一遍 | `n, m ≤ 1000` |
| 最值 / 距离 | 两两枚举 `O(n²)` | `n ≤ 1000` |
| 子集 / 方案 | 深搜枚举所有组合 | `n ≤ 20` |
| 查找 | 线性扫描 | `n ≤ 1000` |
| 排序相关 | 每次重新排序 | 小数据档 |

::: pitfall 先交暴力，再动正解
这是**考试策略**，不是偷懒：

- 先交暴力 = **锁定了那 30 分**，后面无论发生什么都不会丢
- 再想正解 = 心态完全不同，你不会因为"手里一分没有"而慌

**很多人在考场上只写了正解，结果正解有 bug，0 分；
而先交暴力的人，最少也有 30 分。**
:::

### 二、特判：零成本的分

题目里明确提到的特殊情形，**一定要单独处理**。这类分最好拿，因为题目已经告诉你了。

| 题目里的这句话 | 你该特判什么 |
| --- | --- |
| "如果无解，输出 `-1`" | 无解的情况 |
| "保证有解" | 不用判，但别输出多余内容 |
| "`n = 1` 时……" | `n = 1` |
| "所有数互不相同" | 可以省掉去重，也可以拿来验证逻辑 |
| "答案对 10⁹+7 取模" | 每一步取模 |
| "可能有多个答案，输出任意一个" | 那就输出最容易构造的那个 |

::: exam 特判的两个纪律
1. **特判必须有依据。** 题目说了"无解输出 -1"你才能输出 -1；
   题目没说，你猜着输出 `-1` 只是碰运气。
2. **特判要写在正确的位置。** 在读完输入之后、进入主逻辑之前。
   写在开头就 `return 0`，可能连输入都没读——**多组数据时会连锁出错**。
:::

### 三、分档：一份代码，两种做法

按数据规模选做法，让代码"小的用暴力、大的用正解"：

```cpp
#include <cstdio>
using namespace std;

int main() {
    int n;
    scanf("%d", &n);

    if (n <= 1000) {
        // 小数据：暴力，保证过
        // brute();
    } else {
        // 大数据：正解，写不出来就……
        // solve();
    }
    return 0;
}
```

::: pitfall 分档的收益高，风险也高
分档意味着**你要写两套逻辑**，而且必须两套都正确：

- 正解写错了 → 大数据那档 0 分，而你可能**已经占用了本该写暴力的时间**
- 分界点写错 → 本来能过的小数据也挂了

**保守建议**：如果你对正解没有八成把握，**就只写暴力**。
一套正确的暴力，比一套半成品的分档更值钱。
:::

### 四、几种"额外手段"及其代价

| 手段 | 怎么做 | 能拿分吗 | 风险 |
| --- | --- | --- | --- |
| **打表** | 把答案硬编码进数组 | 只在数据范围极小、答案固定时有用 | 表太大源文件超限；范围一变就错 |
| **贪心构造** | 用贪心求一个"可能不对"的答案 | 有时能过部分点 | 大多数时候错 |
| **随机化** | 随机试很多次取最优 | 部分题目有效 | 不稳定，可能反而更差 |
| **输出样例** | 直接输出题目样例的答案 | 极少数情况下恰好命中 | **基本无用**，别把时间花在这 |
| **判掉小数据** | 只处理 `n` 很小的情况 | 有效（就是暴力） | 无 |

::: pitfall "输出样例"是浪费时间的
网上有些段子说"输出样例答案能骗到分"。**在现在的评测系统上基本不成立**：
样例通常就是第一个测试点，而且往往被单独验证。

**同样的时间，写一个暴力能拿 30 分；输出样例大概率是 0 分。**
:::

### 五、骗分的底线

这里的"骗分"指的是**按测试点合理拿分**，不是攻击评测系统。

::: exam 三条不能越过的线
1. **不要提交与题目无关的内容**，不要试图利用评测系统的缺陷。
2. **不要在代码里写针对特定测试点的作弊逻辑**（比如判断输入是不是某个特定文件）。
3. **不要提交有病毒/破坏性的代码。**

违规的后果不是丢分，是**取消成绩**。这条没有商量余地。

**这里讲的每一个手段，都是"用正确的程序拿它该得的分"。**
:::

### 六、考场上的做题顺序

把前面几节的结论合起来，就是一条可执行的路线：

```text
1. 通读四题，标出每题的数据范围和分档
        ↓
2. 每题的暴力先写完、测对、交上去   ← 锁定保底分
        ↓
3. 从最容易的那题开始，冲击更高档
        ↓
4. 有时间再碰正解
        ↓
5. 最后 30 分钟只检查，不改逻辑
```

::: exam 一条能防空卷的纪律
**任何时候，四道题都必须有一份能编译、能跑的代码在评测机上。**

哪怕那道题的代码就是"读入然后输出 0"——它在某些题目上真的能拿到分（比如答案是 0 的情况），
而且它保证你不会因为手滑而全卷 0 分。

**空文件永远 0 分，写了就有机会。**
:::

## 动手检查

1. 找一道你以前**放弃过**的题，只写暴力，看看能在洛谷上拿到多少分。
2. 把自己最近三题的代码拿出来，检查有没有漏掉题目明确提到的特判
   （"无解输出 -1"、"n = 1"、"取模"）。
3. 用 [数据范围表就是给分表](/practice/data-range) 的方法，给一道题写出它的分档表。
4. 计时：写一道题的暴力，看看用了几分钟。**这是你考场上真实可用的时间预算。**

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | [洛谷 P1102 A-B 数对](https://www.luogu.com.cn/problem/P1102) | 先写 O(n²) 拿小数据分，再想优化 |
| 基础 | [洛谷 P2249 查找](https://www.luogu.com.cn/problem/P2249) | 线性查找 vs 二分查找的分差 |
| 巩固 | [洛谷 P1824 进击的奶牛](https://www.luogu.com.cn/problem/P1824) | 特判 + 暴力枚举答案 |
| 巩固 | 挑一道你完全不会的题，只写暴力和特判，记录得分 | 亲手验证"暴力真的有分" |
| 挑战 | 给一道题写"分档"版本（小数据暴力 + 大数据优化），两档都测 | 分档的风险控制 |

::: pitfall 练习时也要"按考场方式做"
平时刷题容易养成一个坏习惯：**看一眼没思路就直接看题解**。

考前两周改成这样练：

1. 先想 10 分钟
2. 想不出来 → **写暴力交上去**
3. 再看题解，对照自己差在哪

**这样练，你练的是"考场上的决策"，不只是"算法"。**
:::
