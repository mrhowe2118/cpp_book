# 竞赛宏与实用技巧

宏能让你**少打字**。但它也最容易给你埋雷——因为宏是**纯文本替换**，不是函数调用。

这一节讲：哪些宏值得用，哪些宏千万别碰，以及为什么。

## 本节学会什么

- 掌握 3 个真正值得用的宏/技巧（快读、调试宏、常用缩写）
- 亲手复现宏的两个经典陷阱：**缺括号**和**副作用**
- 知道 `#define int long long` 的坑在哪
- 建立"宏要少而精"的判断标准

## 为什么需要它

先看一段"看起来完全正确"的代码：

```cpp
#define sq(x) x * x
```

`sq(3)` 是 `9`，没问题。那 `sq(1 + 2)` 是多少？

**是 `5`。**

因为宏只是文本替换，`sq(1 + 2)` 展开成：

```text
1 + 2 * 1 + 2      // = 1 + 2 + 2 = 5
```

::: exam 宏和函数的根本区别
| | 函数 | 宏 |
| --- | --- | --- |
| 展开方式 | 真正调用，参数先算好 | **纯文本替换** |
| 参数求值次数 | 一次 | **可能多次** |
| 优先级 | 不用担心 | **必须自己加括号** |

**只要用宏，就要自己负责括号和求值次数这两件事。**
:::

## 最小可运行示例：亲手复现两个陷阱

### 陷阱一：缺括号

<!-- expect
5
9
-->
```cpp
#include <cstdio>
#define sq(x) x * x          // ✗ 参数没加括号

int main() {
    printf("%d\n", sq(1 + 2));   // 展开成 1 + 2 * 1 + 2 = 5，不是 9
    printf("%d\n", sq(3));       // 3 * 3 = 9，这个碰巧对
    return 0;
}
```

加上括号就对了：

<!-- expect
9
-->
```cpp
#include <cstdio>
#define SQ(x) ((x) * (x))    // ✓ 参数和整体都加括号

int main() {
    printf("%d\n", SQ(1 + 2));   // (1 + 2) * (1 + 2) = 9
    return 0;
}
```

::: pitfall 正确的宏有"两层括号"
```cpp
#define SQ(x) ((x) * (x))
//            ↑  ↑  ↑ 参数各一层
//      ↑            ↑ 整体再一层
```

- **参数加括号**：防止 `1 + 2` 被拆开
- **整体加括号**：防止在更大的表达式里被拆开，比如 `2 * SQ(3)` → `2 * ((3) * (3))`

**只加一层的宏，一定会在某个地方出错。**
:::

### 陷阱二：副作用——参数被算了两次

<!-- expect
m=2 i=3
-->
```cpp
#include <cstdio>
#define MAX(a, b) ((a) > (b) ? (a) : (b))    // 括号都加了，看着很规范

int main() {
    int i = 1, j = 0;
    int m = MAX(i++, j);     // i++ 出现了两次！
    printf("m=%d i=%d\n", m, i);
    return 0;
}
```

展开后是 `((i++) > (j) ? (i++) : (j))`：

1. 判断条件先执行一次 `i++` → `i` 变成 2
2. 条件为真，进入 `(i++)` → 又执行一次 → `i` 变成 3，返回 2

**结果 `m = 2, i = 3`**，而你可能以为 `m = 1, i = 2`。

::: pitfall 带副作用的参数永远不要传给宏
`i++`、`--j`、`f(x)`（函数有副作用）—— 这些传给宏都可能**被执行多次**。

**这也是为什么 C++ 更推荐 `inline` 函数和 `std::max`：**

```cpp
inline int max2(int a, int b) { return a > b ? a : b; }   // ✓ 参数只求值一次
```

竞赛里如果要用 `max`/`min`，**优先用标准库的 `std::max` / `std::min`**（`<algorithm>`），
它们是真函数，不会有这个问题。
:::

## 值得用的宏和技巧

### 1. 快读（输入量大时必备）

**什么时候用**：输入有 10⁶ 个数以上，`cin` 和 `scanf` 都不够快。

<!-- expect
3
10 20 30
---
60
-->
```cpp
#include <cstdio>

inline int read() {
    int x = 0, f = 1;
    char c = getchar();
    while (c < '0' || c > '9') {
        if (c == '-') f = -1;
        c = getchar();
    }
    while (c >= '0' && c <= '9') {
        x = x * 10 + (c - '0');
        c = getchar();
    }
    return x * f;
}

int main() {
    int n = read();
    long long sum = 0;
    for (int i = 0; i < n; i++) sum += read();
    printf("%lld\n", sum);
    return 0;
}
```

::: range 快慢的顺序（输入 10⁶ 个整数时）
| 方式 | 相对速度 |
| --- | --- |
| `cin` / `cout`（默认） | 最慢 |
| `scanf` / `printf` | 快 |
| `cin` + `sync_with_stdio(false)` | 接近 `scanf` |
| **手写快读** | 最快（但代码长） |

**建议**：默认用 `scanf`/`printf`。只有确实被卡了才上快读。
:::

### 2. 调试宏：会自动打印变量名

```cpp
#include <cstdio>
#define dbg(x) fprintf(stderr, #x " = %d\n", x)
```

`#x` 会把变量名变成字符串。`dbg(n)` 输出 `n = 5`，
**你不用手写 "n = "**——变量名改了它也跟着改。

<!-- expect
8
-->
```cpp
#include <cstdio>
#define dbg(x) fprintf(stderr, #x " = %d\n", x)

int main() {
    int n = 5, m = 3;
    dbg(n);              // 只打到屏幕（stderr），不进答案文件
    dbg(m);
    printf("%d\n", n + m);   // 这一行才进答案文件
    return 0;
}
```

::: pitfall 调试输出必须打到 `stderr`
上面 `dbg` 用的是 `fprintf(stderr, ...)`，所以它**不会进 `apple.out`**。

如果用 `cout` 或 `printf`，调试信息会混进答案文件里 → **WA**。

**纪律：调试输出只走 `cerr` / `stderr`，而且交卷前全部删掉。**
:::

### 3. 常用缩写

| 宏 | 展开 | 用途 |
| --- | --- | --- |
| `#define pb push_back` | — | 少打字 |
| `#define fi first` / `#define se second` | — | `pair` 用 |
| `#define all(x) (x).begin(), (x).end()` | — | `sort(all(v))` |
| `#define rep(i, a, b) for (int i = (a); i <= (b); i++)` | — | 循环 |

::: pitfall 缩写宏只在你"闭着眼睛都不会写错"时才值得
`rep` 这类宏有个隐蔽问题：**它把循环变量的类型定死了**。

```cpp
#define rep(i, a, b) for (int i = (a); i <= (b); i++)
rep(i, 1, n)        // i 被强制成 int
```

如果 `n` 超过 `int` 范围，或者你本来想用 `long long`，就会溢出。

**建议**：`all(x)` 和 `pb` 值得用；`rep` 这类**看个人习惯**，用之前先想清楚类型。
:::

## 一个不推荐但要知道的写法

```cpp
#include <cstdio>
#define int long long        // ⚠️ 知道有这回事，但不推荐
signed main() {              // 注意：main 必须写 signed
    int a = 1, b = 2;
    printf("%lld\n", a + b);
    return 0;
}
```

::: pitfall `#define int long long` 的三个坑
1. **`main` 必须改成 `signed main()`**，否则变成 `long long main()`，编译不过
2. **`scanf("%d", &x)` 全部要改成 `%lld`**——忘了就是读进垃圾值
3. **内存和常数都变大**：所有 `int` 都变成 8 字节，数组和速度都受影响

**它的诱惑是"不用再想溢出"，代价是"所有 `%d` 都得改"。**

正确做法还是老老实实：**该用 `long long` 的地方手动写 `long long`**。
:::

## 用宏的三条纪律

::: exam 宏的取舍标准
1. **能用真函数就不用宏**：`inline` 函数、`std::max`、`std::min` 都比宏安全
2. **宏必须两层括号**：参数一层、整体一层，一个都不能少
3. **绝不给宏传带副作用的参数**：`i++`、`--j` 一律不传

**宏越少越安全。** 一份模板里有两三个必要的宏就够了，
堆二十个宏的代码，出错时你连展开成什么样都看不出来。
:::

## 动手检查

1. 把 `sq(1 + 2)` 的展开式**手写出来**，确认是 `5`。
2. 把 `MAX(i++, j)` 展开成完整表达式，一步步推出 `i` 最终是多少。
3. 把上面那个 `qpow` 改成 `inline` 函数版本，确认结果一致。
4. 检查你自己的模板里：
   - 每个宏是不是都有两层括号？
   - 有没有哪个宏的参数可能带 `++`？
