# 对拍与随机数据

**样例只能测一种情况，而你写的代码一定有没想到的地方。**

对拍是唯一能在考场上"自己检查自己"的办法：**用慢但一定对的暴力，去验证快但不一定对的正解。**

## 本节学会什么

- 掌握对拍的三件套：**数据生成器 + 暴力 + 待验证程序**
- 会用固定种子生成可复现的随机数据
- 学会写一个能一直跑的对拍脚本
- 知道"对拍不过"之后该怎么定位

## 为什么需要它

你有没有过这种经历：

> 样例全过，感觉逻辑没问题，交上去 WA 了。
> 然后盯着代码看半小时，什么也没看出来。

问题在于**样例太弱**。它只验证了出题人挑出来的那一种情况，
而你代码里的 bug 藏在别的地方——`n = 1` 的时候、有负数的时候、
两个元素相等的时候。

::: exam 对拍解决的就是"我看不出来"
人**看不出自己的错误**，这是认知规律，不是能力问题。

所以不要靠"再看一遍"来检查逻辑，要靠**让程序自己比较**：

```text
随机生成数据  →  暴力跑一遍  →  你的程序跑一遍  →  比较两个结果
     ↑                                                      │
     └──────────── 不一致就说明有 bug，停下来分析 ←──────────┘
```

**几百组随机数据，通常几十组之内就能抓到 bug。**
:::

## 最小可运行示例：三件套

以「**最大子段和**」为例（求一段连续子数组的最大和）。

### ① 暴力程序 `brute.cpp`——慢，但一定对

<!-- expect
8
-2 11 -4 13 -5 -2 1 3
---
20
-->
```cpp
#include <cstdio>
using namespace std;

const int MAXN = 100005;
int a[MAXN];

int main() {
    int n;
    scanf("%d", &n);
    for (int i = 0; i < n; i++) scanf("%d", &a[i]);

    long long best = -1e18;
    for (int i = 0; i < n; i++) {          // 枚举起点
        long long sum = 0;
        for (int j = i; j < n; j++) {      // 枚举终点
            sum += a[j];
            if (sum > best) best = sum;
        }
    }
    printf("%lld\n", best);
    return 0;
}
```

### ② 待验证程序 `solve.cpp`——快，但可能错

<!-- expect
8
-2 11 -4 13 -5 -2 1 3
---
20
-->
```cpp
#include <cstdio>
using namespace std;

const int MAXN = 100005;
int a[MAXN];

int main() {
    int n;
    scanf("%d", &n);
    for (int i = 0; i < n; i++) scanf("%d", &a[i]);

    long long cur = 0, best = -1e18;
    for (int i = 0; i < n; i++) {
        cur = cur > 0 ? cur + a[i] : a[i];   // 前面的和是负的，不如从自己重新开始
        if (cur > best) best = cur;
    }
    printf("%lld\n", best);
    return 0;
}
```

### ③ 数据生成器 `gen.cpp`——随机造数据

```cpp
#include <cstdio>
#include <random>
using namespace std;

int main() {
    // 固定种子：每次生成的数据完全一样，便于复现问题
    mt19937 rng(20261013);

    int n = rng() % 10 + 1;              // n ∈ [1, 10]，先从小数据开始
    printf("%d\n", n);
    for (int i = 0; i < n; i++) {
        printf("%d ", (int)(rng() % 21) - 10);   // 数在 [-10, 10]，含负数
    }
    printf("\n");
    return 0;
}
```

::: range 数据生成器的三个要点
| 要点 | 为什么 |
| --- | --- |
| **从小数据开始** | `n = 5` 就能暴露的 bug，没必要用 `n = 10⁵` 去跑 |
| **一定要包含负数、0、重复值** | 这些正是边界 bug 的来源 |
| **数据规模要碰边界** | 偶尔生成 `n = 1`、`n = 最大值` |
:::

### ④ 对拍脚本

**Linux / NOI Linux**（`check.sh`）：

```bash
#!/bin/bash
g++ -std=c++17 -O2 -o brute brute.cpp
g++ -std=c++17 -O2 -o solve solve.cpp
g++ -std=c++17 -O2 -o gen   gen.cpp

for i in $(seq 1 1000); do
    ./gen > data.in
    ./brute < data.in > brute.out
    ./solve < data.in > solve.out
    if ! diff -q brute.out solve.out > /dev/null; then
        echo "第 $i 组数据不一致！数据已保存在 data.in"
        break
    fi
    echo "第 $i 组通过"
done
```

**Windows**（`check.bat`）：

```bat
@echo off
g++ -std=c++17 -O2 -o brute.exe brute.cpp
g++ -std=c++17 -O2 -o solve.exe solve.cpp
g++ -std=c++17 -O2 -o gen.exe gen.cpp

for /l %%i in (1,1,1000) do (
    gen.exe > data.in
    brute.exe < data.in > brute.out
    solve.exe < data.in > solve.out
    fc brute.out solve.out > nul
    if errorlevel 1 (
        echo 第 %%i 组数据不一致！数据已保存在 data.in
        goto :eof
    )
    echo 第 %%i 组通过
)
```

::: pitfall `diff` / `fc` 的一个坑
如果输出的**行尾多一个空格**，`diff` 会认为两行不同。

这其实帮了你：它顺便验证了输出格式。但也可能**误报**——
两个程序都多一个空格时，`diff` 反而会通过。

**所以对拍只验证"两个程序是否一致"，不验证格式是否符合题目要求。**
:::

## 关键过程与易错点

### 一、暴力程序必须"一定对"

对拍的逻辑是：

> **暴力是对的**（可能慢），如果正解和暴力不一致，那**正解错了**。

这个推理的前提是**暴力真的对**。所以暴力要写成最直白、最笨、最不容易错的版本：

| 别这样写暴力 | 要这样写 |
| --- | --- |
| 用了和正解一样的技巧 | 纯枚举，怎么看都对 |
| 用了优化 | 三层循环就三层循环 |
| 边界做了特殊处理 | 尽量不特判 |

**如果暴力也错了，对拍会告诉你"不一致"，但你会怀疑正解——白白浪费时间。**

### 二、数据要"有针对性"

纯随机数据能发现大部分 bug，但有几类问题它很难碰到。要**手工加几组**：

| 针对的问题 | 手造什么数据 |
| --- | --- |
| `n = 1` 边界 | `1` 加一个数 |
| 全是负数 / 全是 0 | 全 `-5`、全 `0` |
| 全相同 | 所有数一样 |
| 最大值 | `n` 取到题目上限，数值取到上限 |
| 溢出 | 数据大到求和会超 `int` |
| 多组数据 | 多组 + 每组规模不同 |

::: range 一个高效习惯：把"手造数据"也放进对拍
不用每次都手输。开一个 `special/` 目录，把几组手工数据存成文件，
对拍脚本先跑这些固定的，再跑随机。

**手造数据 + 随机数据**，覆盖率最高。
:::

### 三、对拍发现不一致之后

不要立刻改代码。先做这三步：

```text
1. 保住现场：data.in / brute.out / solve.out 不要动
2. 看清楚：打开 data.in，人肉算一遍（数据量小，能算）
3. 定位：确认到底哪个错了（先信暴力），再想为什么
```

::: exam 用"缩小数据"把 bug 逼出来
如果数据太大看不出规律，就**改生成器把规模调小**（比如 `n > 3` 就重生成），
让出问题的数据变得小到能在纸上一行一行算。

**能人工验算的最小数据，是最好的调试工具。**
:::

### 四、随机数的写法

| 写法 | 说明 | 建议 |
| --- | --- | --- |
| `rand()` | C 风格，范围小（约 32767），质量一般 | 简单场景够用 |
| `mt19937` | C++11 的梅森旋转，质量好 | **推荐** |
| `srand(time(0))` | 每次运行种子不同 | 平时可以；**复现问题时要固定种子** |
| 固定种子 | `mt19937 rng(12345)` | **对拍时推荐** |

::: pitfall 用 `time(0)` 做种子时无法复现
对拍时如果每次都换种子，那么"出问题的数据"你**再也造不出来了**——
下次跑种子变了，bug 可能不出现。

**对拍阶段：固定种子。**
找到一个出问题的种子后，那个种子的数据就是你调试的样本。
:::

## 动手检查

1. 把上面三件套**真的跑一遍**，确认 1000 组都能通过。
2. 故意把 `solve.cpp` 里改成 `cur = cur + a[i];`（去掉重新开始那一步），
   重新对拍，看第几组数据报不一致。
3. 打开报错的那组 `data.in`，在纸上手算一遍，确认暴力是对的。
4. 把生成器的 `n` 范围改成 `[1, 100]`，看会不会出现新的不一致。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 用三件套对拍一道你做过的简单题 | 完整走一遍流程 |
| 基础 | 把生成器改成"偶尔生成 n = 1" | 边界覆盖 |
| 巩固 | 用对拍找出你以前一道 WA 的题的真实原因 | 对拍的实战价值 |
| 巩固 | 给一道多组数据的题写生成器 | 多组数据的清空问题 |
| 挑战 | **在考场上**：正解写完后，用 15 分钟对拍验证 | 把对拍变成考场动作 |

::: pitfall 对拍有时间成本，要算账
写三件套 + 对拍，大概要 15～20 分钟。

**值不值？**

- 一道 100 分的题，你只有七成把握 → **值**，找出一个 bug 就是几十分
- 一道 20 分的题 → 不值，直接交
- 考试只剩 40 分钟 → 不值，去检查文件关和收尾清单

**对拍是"高价值题"才配用的工具。**
:::
