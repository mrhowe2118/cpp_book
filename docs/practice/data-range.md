# 数据范围表就是给分表

**拿到题目的第一件事不是想算法，是看数据范围。**

数据范围是出题人留给你最诚实的一份情报：它同时告诉你**该用什么算法**、**该用什么类型**、以及**这道题的分是怎么发的**。

## 本节学会什么

- 用数据范围反推目标复杂度，再反推算法
- 记住"1 秒能跑多少次运算"这个标尺
- 看懂 Subtask 分档：不会正解也能把低档分拿满
- 养成"读题三分钟先填表"的考场动作

## 为什么需要它

很多学生拿到题是这样想的：

> "这题……我好像见过，用二分？还是贪心？想不出来，先写个暴力吧。"

**这是在赌。** 而数据范围把赌博变成了查表。

同一道题，出题人给的数据范围不同，正解就完全不同：

| 数据范围 | 正解 |
| --- | --- |
| `n ≤ 20` | 爆搜 / 状压 DP |
| `n ≤ 5000` | O(n²) 的 DP 或贪心 |
| `n ≤ 10⁵` | 排序 + 二分 / 前缀和 / 单调栈 |
| `n ≤ 10⁹` | 二分答案 / 公式 / 快速幂 |

**你不需要"感觉"该用什么，你只需要量一下 n 有多大。** 90% 的情况下，答案就在范围里写着。

::: exam 这条最值钱
数据范围**不是题目的装饰**，它是**给分表**。
出题人按数据分档给分，而每一档的边界，都在告诉你那一档该写什么。
**看懂它，你就知道先写什么、后写什么、写不出来时至少能保住多少分。**
:::

## 关键过程与易错点

### 标尺：1 秒能跑多少次运算

评测机的时间限制一般是 1 秒（有时 2 秒）。你需要一个换算标尺：

::: range 本书统一使用的估算法
**1 秒 ≈ 10⁸ 次简单运算**（加减、比较、数组访问）。

按这个标尺反推：

| 数据范围 | 允许的复杂度 | 常见算法 |
| --- | --- | --- |
| `n ≤ 20` | O(2ⁿ)、O(n!) | 爆搜、全排列、状压 |
| `n ≤ 300` | O(n³) | Floyd、区间 DP |
| `n ≤ 5000` | O(n²) | 朴素 DP、二维枚举 |
| `n ≤ 10⁵` | **O(n log n)** | 排序、二分、前缀和、堆 |
| `n ≤ 10⁶` | O(n) | 线性扫描、桶计数 |
| `n ≤ 10⁹` 或更大 | O(log n)、O(1) | 二分答案、公式、快速幂 |

**先量 n，再查表，最后才想具体算法。** 顺序反了，就会在错误的方向上浪费半小时。
:::

::: pitfall 这个标尺要留余量
`n ≤ 10⁵` 时写 O(n²) 是 10¹⁰ 次运算——**超时 100 倍**，不是"慢一点"。
反过来，`n ≤ 5000` 时写 O(n²)（2500 万次）**完全来得及**，这时候硬凑 O(n log n) 是浪费时间。

另外：常数因子很关键。同样是 O(n log n)，`sort` 比手写冒泡快得多；
`cin/cout` 不加优化可能比 `scanf/printf` 慢好几倍。
**标尺是粗略的，但"差一个数量级"的判断从不出错。**
:::

### 实操：把范围翻译成方案

看一道自己出的题：

> 给 n 个数 a₁..aₙ，有 m 次询问，每次问区间 `[l, r]` 内所有数的和。
> 数据范围：`n, m ≤ 10⁵`，`|aᵢ| ≤ 10⁹`，`1 ≤ l ≤ r ≤ n`。

先在纸上填这张表：

| 从范围里读到 | 推出了什么 |
| --- | --- |
| `n, m ≤ 10⁵` | 目标复杂度是 O(n log n) 或 O(n) |
| 有 m 次询问 | 不能每次重新扫一遍（那就是 O(nm) = 10¹⁰，TLE） |
| `|aᵢ| ≤ 10⁹` | 单个数 `int` 装得下 |
| 但要求和，且 n 是 10⁵ | **和最大到 10¹⁴，`int` 装不下 → 必须 `long long`** |
| `l ≤ r` | 不用处理空区间 |

于是结论出来了：**用前缀和 + `long long`。**

```cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;
long long a[MAXN], s[MAXN];   // s[i] = a[1] + ... + a[i]

int main() {
    int n, m;
    cin >> n >> m;
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        s[i] = s[i - 1] + a[i];       // 预处理 O(n)
    }
    while (m--) {
        int l, r;
        cin >> l >> r;
        cout << s[r] - s[l - 1] << '\n';   // 每次询问 O(1)
    }
    return 0;
}
```

**注意最后一行推出来的 `long long`——那是数据范围给的第二个答案。**
《数据类型与溢出》那一节讲的是"怎么选类型"，这一节讲的是"从哪里知道该选什么类型"。

::: pitfall 只看 n，不看数值范围
`n ≤ 10⁵` 只决定了**复杂度**。**数值范围**决定**类型**，两者要分别读。

容易被忽略的三种：
1. `aᵢ` 没超 `int`，但**求和**超了 → 累加变量用 `long long`
2. 有**乘法**（组合数、面积、乘积）→ 提前转 `long long`
3. 答案要**取模** → 每一步都要取模，不能只在最后取
:::

### Subtask：分档就是给分点

很多题（尤其复赛第一、二题）的数据是**分档**的，每档单独给分：

| 档位 | 数据范围 | 能用什么 | 大致分值 |
| --- | --- | --- | --- |
| 1 | `n ≤ 20` | 爆搜 | 20～30 |
| 2 | `n ≤ 1000` | O(n²) | +20 |
| 3 | `n ≤ 10⁵` | 正解 | +50 |

**这张表的意思是：你不会正解，也应该拿到前两档。**

::: exam 考场上的分档策略
1. **先把最低档的暴力写出来、跑对、交上去。** 拿到 20～30 分，比对着正解空想 40 分钟强。
2. **再想 O(n²) 的中间档。** 通常比正解容易得多，往往是"去掉优化"的版本。
3. **最后才尝试正解。** 时间不够就保住已有的分。

**复赛不是"要么满分要么零分"。** 会分档拿分的人，总分比死磕正解的人高得多。
:::

### 读题三分钟：固定动作

拿到任何一道题，先花三分钟填这张表，**不要碰键盘**：

1. **输入什么？** 几个数、什么格式、有没有多组数据
2. **n 有多大？** 写出量级（10⁵ 还是 10⁹）
3. **目标复杂度是多少？** 查上面的标尺
4. **数值范围？** 会不会溢出，要不要 `long long`，要不要取模
5. **有几档数据？** 最低档能拿多少分

填完再开始写。这三分钟能省下后面三十分钟的乱撞。

::: pitfall 顺便把"多测"的坑记住
如果题目说"**多组数据**"（`T` 组），那么：

- 每次都要**重新读入**，别把上一次的数据带进这一次
- 全局数组、累加变量、标记数组**必须清空**
- 清空方式：整段 `memset` 或用循环重置

**"多组数据没清空"是复赛丢分榜上的常客**，在《结果关》里会专门讲。
:::
