# list 链表（选读）

::: exam 先说结论：**竞赛里几乎用不到 `list`**
它属于"知道有这个东西、看得懂别人代码"的范畴。

**但它的思维方式（链表）很重要**——很多算法（邻接表、链式前向星）都用这个思路，
只不过实现上用**数组模拟**而不是 `list`。

**这一节读一遍就行，不用练熟。**
:::

## 本节学会什么

- 知道 `list` 是双向链表，擅长"任意位置插入删除"
- 知道它的两个致命短板：**不能随机访问、不能配合需要随机访问的算法**
- 理解为什么竞赛里更常用**数组模拟链表**
- 看得懂用了 `list` 的代码

## 为什么需要它

`list` 和 `vector` 是两种完全不同的存储方式：

| | `vector` | `list` |
| --- | --- | --- |
| 内存布局 | **连续**（挨着放） | 分散（每个元素单独一块，用指针连起来） |
| 随机访问 `v[i]` | ✅ O(1) | ❌ **不支持** |
| 中间插入 / 删除 | O(n)（要搬后面的元素） | **O(1)**（改两个指针） |
| 内存开销 | 小 | **大**（每个元素都要存前后指针） |
| 缓存友好度 | **好** | 差 |

::: exam 关键差别：访问 vs 修改
```text
vector：找第 i 个很快（地址直接算），但中间插一个要搬走后面所有元素
list：  插一个很快（改指针），但找第 i 个要从头一个个走过去
```

**"插入快"的前提是"你已经站在那个位置了"。**
而"走到那个位置"本身就要 O(n)——**所以优势常常被抵消。**
:::

## 最小可运行示例

<!-- expect

---
1 2 3 5
-->
```cpp
#include <cstdio>
#include <list>
using namespace std;

int main() {
    list<int> l;

    l.push_back(1);
    l.push_back(3);
    l.push_back(5);

    // 在第二个元素前面插入 2
    auto it = l.begin();
    ++it;                        // 现在指向 3
    l.insert(it, 2);             // 在 3 前面插入 2

    for (int x : l) printf("%d ", x);
    printf("\n");

    // 注意：list 不能用下标访问
    // printf("%d\n", l[0]);     // ✗ 编译错误

    return 0;
}
```

输出 `1 2 3 5`。

## 关键过程与易错点

### 一、`list` 的两个"不能"

::: pitfall 一：不能用下标
```cpp
list<int> l = {1, 2, 3};
cout << l[0];                // ✗ 编译错误
```

**原因**：链表里的元素不是连续存放的，没法"首地址 + i × 大小"算出第 i 个的位置。

**只能从头一个个走**：

```cpp
auto it = l.begin();
advance(it, 2);              // 往后走 2 步，指向第 3 个元素
cout << *it;
```

**注意 `advance` 是 O(n) 的**——走 k 步就是 k 次操作。
:::

::: pitfall 二：不能直接用 `sort(begin, end)`
```cpp
sort(l.begin(), l.end());    // ✗ 编译错误！
```

**因为标准库的 `sort` 需要"随机访问迭代器"**（能一步跳到任意位置），
而 `list` 只有"双向迭代器"（只能一步步挪）。

**必须用 `list` 自己的成员函数**：

```cpp
l.sort();                    // ✓ 成员函数，O(n log n)
l.sort(greater<int>());      // 降序
```

**这个细节很能说明问题**：`list` 连"排序"都得特殊处理，
**说明它和通用算法的配合是有代价的。**
:::

::: range 迭代器的五种能力（了解）
| 能力 | 能做什么 | 哪些容器 |
| --- | --- | --- |
| 随机访问 | `it + 5`、`it[3]` | `vector`、`deque`、数组 |
| 双向 | `++it`、`--it` | `list`、`set`、`map` |
| 单向 | 只能 `++it` | `forward_list` |

**`sort` 要求随机访问**，所以只能用于 `vector` / `deque` / 数组。
`set` / `map` 本身有序，不需要排。
`list` 只能用自己的 `sort`。
:::

### 二、`list` 真正擅长的场景

| 场景 | `list` 合适吗 |
| --- | --- |
| 频繁在**已知位置**插入删除 | ✅ 合适 |
| 需要随机访问 | ❌ 用 `vector` |
| 需要遍历 + 少量插入 | `vector` 通常更快（缓存友好） |
| 需要排序 | 用 `vector`（`sort` 更快） |
| **竞赛里的绝大多数需求** | **`vector` 或数组** |

::: exam 为什么 `vector` 常常更快（即使理论上更慢）
**因为 CPU 缓存偏爱连续内存。**

```text
vector：元素挨着放 → 一次读进缓存，后面几十个都能直接用
list：  元素散在各处 → 每读一个都可能要访问内存
```

**结果**：`list` 的"O(1) 插入"优势，常常被"缓存不友好"抵消掉。

**结论：不要因为"插入快"就选 `list`。** 先测一下再说——而在竞赛里，
你通常没时间测，**所以用 `vector`**。
:::

### 三、竞赛里的"链表"长什么样

**真正的链表思路在竞赛里用得很广**，但实现方式是**数组模拟**：

```cpp
// 用数组模拟链表
const int MAXN = 100005;
int val[MAXN];               // 每个节点的值
int nxt[MAXN];               // 下一个节点的下标（0 表示空）
int head = 0, tot = 0;       // 头指针、节点计数器

// 在头部插入
void pushFront(int x) {
    val[++tot] = x;
    nxt[tot] = head;
    head = tot;
}

// 遍历
for (int p = head; p; p = nxt[p]) {
    printf("%d ", val[p]);
}
```

**为什么用数组模拟？**

| 优势 | 说明 |
| --- | --- |
| 快 | 没有动态内存分配，缓存友好 |
| 好调试 | 可以直接看 `val[i]`、`nxt[i]` |
| 可控 | 内存是一次性分配好的 |

**图论里的"链式前向星"就是这种写法**（`head[]` + `nxt[]` + `to[]`）。

**所以你该记的是"链表的思想"，不是 `list` 这个容器。**
:::

### 四、`list` 的成员函数速查（看得懂就行）

| 操作 | 写法 |
| --- | --- |
| 头/尾插入 | `l.push_front(x)` / `l.push_back(x)` |
| 头/尾删除 | `l.pop_front()` / `l.pop_back()` |
| 插入 | `l.insert(it, x)` — 在 `it` 前插入 |
| 删除 | `l.erase(it)` — 返回下一个位置 |
| 排序 | `l.sort()` |
| 去重 | `l.unique()` — **只去相邻重复** |
| 反转 | `l.reverse()` |
| 大小 | `l.size()` |
| 清空 | `l.clear()` |

**注意 `unique()` 也是成员函数**，原因和 `sort` 一样（迭代器能力不够）。

::: pitfall 这一节的"考点"其实是概念
没有人会在比赛里让你用 `list` 写题。

**但"链表"这个概念会反复出现**：

- 图论的邻接表（`vector<int> g[]`）
- 链式前向星（`head[]` + `nxt[]`）
- 并查集的路径压缩
- 哈希表的拉链法

**理解了"用指针/下标把分散的节点串起来"这个思路，
后面学这些都会轻松很多。**
:::
