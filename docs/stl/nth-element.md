# nth_element 第 k 小

只要**第 k 小**的那个数，不需要全部排好序——这种情况用 `nth_element`，平均 O(n)。

比 `sort` 的 O(n log n) 更快。

## 本节学会什么

- 用 `nth_element` 求"第 k 小"和"第 k 大"
- 理解它**只保证一个位置是对的**
- 知道它为什么比 `sort` 快
- 知道什么时候用 `nth_element`、什么时候还是得 `sort`

## 为什么需要它

看一个常见需求：**求中位数**（也就是第 `n/2` 小的数）。

| 做法 | 复杂度 |
| --- | --- |
| `sort` 后取中间 | O(n log n) |
| **`nth_element`** | **平均 O(n)** |

::: exam 为什么能更快
**因为"排序"做了很多你不需要的工作。**

```text
需求：只要知道第 3 小的是谁

sort：            把 7 个数全部排好序      做了很多无用功
nth_element：     只把"该在位置 2 的那个"放对  其他位置不管
```

**`nth_element` 用的是"快速选择"算法**（和快排同源，但只递归一边），
所以平均复杂度是 O(n)。
:::

## 最小可运行示例

<!-- expect

---
第 3 小 = 3
第 2 大 = 8
-->
```cpp
#include <cstdio>
#include <algorithm>
#include <functional>
using namespace std;

int main() {
    int a[7] = {5, 3, 8, 1, 9, 2, 7};
    int n = 7;

    // 找第 3 小：它应该排在【下标 2】（下标从 0 开始）
    nth_element(a, a + 2, a + n);
    printf("第 3 小 = %d\n", a[2]);

    // 找第 2 大：加 greater，它应该排在【下标 1】
    nth_element(a, a + 1, a + n, greater<int>());
    printf("第 2 大 = %d\n", a[1]);

    return 0;
}
```

原数组排序后是 `1 2 3 5 7 8 9`：

- 第 3 小 = `3` ✓
- 第 2 大 = `8` ✓

::: range 参数怎么写
```cpp
nth_element(起点, 目标位置, 终点);

// 求第 k 小（k 从 1 开始数）
nth_element(a, a + (k - 1), a + n);      // 结果在 a[k-1]

// 求第 k 大
nth_element(a, a + (k - 1), a + n, greater<int>());   // 结果在 a[k-1]
```

**最容易错的就是下标**：

| 想求 | 目标位置 |
| --- | --- |
| 第 1 小（最小值） | `a + 0` |
| 第 k 小 | **`a + (k - 1)`** ← 别忘了减 1 |
| 第 n 小（最大值） | `a + (n - 1)` |

**记法：`nth_element` 的第二个参数是"下标"，不是"第几"。**
:::

## 关键过程与易错点

### 一、它只保证"那一个位置"

::: pitfall 别以为调用之后数组有序了
```cpp
int a[7] = {5, 3, 8, 1, 9, 2, 7};
nth_element(a, a + 2, a + n);

// ✗ 错误假设：以为 a 已经排好序
for (int i = 0; i < 7; i++) cout << a[i] << ' ';
```

**它保证的只有两件事**：

1. **`a[2]` 就是第 3 小的数**（正确）
2. `a[0]`、`a[1]` 都不大于它，`a[3]` 及之后都不小于它

**其他位置的顺序是"不确定的"**——不同编译器、不同数据都可能不一样。

**所以：**

- 只要第 k 小 → 用 `nth_element` ✅
- 需要完整有序 → 用 `sort` ✅
:::

### 二、`nth_element` vs `sort`：怎么选

| 需求 | 用什么 |
| --- | --- |
| 完整有序 | `sort` |
| **只要第 k 小 / 中位数** | **`nth_element`** |
| 要前 k 小（但不要求内部有序） | `nth_element(a, a + k - 1, a + n)` |
| 要前 k 小**且内部有序** | 先 `nth_element` 再对前 k 个 `sort` |
| 数据量很小（几百） | `sort` 就行，差别可忽略 |

::: range 一个经典组合
```cpp
// 求前 3 小的数（有序）
nth_element(a, a + 3, a + n);      // 前 3 个就是最小的 3 个（顺序不定）
sort(a, a + 3);                     // 再把这 3 个排好
```

**这样比"整体 sort"快**：整体是 O(n log n)，
而 `nth_element` + 部分 `sort` 是 O(n + k log k)。

**k 远小于 n 时，差距很明显。**
:::

### 三、中位数：最常用的场景

```cpp
int n = 7;
nth_element(a, a + n / 2, a + n);
int median = a[n / 2];              // 中位数
```

**注意**：`n` 是偶数时，"中位数"的定义要看题目
（是取中间两个的平均，还是取较小的那个）。

```cpp
// 偶数个时取中间两个的平均
int a1 = ...;                       // 第 n/2 小
int a2 = ...;                       // 第 n/2 + 1 小
```

**做题时先看清题目怎么定义"中位数"。**

### 四、它是"平均 O(n)"，不是"保证 O(n)"

**`nth_element` 用的是快速选择**，最坏情况（每次选的基准都很偏）会退化到 O(n²)。

| 场景 | 风险 |
| --- | --- |
| 随机数据 | 几乎不会退化 |
| 出题人故意构造的数据 | **理论上可能被卡** |

::: pitfall 竞赛里的实际处理
**绝大多数题目随机数据下 `nth_element` 都很稳。**

**如果担心被卡**（比如需要严格 O(n log n)），有几条路：

1. 直接用 `sort`（O(n log n)，稳）
2. 用 `priority_queue` 维护前 k 个（O(n log k)）
3. 用"随机打乱后 `nth_element`"

**竞赛建议**：不确定就用 `sort`。差值只有 log n 倍，
**但 `sort` 的行为完全可预测**。
:::

### 五、别忘了包含头文件

```cpp
#include <algorithm>          // sort / nth_element 都在这里
#include <functional>         // greater<int> 在这里
```

## 动手检查

1. 用 `sort` 和 `nth_element` 分别求同一个数组的中位数，确认结果一致。
2. 调用 `nth_element` 后**打印整个数组**，看看它是不是有序的（观察"部分有序"）。
3. 求第 1 小和第 n 小（即最小值和最大值），验证下标是 `0` 和 `n-1`。
4. 用 `nth_element` + 部分 `sort` 求"前 3 小的数（有序）"。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 读入 n 个数，输出第 k 小的数 | `nth_element` |
| 基础 | 读入 n 个数，输出中位数 | `nth_element` |
| 基础 | 读入 n 个数，输出第 k 大的数 | `greater<int>` |
| 巩固 | 输出前 k 小的数（要求内部有序） | `nth_element` + `sort` |
| 巩固 | [洛谷 P1138 第 k 小整数](https://www.luogu.com.cn/problem/P1138) | 去重 + 第 k 小 |
| 挑战 | 用 `nth_element` 求"第 k 小"的最坏复杂度分析 | 理解快速选择 |

::: pitfall P1138 是"去重 + 第 k 小"的组合
它要求先**去重**再找第 k 小。

所以顺序是：

```cpp
sort(a, a + n);                        // 排序
int m = unique(a, a + n) - a;          // 去重
// 此时已经有序了，直接输出 a[k-1] 就行
```

**注意**：这道题里既然已经为了去重排了序，就**不需要 `nth_element` 了**——
直接取下标即可。

**这正是选型的关键：先看题目还要求什么。**
如果需要排序（去重、找相邻），那就顺手 `sort` 完；
如果**只要第 k 小**，才用 `nth_element`。
:::
