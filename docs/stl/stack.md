# stack 栈

栈是**后进先出**（LIFO）的容器：最后放进去的，最先拿出来。

它看起来简单，但"括号匹配""表达式求值""撤销操作"这类问题**天生就是栈**。

## 本节学会什么

- 理解 LIFO（后进先出）
- 掌握 `push` / `pop` / `top` / `empty` 四个操作
- 知道 `stack` **不能遍历**，以及为什么
- 会用栈解决括号匹配这类问题
- 知道怎么用数组模拟一个栈

## 为什么需要它

先想一个日常场景：**浏览器的"后退"**。

你访问 A → B → C，按后退应该回到 B，再按回到 A。

```text
访问顺序：A, B, C
后退顺序：B, A     ← 正好是"反过来"
```

**"最后访问的最先返回"就是 LIFO。** 用栈存访问记录，后退就是 `pop`。

::: exam 栈的规则只有一句
```text
只能从一端进出：
   push  →  放到顶上
   top   →  看顶上是什么（不拿走）
   pop   →  把顶上拿走

后放的先拿，先放的后拿。
```

**就像一摞盘子：你只能拿最上面那个。**
:::

## 最小可运行示例

<!-- expect
(())
---
YES
-->
```cpp
#include <iostream>
#include <stack>
#include <string>
using namespace std;

int main() {
    string s;
    cin >> s;

    stack<char> st;
    bool ok = true;

    for (char c : s) {
        if (c == '(') {
            st.push(c);                       // 左括号：入栈
        } else if (c == ')') {
            if (st.empty()) {                 // 没有左括号可以配对
                ok = false;
                break;
            }
            st.pop();                         // 配对成功，弹出一个
        }
    }

    if (!st.empty()) ok = false;              // 还有没配对的左括号

    cout << (ok ? "YES" : "NO") << '\n';
    return 0;
}
```

输入 `(())`，输出 `YES`。

::: range 括号匹配为什么是栈
```text
输入 ( ( ) )
      ↑
      push  → 栈：[ ( ]

输入   ( ( ) )
        ↑
        push  → 栈：[ ( ( ]

输入   ( ( ) )
          ↑
          遇到 )，pop 一个 → 栈：[ ( ]     ✓ 配对

输入   ( ( ) )
            ↑
            遇到 )，pop 一个 → 栈：[ ]      ✓ 配对

结束，栈空 → 匹配成功
```

**关键洞察**：右括号必须和**最近的、还没配对的**左括号配对。
而"最近的、还没配对的"正是**栈顶**。

**每当你听到"最近的""嵌套的""撤回"这类词，就该想到栈。**
:::

## 关键过程与易错点

### 一、只有四个操作

| 操作 | 写法 | 说明 |
| --- | --- | --- |
| 入栈 | `st.push(x);` | 放到栈顶 |
| 出栈 | `st.pop();` | 拿掉栈顶（**不返回值**） |
| 看栈顶 | `st.top();` | 只看不拿 |
| 判空 | `st.empty();` | **用之前必须判空** |
| 元素个数 | `st.size();` | |

::: pitfall `pop()` 不返回元素，要用 `top()` 先取
```cpp
int x = st.pop();        // ✗ 编译错误：pop 返回 void
```

正确写法是**两步**：

```cpp
int x = st.top();        // ① 先看
st.pop();                // ② 再拿掉
```

**为什么这样设计？** 因为 `pop` 如果返回值，在"返回时拷贝失败"的情况下
会丢掉数据。标准库选择了"安全但多一步"的设计。

**记法：`top` 拿值，`pop` 只删。**
:::

::: pitfall 空栈上 `top()` 或 `pop()` 是未定义行为
```cpp
stack<int> st;
cout << st.top();        // ✗ 未定义行为！可能输出垃圾值，也可能崩溃
st.pop();                // ✗ 同样危险
```

**`stack` 不做任何越界检查。** 所以：

```cpp
if (!st.empty()) {
    cout << st.top();
    st.pop();
}
```

**纪律：每次 `top()` / `pop()` 之前，先问一句"栈可能空吗"。**

这个错误在括号匹配、表达式求值里特别常见——
**"右括号比左括号多"就是空栈弹出的典型场景。**
:::

### 二、`stack` 不能遍历

```cpp
for (int x : st) { }             // ✗ 编译错误！stack 没有迭代器
cout << st[0];                   // ✗ 也没有下标
```

::: exam 为什么故意不给遍历
**因为"遍历栈"在语义上是不该做的事。**

栈的语义是"只能访问栈顶"。允许你随便看中间的元素，
就等于破坏了这个抽象——那你还不如直接用 `vector`。

**这其实是好事**：它逼着你按栈的方式思考。

**如果你真的需要遍历中间的（比如调试），说明栈可能不是合适的结构。**
:::

### 三、用数组模拟栈

竞赛里有时会用数组手写栈（更快，或者需要访问中间元素）：

```cpp
const int MAXN = 100005;
int st[MAXN];
int top = 0;                     // top 指向栈顶元素的下标；0 表示空

// push
st[++top] = x;

// top
int x = st[top];

// pop
top--;

// 判空
if (top == 0) { }                // 空
```

::: range 什么时候用数组模拟
| 场景 | 建议 |
| --- | --- |
| 普通使用 | **`stack<int>`**，语义清楚 |
| 需要访问中间元素 | **数组**（`stack` 做不到） |
| 需要极高的速度 | 数组（省掉容器开销） |
| 需要 `stack` 里存结构体 | 都可以，但数组模拟更省内存 |

**注意**：用手写栈时 `top` 这个变量名**撞标准库**吗？
不会——`top` 不是标准库名字。但 `stack` 是，别把变量叫 `stack`。
:::

### 四、典型应用场景

| 问题 | 为什么用栈 |
| --- | --- |
| **括号匹配** | 最近的未配对左括号 |
| **表达式求值** | 运算符优先级 + 括号 |
| **单调栈**（下一个更大元素） | 维护"还没找到答案"的元素 |
| **DFS 的非递归写法** | 用栈模拟递归 |
| **撤销 / 回退** | 后进先出 |

::: pitfall 单调栈是栈最重要的进阶用法
**"求每个元素右边第一个比它大的数"**——这类题用栈能在 O(n) 内解决。

思路：栈里维护一个"递减"的序列，遇到更大的数就弹出栈顶并记录答案。

**现在不用急着学**，只要记住：**"找下一个更大/更小" → 想单调栈**。

（这块内容属于进阶，本书不展开。）
:::

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 读入一个字符串，用栈翻转后输出 | `push` / `pop` |
| 基础 | [洛谷 P1739 表达式括号匹配](https://www.luogu.com.cn/problem/P1739) | 括号匹配 |
| 巩固 | 判断一个字符串是不是回文（用栈实现） | 栈 + 队列对比 |
| 巩固 | [洛谷 P1449 后缀表达式](https://www.luogu.com.cn/problem/P1449) | **栈的经典应用**：后缀表达式求值 |
| 挑战 | [洛谷 P1996 约瑟夫问题](https://www.luogu.com.cn/problem/P1996) | 队列模拟（下一节的主角） |

::: pitfall P1449 是"栈"的真正入门题
后缀表达式（逆波兰式）求值的规则：

```text
遇到数字 → 入栈
遇到运算符 → 弹出两个数，运算，结果压回栈
最后栈里剩下的就是答案
```

**为什么用栈？** 因为运算符要作用于**最近的两个操作数**——
又是"最近"，又是栈。

做完这道题，你就真的理解栈了。
:::
