# unique 去重

`unique` 把**相邻的**重复元素"搬到后面"，返回新的尾位置。

**注意两个关键词：相邻、搬到后面**——这两点决定了它的用法和坑。

## 本节学会什么

- 掌握 `sort` + `unique` + 计算长度的标准三连
- 理解 `unique` 为什么**必须先排序**
- 知道 `unique` 并不会真的删除元素
- 会写 `vector` 版本和数组版本

## 为什么需要它

先看一个需求：**给 n 个数，输出去重后有多少个不同的数。**

不用 `unique`，你得手写：

```cpp
sort(a, a + n);
int cnt = 1;
for (int i = 1; i < n; i++) {
    if (a[i] != a[i - 1]) cnt++;
}
```

用 `unique` 只要一行：

```cpp
sort(a, a + n);
int m = unique(a, a + n) - a;        // m 就是"不同数的个数"
```

::: exam 标准三连：排序 → 去重 → 用返回值
```cpp
sort(a, a + n);                       // ① 排序（必须）
int m = unique(a, a + n) - a;         // ② 去重，m 是新的有效长度
// ③ 之后只用前 m 个元素
```

**这三步是一个整体，少一步都会出错。**
:::

## 最小可运行示例

<!-- expect

---
m = 3
1 2 3
-->
```cpp
#include <cstdio>
#include <algorithm>
using namespace std;

int main() {
    int a[8] = {3, 1, 3, 2, 1, 2, 3, 1};
    int n = 8;

    sort(a, a + n);                       // ① 排序
    int m = unique(a, a + n) - a;         // ② 去重，拿到新长度

    printf("m = %d\n", m);

    for (int i = 0; i < m; i++) {         // ③ 只用前 m 个
        printf("%d ", a[i]);
    }
    printf("\n");

    return 0;
}
```

输出：

```text
m = 3
1 2 3
```

### `unique` 到底做了什么

```text
原数组（已排序）：  1  1  1  2  2  3  3  3
                    ↑
              unique 把不重复的往前搬：

处理后：            1  2  3  ?  ?  ?  ?  ?
                             ↑
                     后面这些是"残留"，值不确定
                    unique 返回的迭代器指向这里

unique(...) - a = 3   ← 前 3 个是有效数据
```

::: exam 两个关键事实
1. **它是"搬"不是"删"**：数组长度没变，只是把不重复的挪到了前面
2. **返回值才是新长度**：必须用它，不能继续用原来的 `n`

**记法：`unique` 返回"新结尾在哪"，你要自己去用这个信息。**
:::

## 关键过程与易错点

### 一、前提：必须先排序

<!-- expect

---
m = 6
3 1 3 2 1 2
-->
```cpp
#include <cstdio>
#include <algorithm>
using namespace std;

int main() {
    int a[6] = {3, 1, 3, 2, 1, 2};        // ✗ 没有排序
    int m = unique(a, a + 6) - a;

    printf("m = %d\n", m);
    for (int i = 0; i < m; i++) printf("%d ", a[i]);
    printf("\n");
    return 0;
}
```

输出：

```text
m = 6
3 1 3 2 1 2
```

**一个都没去掉！**

::: pitfall `unique` 只处理"相邻"的重复
`unique` 的实现就是"**比较相邻两个元素，相同就跳过**"。

```text
{3, 1, 3, 2, 1, 2}
 ↑  ↑            3 和 1 不同，留着
    ↑  ↑         1 和 3 不同，留着
       ↑  ↑      3 和 2 不同，留着
          ...
没有任何相邻的重复 → 一个都删不掉
```

**所以必须先用 `sort` 把它们排到一起。**

**这是 `unique` 唯一的坑，也是最容易忘的一步。**
:::

### 二、`vector` 版本：配合 `erase` 真正"删掉"

数组版本只能"假装截断"（记住 `m`）。
`vector` 可以真的删掉多余元素：

```cpp
sort(v.begin(), v.end());
v.erase(unique(v.begin(), v.end()), v.end());      // ✓ 一行完成
```

**这句话的含义**：把"从新结尾到原来的结尾"这一段全部删掉。

| 版本 | 写法 | 之后怎么用 |
| --- | --- | --- |
| 数组 | `int m = unique(a, a+n) - a;` | 只用前 `m` 个 |
| `vector` | `v.erase(unique(v.begin(), v.end()), v.end());` | 直接用 `v`，它的 `size()` 已经对了 |

::: range 数组版和 vector 版怎么选
| 场景 | 建议 |
| --- | --- |
| 数据用普通数组存的 | 记住 `m`，循环用 `i < m` |
| 数据用 `vector` 存的 | 用 `erase` 真正删掉，后面代码更干净 |
| 之后还要用原数组的全部数据 | **不要**用 `erase`（会丢失数据） |

**数组版更轻，vector 版更清晰。** 竞赛里两种都很常见。
:::

### 三、`unique` 也能自定义"什么算重复"

默认是"值相等"。可以传第三个参数指定判断规则：

```cpp
// 认为"除以 10 的余数相同"就算重复
bool sameMod10(int a, int b) {
    return a % 10 == b % 10;
}
int m = unique(a, a + n, sameMod10) - a;
```

**注意**：这个规则也必须**只对相邻元素生效**，
所以还是要先按同样的规则排序，让"该算重复的"排在一起。

::: pitfall 自定义规则的排序和去重必须"口径一致"
```cpp
sort(a, a + n, cmpByMod10);                    // 按余数排序
int m = unique(a, a + n, sameMod10) - a;       // 按余数去重
```

**如果排序用一套规则、去重用另一套**，`unique` 就找不到相邻的重复，
结果和没去重一样。

**这种 bug 很隐蔽**：两行代码看起来都对，只是不匹配。
:::

### 四、和 `set` 的对比

| | `sort` + `unique` | `set` |
| --- | --- | --- |
| 代码 | 3 行 | 插入时自动完成 |
| 复杂度 | O(n log n) | O(n log n) |
| 需要下标访问 | ✅ 可以 | ❌ 不行 |
| 后续还要查找 | 要再二分 | 天然支持 |
| 常数 | **小** | 大 |

::: exam 怎么选
```text
只需要"去重后有哪几个数，按顺序输出"
  → 两者都行；数据量大时 sort + unique 常数更小

之后还要反复查询"某个数在不在"
  → set

需要用下标访问第 k 个
  → sort + unique（set 做不到）
```

**共同点：两者都要求最后结果是"有序"的**——
`sort + unique` 是有序的，`set` 也是有序的。

**如果题目只要"去重"不要"有序"**，可以用哈希（`unordered_set`），
但竞赛里为了稳，通常还是排序去重。
:::

### 五、完整模板

**数组版**：

```cpp
sort(a, a + n);
int m = unique(a, a + n) - a;
// 之后统一用 m，不要再用 n
for (int i = 0; i < m; i++) { /* ... */ }
```

**vector 版**：

```cpp
sort(v.begin(), v.end());
v.erase(unique(v.begin(), v.end()), v.end());
// 之后直接用 v.size()
```

::: pitfall 最容易犯的三个错
| 错误 | 症状 |
| --- | --- |
| 忘了 `sort` | 一个都没去掉，`m` 还是 `n` |
| 忘了用返回值 | 后面还在用原来的 `n`，多循环了无效数据 |
| 以为 `unique` 删了元素 | 直接输出整个数组，末尾出现垃圾值 |

**第二条尤其隐蔽**：如果残留的"无效数据"恰好数值正常，
程序不会崩，只是**结果里多了几个不该有的数**。
:::

## 动手检查

1. 把示例里的 `sort` 注释掉，运行看 `m` 变成几。
2. 用 `unique` 之后**不**使用返回值（继续用 `n` 循环输出），看末尾出现什么。
3. 用 `vector` + `erase` 版本重写一遍，确认 `v.size()` 就是去重后的个数。
4. 对比 `sort + unique` 和 `set` 两种去重写法，数一数各写了几行。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 读入 n 个数，排序去重后输出个数和每个数 | `sort` + `unique` |
| 基础 | [洛谷 P1059 明明的随机数](https://www.luogu.com.cn/problem/P1059) | **排序去重的经典题** |
| 巩固 | 用 `vector` + `erase` 版本重做上面一题 | `vector` 的去重写法 |
| 巩固 | 统计数组里有多少个不同的数（两种写法对比） | `unique` vs `set` |
| 挑战 | 给 n 个数，去重后输出第 k 小的数（不用 `set`） | `sort` + `unique` + 下标 |

::: pitfall P1059 可以写两遍
**第一遍**用 `sort + unique`，**第二遍**用 `set`。

写完之后对比：
- 哪个代码短？
- 哪个更容易理解？
- 如果要**按原顺序**输出去重结果，哪个能做到？

**亲手对比过，选型就不靠猜了。**
:::
