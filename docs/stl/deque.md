# deque 双端队列

`deque`（读作 "deck"）是**两端都能高效插入删除**的队列：
既能在队尾进出，也能在队头进出——**而且还能用下标访问**。

## 本节学会什么

- 掌握 `push_front` / `push_back` / `pop_front` / `pop_back`
- 知道 `deque` 比 `queue` 多了什么、比 `vector` 强在哪
- 会用 `deque` 实现**单调队列**（滑动窗口最大值）
- 知道什么时候**不该**用 `deque`

## 为什么需要它

看它和前面几个容器的关系：

| 容器 | 下标访问 | 头插 | 尾插 | 头删 | 尾删 | 遍历 |
| --- | --- | --- | --- | --- | --- | --- |
| `vector` | ✅ | ❌ **O(n)** | ✅ | ❌ O(n) | ✅ | ✅ |
| `queue` | ❌ | ❌ | ✅ | ✅ | ❌ | ❌ |
| `stack` | ❌ | ❌ | ✅（顶） | ❌ | ✅（顶） | ❌ |
| **`deque`** | **✅** | **✅** | **✅** | **✅** | **✅** | **✅** |

::: exam deque 是"能力最全"的那个
它同时具备：

- `vector` 的**下标访问和遍历**
- `queue` 的**两端高效操作**
- `stack` 的**栈式操作**（用 `push_back` + `pop_back`）

**代价**：每个单项操作都不如专用容器极致（下标访问比 `vector` 慢一点，
内存不是连续的一块）。
:::

## 最小可运行示例

<!-- expect

---
0 1 2 3
front = 0, back = 3
1 2
-->
```cpp
#include <cstdio>
#include <deque>
using namespace std;

int main() {
    deque<int> dq;

    dq.push_back(2);          // 尾插
    dq.push_back(3);
    dq.push_front(1);         // 头插
    dq.push_front(0);

    // 可以用下标访问，也可以遍历
    for (int i = 0; i < (int)dq.size(); i++) printf("%d ", dq[i]);
    printf("\n");

    printf("front = %d, back = %d\n", dq.front(), dq.back());

    dq.pop_front();           // 删头
    dq.pop_back();            // 删尾

    for (int x : dq) printf("%d ", x);
    printf("\n");

    return 0;
}
```

输出：

```text
0 1 2 3
front = 0, back = 3
1 2
```

**注意插入顺序是"尾插 2、尾插 3、头插 1、头插 0"，结果却排成 `0 1 2 3`**——
这就是"两端都能插"的效果。

## 关键过程与易错点

### 一、常用操作

| 操作 | 写法 |
| --- | --- |
| 尾插 / 尾删 | `dq.push_back(x);` / `dq.pop_back();` |
| 头插 / 头删 | `dq.push_front(x);` / `dq.pop_front();` |
| 看队头 / 队尾 | `dq.front();` / `dq.back();` |
| 下标访问 | `dq[i];` |
| 元素个数 | `dq.size();` |
| 判空 | `dq.empty();` |
| 清空 | `dq.clear();` |

::: pitfall 空 deque 上 `front()` / `back()` 是未定义行为
```cpp
deque<int> dq;
cout << dq.front();        // ✗ 未定义行为
```

**和 `queue` / `stack` 一样，不做检查。** 用之前先 `if (!dq.empty())`。
:::

### 二、`deque` vs `vector`：怎么选

| | `vector` | `deque` |
| --- | --- | --- |
| 下标访问速度 | **更快**（连续内存） | 稍慢（分段存储） |
| 头插 | O(n) | **O(1)** |
| 内存占用 | **更省** | 稍多 |
| 与 STL 算法配合 | 都行 | 都行 |

::: exam 简单的选型标准
```text
只需要尾插 + 下标访问        → vector     （绝大多数情况）
还需要在头部频繁插入/删除     → deque
只需要队头出、队尾进         → queue      （语义最清楚）
```

**默认用 `vector`。** 只有确实需要"两端操作"时才换 `deque`。
:::

### 三、`deque` 最经典的用途：单调队列

**问题**：给 n 个数，求每个长度为 k 的滑动窗口里的最大值。

**暴力**：每个窗口扫一遍 → O(nk)，可能超时。

**单调队列**：用 `deque` 维护一个"下标单调、值也单调"的队列 → O(n)。

<!-- expect

---
3 3 5 5
-->
```cpp
#include <cstdio>
#include <deque>
using namespace std;

int main() {
    int n = 6, k = 3;
    int data[6] = {1, 3, -1, -3, 5, 3};

    deque<int> dq;                  // 存下标，对应的值保持递减

    for (int i = 0; i < n; i++) {
        // ① 队头如果已经滑出窗口，弹掉
        while (!dq.empty() && dq.front() <= i - k) dq.pop_front();

        // ② 队尾那些"比当前值小"的，永远不可能再成为最大值了，弹掉
        while (!dq.empty() && data[dq.back()] <= data[i]) dq.pop_back();

        dq.push_back(i);

        // ③ 窗口形成之后，队头就是最大值
        if (i >= k - 1) printf("%d ", data[dq.front()]);
    }
    printf("\n");
    return 0;
}
```

输出 `3 3 5 5`。

::: range 为什么这样能 O(n)
关键在于**每个元素最多进出队列各一次**：

```text
① 滑出窗口的从队头弹走     —— 每个下标最多被弹一次
② 比当前值小的从队尾弹走   —— 每个下标最多被弹一次
③ 每个下标入队一次
```

所以总的操作次数是 O(n)，虽然写了两层 `while`。

**这是"摊还分析"的典型例子**：
看着像 O(n²)，实际上是 O(n)。

**另一个关键洞察**：如果 `a[i]` 比队尾的值更大，
那么队尾那个数**在它被弹出之前都不可能成为最大值**——因为 `a[i]` 更靠右、还更大。
所以可以直接丢掉。
:::

::: pitfall 单调队列最容易写错的三个地方
| 错误 | 后果 |
| --- | --- |
| ① 里用 `<` 而不是 `<=` | 边界元素残留，答案偏大 |
| ② 里方向写反（用 `>=`） | 队列变成"递增"，队头成了最小值 |
| 忘了"窗口形成后才输出" | 前 k-1 个位置输出了错误答案 |

**判断窗口边界时想清楚**：窗口是 `[i-k+1, i]`，
所以"滑出窗口"的条件是 `下标 <= i - k`。
:::

### 四、什么时候**不该**用 `deque`

::: pitfall deque 的三个"别用"场景
| 场景 | 为什么 | 该用什么 |
| --- | --- | --- |
| 只需要尾插 + 随机访问 | `deque` 更慢更占内存 | `vector` |
| 需要频繁在**中间**插入删除 | `deque` 中间操作也是 O(n) | `list`（或干脆别用链表） |
| 需要极致性能 | `vector` 的连续内存对缓存友好 | `vector` / 手写数组 |

**`deque` 的价值只在"两端都要操作"**——超出这个范围，它有更合适的选择。
:::

## 动手检查

1. 把示例里 `push_front(1)` 改成 `push_back(1)`，观察输出顺序的变化。
2. 复现"空 deque 上 `front()`"。
3. 把滑动窗口示例的 k 改成 2、4，手工推演一组数据再运行验证。
4. 用 `vector` 的 `insert(v.begin(), x)` 实现"头插"，和 `deque` 的 `push_front` 比一比
   代码可读性。（数据量小时都行，但 `vector` 头插是 O(n)。）

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 用 `deque` 实现一个"两端都能进出的队列"，正序和倒序输出 | 基本操作 |
| 基础 | 用 `deque` 判断回文（一头一尾比较） | `front` / `back` |
| 巩固 | [洛谷 P1440 求 m 区间内的最小值](https://www.luogu.com.cn/problem/P1440) | **单调队列模板题** |
| 巩固 | [洛谷 P1886 滑动窗口](https://www.luogu.com.cn/problem/P1886) | 单调队列（同时求最大最小） |
| 挑战 | 用 `deque` 实现 0-1 BFS（边权只有 0 和 1 的最短路） | `deque` 的高级应用 |

::: pitfall P1440 / P1886 是单调队列的标准题
两道题的差别只是"求最大"还是"求最小"：

- 求最大 → 队列**递减**（队头最大）
- 求最小 → 队列**递增**（队头最小）

**把示例代码里的比较符号反过来就行。**

**如果这两道题能独立写出来，说明你不仅会用 `deque`，
还理解了"单调队列"这个技巧本身。**
:::
