# 控制与数据单元练习

第 9～15 节讲的是"**怎么用循环、数组、结构体组织数据**"。这一节是它们的验收。

**先做自测，再做综合题。** 通不过就回去补。

## 本节学会什么

- 用自测清单确认第 9～15 节真的学会了
- 通过一道**综合例题**，把分支、循环、数组、结构体、排序串起来
- 知道自己能不能进入"字符串"和"函数"部分

## 为什么需要它

第 9～15 节的知识点**单独看都不难**，真正的难点是：**把它们组合起来解决一道完整的题。**

> 单独写循环：会。
> 单独定义结构体：会。
> 单独写排序：会。
> **但"读入 n 个学生、算总分、多关键字排序、输出前 k 名"——就卡住了。**

::: exam 这一节就是练"组合"
一道真实的题目，通常是这样的结构：

```text
读入数据 → 存进数组/结构体 → 遍历处理 → 排序 → 按格式输出
   ↑           ↑              ↑        ↑        ↑
 输入输出     数组/结构体      循环     排序     格式控制
```

**任何一环不熟，整道题就写不出来。** 所以自测要**按环**检查，而不是"感觉会了"。
:::

### 综合例题：把六节内容串起来

**题目**：给 n 个学生的三科成绩，按总分从高到低排序，输出前 k 名的编号和总分。
总分相同时，编号小的在前。

这道题用到了：读取 → 结构体 → 循环 → 排序（多关键字）→ 格式化输出。

<!-- expect
5 3
90 80 70
100 100 100
80 90 95
60 60 60
95 90 85
---
2 300
5 270
3 265
-->
```cpp
#include <cstdio>
#include <algorithm>
using namespace std;

const int MAXN = 1005;

struct Student {
    int id;
    int chinese, math, english;
    int total;
};

Student st[MAXN];

// 总分降序；同分时编号升序
bool cmp(const Student &a, const Student &b) {
    if (a.total != b.total) return a.total > b.total;
    return a.id < b.id;
}

int main() {
    int n, k;
    scanf("%d %d", &n, &k);

    // ① 读入
    for (int i = 0; i < n; i++) {
        st[i].id = i + 1;
        scanf("%d %d %d", &st[i].chinese, &st[i].math, &st[i].english);
        st[i].total = st[i].chinese + st[i].math + st[i].english;
    }

    // ② 排序
    sort(st, st + n, cmp);

    // ③ 输出前 k 名
    for (int i = 0; i < k; i++) {
        printf("%d %d\n", st[i].id, st[i].total);
    }
    return 0;
}
```

先把样例的正确答案在纸上算出来：

| 编号 | 总分 | 名次 |
| --- | --- | --- |
| 1 | 240 | 4 |
| 2 | 300 | **1** |
| 3 | 265 | 3 |
| 4 | 180 | 5 |
| 5 | 270 | **2** |

前 3 名是 **`2 300` / `5 270` / `3 265`**，和程序输出一致。

::: exam 为什么要先在纸上算一遍
**如果你不先算出正确答案，就没有东西可以比对。**

很多人的"测试"其实是：跑一遍程序 → 看一眼输出 → "嗯，看着像对的" → 提交 → WA。

**正确做法：先在纸上算，再拿程序结果去比。** 不一致的地方就是 bug 所在。
:::

### 如果漏算了一科会怎样

把总分改成只加语文和数学（漏了英语）：

<!-- expect
5 3
90 80 70
100 100 100
80 90 95
60 60 60
95 90 85
---
2 200
5 185
1 170
-->
```cpp
#include <cstdio>
#include <algorithm>
using namespace std;

const int MAXN = 1005;

struct Student {
    int id;
    int chinese, math, english;
    int total;
};

Student st[MAXN];

bool cmp(const Student &a, const Student &b) {
    if (a.total != b.total) return a.total > b.total;
    return a.id < b.id;
}

int main() {
    int n, k;
    scanf("%d %d", &n, &k);

    for (int i = 0; i < n; i++) {
        st[i].id = i + 1;
        scanf("%d %d %d", &st[i].chinese, &st[i].math, &st[i].english);
        st[i].total = st[i].chinese + st[i].math;   // ✗ 漏了英语
    }

    sort(st, st + n, cmp);

    for (int i = 0; i < k; i++) {
        printf("%d %d\n", st[i].id, st[i].total);
    }
    return 0;
}
```

输出变成 `2 200` / `5 185` / `1 170`——**总分全错，名次也跟着变了**。

::: pitfall 这类错误最危险的地方
它**不崩、不报错**，只是答案全错。

而且变化很小（只是第三名从 3 号变成了 1 号），**如果你只扫一眼输出，很容易以为是"差不多对"**。

**所以比对时要逐字符看完整输出**，这也是[测试与调试](/guide/testing-and-debugging)里强调"手算标准答案"的原因。
:::

::: range 这道题里每一行对应哪一节
| 代码 | 来自 |
| --- | --- |
| `scanf("%d %d", &n, &k)` | 第 5 节 输入输出 |
| `struct Student { ... };` | 第 15 节 结构体 |
| `for (int i = 0; i < n; i++)` | 第 10 节 循环 |
| `st[i].total = ...` | 第 4 节 类型 / 第 15 节 |
| `bool cmp(...)` 多关键字 | 第 15 节 排序 |
| `sort(st, st + n, cmp)` | 第 15 节 |
| `printf("%d %d\n", ...)` | 第 5 节 格式 |
| `const int MAXN = 1005` | 第 6 节 `const` / 第 11 节 数组 |

**一道题把六节全用上了。这就是"组合"的意思。**
:::

## 动手检查

1. 把上面综合例题的 `expect` 改成正确顺序（`2 300` / `5 270` / `3 265`），运行验证。
2. 把 `cmp` 的第二级（`a.id < b.id`）删掉，用**总分相同**的数据测，观察输出是否稳定。
3. 把 `total` 从 `int` 改成 `long long`，想想什么情况下必须这么改。
4. 从 A/B/C 三组各挑一道做完，每道都按"五组边界"测一遍。
