# 变量与作用域

这里讲两件最容易被忽略、但直接决定"答案对不对"的事：**变量有没有初值**，以及**这个变量现在还能不能用**。

## 本节学会什么

- 分清"声明"和"初始化"，知道不初始化会发生什么
- 理解作用域：全局、局部、代码块
- 认出"同名变量互相遮蔽"，知道它为什么会导致 bug
- 知道全局变量和局部变量在初值上的关键差别
- 会用 `const` 定义常量

## 为什么需要它

先看一个学生常遇到的问题：

> 我的程序在本地跑出来是对的，交上去就错了。
> 再跑一次，本地答案又变了。

**如果同一份代码、同一个输入，跑出来的结果不一样**——那基本可以确定是**用了没初始化的变量**。

::: exam 变量有两个属性，很多人只知道一个
| 属性 | 含义 | 出问题的表现 |
| --- | --- | --- |
| **初值** | 一开始里面是什么 | 结果随机、每次不同 |
| **作用域** | 在哪些地方能用 | 编译错误，或改错了对象 |

这两个都不报错（或只报"找不到名字"），**但都能让答案悄悄变错**。
:::

## 最小可运行示例

同一个名字可以在不同的地方表示**不同的东西**：

<!-- expect

---
全局 x = 10
局部 x = 20
-->
```cpp
#include <cstdio>

int x = 10;              // 全局变量

int main() {
    printf("全局 x = %d\n", x);

    int x = 20;          // 局部变量：遮蔽（hide）了同名的全局变量
    printf("局部 x = %d\n", x);

    return 0;
}
```

输出：

```text
全局 x = 10
局部 x = 20
```

`main` 里面写的 `int x` **覆盖**了外面的 `x`。这叫**遮蔽**。

::: pitfall 遮蔽看起来无害，其实很危险
<!-- expect

---
0
-->
```cpp
#include <iostream>
using namespace std;

int sum = 0;             // 全局：本意是累加答案

int main() {
    int a[5] = {1, 2, 3, 4, 5};
    int n = 5;

    for (int i = 0; i < n; i++) {
        int sum = 0;     // ✗ 局部：和全局同名，你以为在累加全局的那个
        sum += a[i];
    }
    cout << sum << '\n'; // 输出的还是全局的 0
    return 0;
}
```

**1 加到 5 的和应该是 15，程序输出的是 `0`**——因为它一直在累加那个被遮蔽的局部变量，
而局部变量每轮都被重新创建、又立刻销毁。

**编译器不会提醒你**（`-Wshadow` 才会，但默认不开）。

**纪律：不要用同一个名字表示两个不同的东西。** 全局就叫 `total`，局部就叫 `cur`。
:::

## 关键过程与易错点

### 一、声明 vs 初始化

```cpp
int a;          // 声明：里面是"不确定的值"
int b = 0;      // 声明 + 初始化：里面确定是 0
```

**`a` 里面到底是什么？答案是：不确定。** 它是那块内存里**恰好残留的东西**。

```cpp
#include <cstdio>

int main() {
    int sum;                    // ✗ 没有初始化
    for (int i = 1; i <= 10; i++) sum += i;
    printf("%d\n", sum);
    return 0;
}
```

这段代码**可能**输出 55，也可能是 32674 或者别的什么。
**具体值取决于之前用这块内存的是谁**——所以本地和评测机不一样，跑两次也可能不一样。

::: range 全局和局部的初值规则**完全不同**
| 变量在哪 | 没写初值时，里面是什么 |
| --- | --- |
| **全局**（`main` 外面） | **自动为 0** ✅ |
| **局部**（函数/代码块里） | **不确定的垃圾值** ⚠️ |
| 局部 + `static` | 自动为 0 |

**这就是"大型数组为什么要开全局"的第二个理由**（第一个是栈空间，见[数组](/guide/arrays)）：

```cpp
int a[100005];          // 全局：自动全 0
// int a[100005];       // 如果写在 main 里：每个元素都是垃圾值
```
:::

::: exam 一条零成本的纪律
**声明变量时就给它初值。**

```cpp
int sum = 0;            // ✓
long long ans = 0;      // ✓
int mx = -1;            // ✓
bool flag = false;      // ✓
```

多打几个字符，换掉一整类"随机错"。这是本书里性价比最高的习惯之一。
:::

### 二、作用域：变量的"活动范围"

作用域就是**这个名字在哪些地方有效**。用一对 `{}` 划出一个新范围：

<!-- expect

---
块内 i = 200
块外 i = 100
-->
```cpp
#include <cstdio>

int main() {
    int i = 100;

    {                        // 新的一层作用域
        int i = 200;         // 这个 i 只活在花括号里
        printf("块内 i = %d\n", i);
    }                        // 出了花括号，这个 i 就被销毁

    printf("块外 i = %d\n", i);
    return 0;
}
```

三层作用域常见的样子：

```cpp
#include <iostream>
using namespace std;

int g = 1;                   // ① 全局：整个文件都能用

int main() {
    int n = 3;
    int a = 2;               // ② 函数级：main 里都能用

    for (int i = 0; i < n; i++) {   // ③ 块级：只在循环里能用
        int t = a + i;
    }
    // 这里用不了 i 和 t——它们已经被销毁了
    return 0;
}
```

::: pitfall 循环变量出了循环就没了
```cpp
for (int i = 0; i < n; i++) { }
cout << i;        // ✗ 编译错误：i 没有定义
```

想让 `i` 在循环后还能用，就要把它声明到循环外面：

```cpp
int i;                       // ✓
for (i = 0; i < n; i++) { }
cout << i;                   // 此时 i 是 n（循环正常结束时）
```

**注意**：如果循环里有 `break`，`i` 不会等于 `n`——它停在跳出时的值。
:::

### 三、全局变量：方便，但不要滥用

全局变量的好处是**哪里都能用**，所以竞赛代码里很常见（尤其是数组）。

但它有两个代价：

| 代价 | 说明 |
| --- | --- |
| **容易遮蔽** | 函数里再声明同名变量，就出现上面那种 bug |
| **多组数据要手动清空** | 全局数组**只在程序启动时清一次**，多组数据之间不会重置 |

第二条尤其重要——**这正是[结果关](/practice/five-gates/result)里那个"第二组被第一组污染"的根源**。

<!-- no-compile -->
```cpp
int cnt[105];              // 全局，启动时全 0

int main() {
    int T; cin >> T;
    while (T--) {
        // ✗ 忘了清空：上一组的数据还在
        memset(cnt, 0, sizeof(cnt));   // ✓ 每组开头清一次
        ...
    }
}
```

### 四、变量的命名规则

| 规则 | 例子 |
| --- | --- |
| 只能用**字母、数字、下划线** | `sum1` `my_var` ✅；`my-var` ❌ |
| **不能以数字开头** | `1st` ❌；`first1` ✅ |
| **区分大小写** | `Sum` 和 `sum` 是两个不同的变量 |
| 不能用**关键字** | `int` `for` `if` `return` `class` ❌ |
| 别用**标准库名字** | `max` `time` `next` ❌（见[编译关](/practice/five-gates/compile)） |

### 五、`const`：把"不该变的"钉住

```cpp
const int MAXN = 100005;        // 常量：后面不能改
const double PI = 3.14159265;
```

好处有三个：

1. **改一处就够**：题目范围从 10⁵ 变成 10⁶，只改这一行
2. **防止手误改掉**：写了 `MAXN = 200;` 编译器会报错
3. **数组大小必须是编译期常量**——所以 `const int MAXN` 是数组尺寸的标准写法

::: pitfall `const` 和"只读变量"的区别
```cpp
const int n = 10;
int a[n];              // ✓ n 是编译期常量，可以用作数组大小

int m;
cin >> m;
const int k = m;       // k 是只读，但值在运行时才确定
int b[k];              // ✗ 变长数组（VLA），C++ 标准不支持
```

**数组大小必须是编译期就确定的常量。** 见[数组](/guide/arrays)。
:::

## 动手检查

1. 写一个用未初始化 `int sum;` 累加的程序，**连续运行 5 次**，看输出是否一样。
   再把 `sum` 改成全局变量，重复实验，看有什么不同。
2. 把"遮蔽"示例里的局部 `int x = 20;` 删掉，观察输出变化。
3. 写一段代码：在 `for` 里声明 `i`，循环结束后尝试使用 `i`，把编译错误读一遍。
4. 用 `-Wshadow` 编译你的旧代码（`g++ -std=c++17 -Wall -Wextra -Wshadow`），
   看看有没有隐藏的同名变量。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 故意用未初始化的变量，制造"每次结果不一样" | 亲眼看到问题 |
| 基础 | 写一个程序，分别用全局和局部数组，观察初值差别 | 理解初值规则 |
| 巩固 | 用 `-Wshadow` 检查你以前写过的三道题 | 找出隐藏的遮蔽 |
| 巩固 | 把一道题里的所有"魔法数字"改成 `const` 常量 | 学会用常量管理配置 |
| 挑战 | 找出一道你"本地对、提交错"的题，判断是不是未初始化 / 作用域问题 | 把这一节用在真实 bug 上 |

::: pitfall 这一节的知识点是"防御性"的
初值和作用域，**在你写对的时候完全感觉不到**。只有出错时才会想起它们。

所以最好的用法是：**写完代码后扫一遍**——

- 每个变量声明时都有初值吗？
- 有没有同名变量出现在不同层？
- 多组数据的全局数组清空了吗？

**这三问花 30 秒，能挡住[结果关](/practice/five-gates/result)里一大半的失分。**
:::
