# 循环结构

分支让程序"选一次"。**循环让它把同一件事做很多次**——这是程序真正开始省力的地方。

## 本节学会什么

- 用 `for` 写出"重复 n 次"的循环
- 分清 `i < n` 和 `i <= n`——这是最常见的错
- 会用 `while`、`break`、`continue`
- 知道嵌套循环为什么会"数量级爆炸"
- 认出死循环，并知道怎么避免

## 为什么需要它

看一道题：**求 1 + 2 + 3 + … + n**。

不用循环，你怎么写？

```cpp
int sum = 1 + 2 + 3 + ... ;    // n 是多少？写不出来
```

**因为 n 是运行时才知道的。** 程序必须能"重复做 n 次"，而这正是循环的作用。

::: exam 循环是"用代码长度换执行次数"
| | 不用循环 | 用循环 |
| --- | --- | --- |
| 求 1 到 100 的和 | 写 100 个数相加 | 4 行代码 |
| 求 1 到 10⁵ 的和 | **不可能写完** | 同样 4 行代码 |

**循环让代码长度和问题规模脱钩**——这是它最重要的意义。

而且这也解释了[数据范围表就是给分表](/practice/data-range)里的那条标尺：
循环要跑 `n` 次，所以 `n` 的量级直接决定了算法能不能过。
:::

## 最小可运行示例

<!-- expect
100
---
5050
-->
```cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;

    long long sum = 0;              // 注意用 long long
    for (int i = 1; i <= n; i++) {  // i 依次取 1, 2, 3, ..., n
        sum += i;                   // 累加
    }
    cout << sum << '\n';
    return 0;
}
```

输入 `100`，输出 `5050`。

### `for` 的三个部分

```cpp
for (int i = 1; i <= n; i++)
//   ①        ②      ③
```

| 位置 | 名称 | 作用 | 执行时机 |
| --- | --- | --- | --- |
| ① | 初始化 | `i` 从几开始 | **只在循环开始前执行一次** |
| ② | 条件 | 满足时才继续循环 | **每轮开始前判断** |
| ③ | 步进 | `i` 怎么变 | **每轮结束后执行** |

执行顺序是：**① → ② 判断 → 循环体 → ③ → ② 判断 → 循环体 → ③ → …**

```text
i = 1          ①
i <= 100 ?     ② 是
  sum += 1     循环体
i++  → i = 2   ③
i <= 100 ?     ② 是
  sum += 2     循环体
...
i = 101
i <= 100 ?     ② 否 → 结束
```

::: pitfall `i <= n` 还是 `i < n`？这是最高频的错误
两种写法对应两种含义：

| 写法 | `i` 取到的值 | 循环次数 |
| --- | --- | --- |
| `for (int i = 1; i <= n; i++)` | 1, 2, …, **n** | n 次 |
| `for (int i = 0; i < n; i++)` | 0, 1, …, **n−1** | n 次 |

**两者都是 n 次，但 `i` 的取值不同。**

最容易错的是**混用**：

<!-- expect
9
-->
```cpp
#include <cstdio>

int main() {
    int a[5] = {3, 1, 4, 1, 5};
    int n = 5;
    int sum = 0;

    for (int i = 0; i < n - 1; i++) sum += a[i];   // ✗ 少算了最后一个

    printf("%d\n", sum);      // 9，正确应该是 14
    return 0;
}
```

5 个数相加，结果却是 4 个数的和——**少了一个**。

**纪律：写循环时先问自己"最后一个元素的下标是几"。**
:::

## 关键过程与易错点

### 一、`while`：只知道"什么时候停"

当循环次数**不固定**（取决于运行中的状态）时，`while` 更自然：

```cpp
int x = n;
int cnt = 0;
while (x > 0) {        // 只要还大于 0 就继续
    x /= 2;
    cnt++;
}
```

| | 适合 |
| --- | --- |
| `for` | **次数已知**（遍历数组、跑 n 次） |
| `while` | **条件已知，次数未知**（除到 0、队列非空） |

`while` 的三种写法是等价的：

```cpp
for (int i = 0; i < n; i++) { }   // for

int i = 0;                        // while
while (i < n) { i++; }

int i = 0;                        // do-while：至少执行一次
do { i++; } while (i < n);
```

::: pitfall `do-while` 的分号
```cpp
do {
    ...
} while (i < n);     // ← 这里有分号
```

`while` 单独用时**不加**分号，`do-while` 结尾**要加**。写反了都会出问题。
:::

### 二、死循环：最常见的"卡死"

```cpp
int i = 0;
while (i < n) {
    // 忘了 i++！
}
```

条件永远成立，程序永远跑不完 → **TLE**。

| 死循环的成因 | 例子 |
| --- | --- |
| 忘了更新循环变量 | 上面这种 |
| 更新方向反了 | `i--` 但条件是 `i <= n` |
| 浮点数精度导致条件永远成立 | `while (x != 0) x -= 0.1;` |
| 二分边界没推进 | `l = mid` 而 `mid` 可以等于 `l` |

::: pitfall 二分是死循环的重灾区
```cpp
while (l <= r) {
    int mid = (l + r) / 2;
    if (check(mid)) l = mid;      // ✗ mid 可能等于 l → l 永远不动
    else r = mid - 1;
}
```

正确写法是 `l = mid + 1`。**写循环时永远问一句：循环变量一定会往前走吗？**
:::

### 三、`break` 和 `continue`

| 语句 | 作用 |
| --- | --- |
| `break` | **立刻结束整个循环** |
| `continue` | **跳过本轮剩下的部分**，进入下一轮 |

<!-- expect
7
-->
```cpp
#include <cstdio>

int main() {
    // 找 2 到 20 里第一个能被 7 整除的数
    for (int i = 2; i <= 20; i++) {
        if (i % 7 != 0) continue;   // 不是 7 的倍数，直接看下一个
        printf("%d\n", i);
        break;                      // 找到了，后面的不用看了
    }
    return 0;
}
```

::: pitfall `break` 只能跳出**一层**循环
```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= m; j++) {
        if (a[i][j] == target) break;    // 只跳出内层，外层还在跑
    }
}
```

想跳出两层，常用做法是加一个标记：

```cpp
bool found = false;
for (int i = 1; i <= n && !found; i++)
    for (int j = 1; j <= m; j++)
        if (a[i][j] == target) { found = true; break; }
```
:::

### 四、嵌套循环：数量级会相乘

```cpp
for (int i = 1; i <= n; i++)
    for (int j = 1; j <= n; j++)
        ...            // 执行 n × n = n² 次
```

| 嵌套层数 | 执行次数 | `n = 1000` 时 |
| --- | --- | --- |
| 一层 | n | 1,000 |
| 两层 | n² | 1,000,000 |
| 三层 | n³ | 1,000,000,000 |

**这就是"复杂度"的来源。** `n = 10⁵` 时写两层循环就是 10¹⁰ 次——**必超时**。

::: pitfall 数据范围决定你能嵌套几层
用[数据范围表就是给分表](/practice/data-range)的标尺（1 秒 ≈ 10⁸）：

| 数据范围 | 最多能嵌套几层 |
| --- | --- |
| `n ≤ 100` | 三层都行（10⁶） |
| `n ≤ 5000` | 两层（2.5×10⁷） |
| `n ≤ 10⁵` | **一层**（10⁵），最多加个 log |
| `n ≤ 10⁶` | 一层，且常数要小 |

**写完循环，数一数它总共要跑多少次。** 这是最实用的复杂度判断法。
:::

### 五、累加变量：初始化 + 类型

```cpp
long long sum = 0;      // ✓ 声明时就初始化，用 long long
for (...) sum += a[i];
```

两个坑：

1. **忘了初始化**：`int sum;` 里面是垃圾值（见[结果关](/practice/five-gates/result)）
2. **类型太小**：累加 10⁵ 个 10⁹ 级别的数 → 结果 10¹⁴，`int` 装不下

## 动手检查

1. 把求和示例的 `i <= n` 改成 `i < n`，输入 100，看结果差多少。
2. 写一个循环求 `n!`（阶乘）。用 `int` 试 `n = 13`，再用 `long long` 试——观察溢出。
3. 故意写一个死循环，运行 5 秒后手动终止，感受一下"程序卡住"是什么样。
4. 数一数下面这段跑多少次，再实际插个计数器验证：
   ```cpp
   for (int i = 1; i <= n; i++)
       for (int j = i; j <= n; j++) { }
   ```
   （答案不是 n²——想清楚再验证。）

| 巩固 | [洛谷 P1217 回文质数](https://www.luogu.com.cn/problem/P1217) | 嵌套循环 + 想清楚要不要优化 |
| 挑战 | 输出 1～n 里所有的质数，分别用"试除法"和"筛法"实现，比较 `n = 10⁶` 时的运行时间 | 亲身体会复杂度的差距 |

::: pitfall 第 6 题是本节的落点
同一道题，两种写法：

- 试除法：对每个数试除到 √n → 大约 `n√n` 次
- 埃氏筛：`n log log n` 次

`n = 10⁶` 时，前者要跑 10⁹ 次（超时），后者不到 10⁷ 次（秒过）。

**你亲手跑一遍，就再也不会忘记"复杂度决定能不能过"。**
:::
