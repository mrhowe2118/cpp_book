# 递归与枚举

**有些问题的解法就是"把所有情况都试一遍"。** 而"试一遍"这件事，用递归写最自然。

这一节是全排列、子集、组合的起点，也是后面"搜索"（DFS）的地基。

## 本节学会什么

- 用递归**枚举所有可能的情况**
- 掌握 DFS 的标准框架：**选择 → 深入 → 恢复现场**
- 理解"恢复现场"为什么必须有，不写会出什么问题
- 会写全排列和组合
- 知道枚举法的复杂度上限（`2ⁿ`、`n!`）

## 为什么需要它

先看一道题：**输出 1～3 的所有排列**。

```text
123
132
213
231
312
321
```

用循环写？三层循环确实能搞定 3 个数的排列：

```cpp
for (int i = 1; i <= 3; i++)
    for (int j = 1; j <= 3; j++)
        for (int k = 1; k <= 3; k++)
            if (i != j && j != k && i != k) printf("%d%d%d\n", i, j, k);
```

但那如果是**10 个数的排列**呢？就写十层循环吗？

::: exam 层数本身就是问题的一部分
```text
3 个数的排列  → 3 层循环
10 个数的排列 → 10 层循环（写不出来）
n 个数的排列  → n 层循环（n 是运行时才知道的）
```

**循环的层数没法随输入变化，而递归可以。**

"每个位置试一遍"这个动作是**一样的**，只是位置在往后走——
这正是递归适合的形态。
:::

## 最小可运行示例：全排列

<!-- expect
3
---
123
132
213
231
312
321
-->
```cpp
#include <cstdio>

int n;
int a[15];              // 每个位置放的数
bool used[15];          // 这个数用过了吗

// 决定第 step 个位置放什么
void dfs(int step) {
    if (step > n) {                        // 所有位置都填好了
        for (int i = 1; i <= n; i++) printf("%d", a[i]);
        printf("\n");
        return;
    }

    for (int i = 1; i <= n; i++) {         // 依次尝试每个数
        if (used[i]) continue;             // 用过了，跳过

        a[step] = i;                       // ① 选择
        used[i] = true;                    //    标记"用了"

        dfs(step + 1);                     // ② 深入下一层

        used[i] = false;                   // ③ 恢复现场
    }
}

int main() {
    scanf("%d", &n);
    dfs(1);
    return 0;
}
```

输入 `3`，输出六个排列。

### DFS 的标准框架

**这三个动作是所有"枚举型递归"的骨架：**

```text
for (每个可选的东西) {
    if (不可选) continue;

    a[step] = 它;          ① 选择：把它放进去
    标记它已被使用;

    dfs(step + 1);         ② 深入：处理下一个位置

    取消标记;              ③ 恢复现场：把它拿出来
}
```

::: exam ③ 恢复现场是新手最容易漏的一步
**为什么要"恢复"？**

因为 `dfs(step+1)` 那条路走完之后，你要**换一个选择重新试**。
如果不把 `used[i]` 改回 `false`，下一个选择就会以为这个数已经被用掉了。

**一句话：不恢复现场，枚举就不完整**（会少很多结果，甚至一个都没有）。
:::

## 关键过程与易错点

### 一、理解"选择 → 深入 → 恢复"到底发生了什么

以 `n = 2` 为例，看每一步：

```text
dfs(1)
 ├ 试 i=1：a[1]=1, used[1]=true
 │   └ dfs(2)
 │       ├ 试 i=1：用过了，跳过
 │       └ 试 i=2：a[2]=2, used[2]=true
 │           └ dfs(3) → 输出 "12"
 │           └ used[2]=false        ← 恢复现场
 │   └ used[1]=false                ← 恢复现场
 └ 试 i=2：a[1]=2, used[2]=true
     └ dfs(2)
         ├ 试 i=1：a[2]=1, used[1]=true
         │   └ dfs(3) → 输出 "21"
         │   └ used[1]=false
         └ 试 i=2：用过了，跳过
     └ used[2]=false
```

**"恢复现场"就发生在每一次从 `dfs(step+1)` 返回之后。**

::: pitfall 恢复现场漏写，最常见的症状是"结果少了一大半"
- 漏了 `used[i] = false` → 后面所有分支都以为这个数被占用了 → **结果变少**
- 恢复时写错了变量 → 更难查

**调试办法**：在恢复现场那一行前后各加一句 `cerr`，打印 `step` 和 `i`，
看每次深入和返回是否配对。
:::

### 二、组合：从 n 个里选 k 个

**组合不管顺序**（`1 2` 和 `2 1` 算同一种），所以要"只往后选"。

<!-- expect

---
1 2
1 3
1 4
2 3
2 4
3 4
-->
```cpp
#include <cstdio>

int n = 4, k = 2;
int a[15];

// 决定第 step 个位置放什么，只能从 start 开始往后选
void dfs(int step, int start) {
    if (step > k) {
        for (int i = 1; i <= k; i++) printf("%d ", a[i]);
        printf("\n");
        return;
    }

    for (int i = start; i <= n; i++) {     // 关键：从 start 开始，不回头
        a[step] = i;
        dfs(step + 1, i + 1);               // 下一个位置只能选更大的数
    }
}
```

输出：

```text
1 2
1 3
1 4
2 3
2 4
3 4
```

::: range 排列 vs 组合：差别只在"能不能回头"
| | 全排列 | 组合 |
| --- | --- | --- |
| 顺序算不算不同 | **算**（`12` ≠ `21`） | **不算**（`{1,2}` = `{2,1}`） |
| 怎么避免重复 | 用 `used[]` 标记已选 | **只往后选**（`start = i + 1`） |
| 数量 | `n!` | `C(n, k)` |

**关键一行就是这个 `start` 参数**——它让"下一个数"只能比当前大，
自然就不会出现 `2 1` 这种重复。
:::

### 三、"选或不选"：另一种枚举子集的写法

除了"按位置放数"，还有一种思路：**对每个元素决定选还是不选**。

```text
dfs(i)：已经处理到第 i 个元素
    ├ 不选第 i 个 → dfs(i + 1)
    └ 选第 i 个   → dfs(i + 1)
```

**每个元素两种选择，n 个元素就是 2ⁿ 种情况**——这正好对应"子集个数"。

::: pitfall 这两种写法都对，但结果顺序不一样
| 写法 | 输出顺序 | 特点 |
| --- | --- | --- |
| 按位置放数 + `used[]` | 字典序 | 全排列常用 |
| 每个元素"选/不选" | 按二进制数顺序 | 子集枚举常用 |

**题目要求"按字典序输出"时，必须用第一种。**

**先看清题目要求的输出顺序，再决定用哪种写法**——这是枚举题最常见的坑。
:::

### 四、复杂度：枚举能解决多大的数据

这决定了你能不能"暴力拿分"。

| 枚举什么 | 情况数 | `n` 最大能到多少 |
| --- | --- | --- |
| 子集 | `2ⁿ` | **约 20** |
| 全排列 | `n!` | **约 10** |
| 组合 `C(n,k)` | 最大约 `2ⁿ/√n` | 约 20 |
| 每个位置 k 种选择，n 个位置 | `kⁿ` | 看 k |

::: exam 记住这条"暴力上限"
**`n ≤ 20` 才敢枚举子集；`n ≤ 10` 才敢枚举全排列。**

对照[数据范围表就是给分表](/practice/data-range)：

- 看到 `n ≤ 20` → 出题人**在提示你"可以爆搜"**
- 看到 `n ≤ 10` → 全排列枚举是正解

**这不是巧合，是出题人按算法给你留的分。**
:::

### 五、剪枝：提前砍掉走不通的分支

有些分支走到一半就知道"不可能有答案了"，可以直接 `return`：

```cpp
void dfs(int step, int sum) {
    if (sum > limit) return;        // 剪枝：已经超了，后面不用试了
    ...
}
```

**剪枝不改变正确性，只是少走一些分支。** 它是搜索题的优化主力，
但**必须先写对朴素版本，再加剪枝**——否则你会分不清是剪错了还是本来就不对。

## 动手检查

1. 把全排列示例里的 `used[i] = false;`（恢复现场）删掉，运行，观察输出少了什么。
2. 把全排列改成 `n = 4`，数一数输出多少行（应该是 `24`）。
3. 把组合示例的 `dfs(step + 1, i + 1)` 改成 `dfs(step + 1, 1)`，运行，看输出变成了什么
   （会出现重复的排列）。
4. 用"选或不选"的写法枚举 `{1,2,3}` 的所有子集，在纸上写出输出顺序，再运行验证。

::: pitfall P1036 是本节的综合落点

**它同时用到**：

- 组合枚举（`start` 参数）
- 递归求和
- 质数判断（[函数入门](/guide/functions)里的 `isPrime`）

**能独立做出来，说明这一节和前面的函数部分都过关了。**
:::
