# 文件操作（选读）

**这一节是选读，但对复赛选手来说其实是必读**——因为复赛的输入输出必须走文件。

内容的重点不是"复赛怎么用"（那在[文件关](/practice/five-gates/file)里讲透了），
而是**本地怎么把文件和键盘输入一样用起来**。

## 本节学会什么

- 用 `freopen` 把标准输入输出接到文件（复赛的标准做法）
- 用 C++ 的 `ifstream` / `ofstream` 读写文件
- **在本地用文件测试**，让本地环境和考场一致
- 知道本地测试时最常见的三个错误

## 为什么需要它

平时刷题（洛谷在线提交）是这样：

```text
题目数据 → 评测机接到 stdin → 你的 cin >> → 你的 cout << → 评测机比对
```

复赛（第二轮机试）是这样：

```text
apple.in → 你的程序自己打开它 → 处理后 → 你的程序自己写到 apple.out → 收卷回收
```

::: exam 差别就在"谁负责接管道"
| | 平时 | 复赛 |
| --- | --- | --- |
| 谁把数据接到 `cin` | 评测机 | **你的代码（`freopen`）** |
| 谁把你的输出收走 | 评测机 | **你的代码** |

**所以复赛里"忘写 `freopen`"= 读到空数据 = 0 分。**

这也是为什么[文件关](/practice/five-gates/file)要单独讲一整节。
:::

## 最小可运行示例

### 方式一：`freopen`（复赛标准做法）

```cpp
#include <cstdio>
#include <iostream>
using namespace std;

int main() {
    freopen("apple.in", "r", stdin);     // 把 apple.in 接到标准输入
    freopen("apple.out", "w", stdout);   // 把 apple.out 接到标准输出

    int a, b;
    cin >> a >> b;
    cout << a + b << '\n';

    return 0;
}
```

**这两行之后，`cin` 和 `cout` 就自动走文件了**——代码其他部分完全不用改。

::: pitfall 本地测试的三个常见错误
| 错误 | 症状 | 改法 |
| --- | --- | --- |
| 本地用键盘输入测试 | `freopen` 写错了也发现不了 | **本地也建 `apple.in` 文件** |
| 文件名大小写不一致 | 本地能跑（Windows 不区分），Linux 打不开 | 逐字符核对 |
| 忘了改回注释掉的 `freopen` | 提交后读到空数据 | **别注释掉，用 `cerr` 调试** |

**第一条最关键**：本地和考场必须用同一种输入方式，否则测试没有意义。
:::

### 方式二：C++ 的 `ifstream` / `ofstream`

```cpp
#include <fstream>
using namespace std;

int main() {
    ifstream fin("apple.in");
    ofstream fout("apple.out");

    int a, b;
    fin >> a >> b;
    fout << a + b << '\n';

    return 0;
}
```

**区别**：这种方式不改 `cin`/`cout`，你得把代码里所有的 `cin` 改成 `fin`、`cout` 改成 `fout`。

**好处**：可以同时读多个文件（不止一个输入文件时有用）。

::: range 什么时候用哪种
| 场景 | 推荐 |
| --- | --- |
| **复赛** | `freopen`——两行搞定，其他代码不用动 |
| 需要读多个文件 | `ifstream` |
| 本地对拍 | 两种都行；`freopen` 改起来少 |

**复赛就用 `freopen`。** 它是为这个场景设计的。
:::

## 关键过程与易错点

### 一、完整的本地测试流程

这是复赛前必须练熟的动作：

```text
1. 建目录，放三个文件：
     apple.cpp     你的代码
     apple.in      测试数据（自己造）
     apple.out     （运行后自动生成）

2. 编译：
     g++ -std=c++17 -O2 apple.cpp -o apple

3. 运行：
     ./apple         （Windows: .\apple.exe）

4. 看结果：
     cat apple.out   或者用编辑器打开

5. 和正确答案比对：
     diff apple.out answer.txt
```

::: exam 为什么必须走一遍这个流程
因为**考试当天的操作和这个一模一样**。

如果你平时都用键盘输入测试，考场上第一次用文件——
`freopen` 有没有写对、输出文件在哪、内容对不对，全都第一次验证。

**那太晚了。** 平时练题时就用文件，考场就是熟练动作。
:::

### 二、用 `cerr` 调试（不污染答案文件）

`freopen` 之后 `cout` 会进文件，屏幕上什么都看不到。调试用 `cerr`：

```cpp
cerr << "调试：n = " << n << '\n';      // 打到屏幕，不进 apple.out
```

**注意**：`cin` 也被重定向了，所以**不能用键盘输入调试**——输入必须来自文件。

### 三、三个容易踩的细节

| 细节 | 说明 |
| --- | --- |
| **工作目录** | `freopen("apple.in")` 找的是"程序运行时所在目录"的文件，不是源文件所在目录 |
| **文件不存在** | `freopen` 失败返回 `NULL`，但不检查的话程序会读到空数据 |
| **相对路径** | 只写文件名（不要 `.\` 或绝对路径），见[文件关](/practice/five-gates/file) |

::: pitfall 检查 `freopen` 是否成功（调试期）
```cpp
if (freopen("apple.in", "r", stdin) == NULL) {
    cerr << "打不开 apple.in！检查工作目录和文件名\n";
    return 1;
}
```

**这一行能在本地帮你立刻定位问题**——不然你只会看到"输出一个奇怪的答案"。

（`freopen` 失败返回 `NULL`，这就是[指针](/guide/pointers)里"空指针"的实际用途。）
:::

### 四、多组数据的文件测试

如果题目是多组数据，本地测试也要造多组的 `apple.in`：

```text
2
3
1 2 3
3
4 5 6
```

**这样你才能发现"多组数据没清空"的 bug**（见[结果关](/practice/five-gates/result)）。

**只造一组数据的本地测试，测不出这类问题。**

## 动手检查

1. 建一个 `apple.in`，写入两个数，用 `freopen` 版本运行，打开 `apple.out` 看结果。
2. 把 `apple.in` 改名成 `apple2.in`（不改代码），运行，观察会发生什么。
   **这次要加上返回值检查**，看它是否提示"打不开"。
3. 用 `ifstream` 版本重写一遍，对比两种写法各改了哪些地方。
4. 造一个**两组数据**的 `apple.in`，写一个"多组数据求和"的程序，故意不清空累加变量，
   看第二组的输出对不对。

| 基础 | 用 `freopen` 写一个 A+B，本地用文件跑通 | 完整流程 |

| 巩固 | 用 `ifstream`/`ofstream` 重写同一题 | 另一种写法 |

| 挑战 | 做一道**完整的复赛真题**：限时、用文件输入输出、最后 30 分钟只检查 | 全流程演练 |
