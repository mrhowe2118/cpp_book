# 递归

**函数调用自己**——听起来像循环，但它能做循环做不到的事。

递归是 CSP-J 的核心考点之一，也是后面"搜索""分治""树形结构"的地基。

## 本节学会什么

- 理解递归：函数调用自己，但**每次解决更小的子问题**
- 记住递归的**三个要素**，并会用它检查自己写的递归
- 看懂递归的执行过程：**前进与回溯**
- 知道朴素递归为什么会"慢到不可用"，以及记忆化怎么救它
- 知道递归深度会爆栈

## 为什么需要它

有些问题**天生就是递归的**。比如"求 n 的阶乘"：

```text
5! = 5 × 4!
4! = 4 × 3!
3! = 3 × 2!
2! = 2 × 1!
1! = 1        ← 到这里不用再往下算了
```

**每一问都比上一问小一号，而且用的是同一个规则。**

::: exam 递归的本质：把大问题变成"同样形状的小问题"
```text
怎么求 n!？
  → 先求 (n-1)!，再乘 n
  → 那怎么求 (n-1)!？
     → 先求 (n-2)!，再乘 (n-1)
     → ……一直到 1! 是已知的
```

**关键在于：每一步的"做法"完全一样，只是规模小了。**
这就是为什么"函数调用自己"是合理的——它调用的是**同一个做法**，只是参数更小。
:::

## 最小可运行示例

<!-- expect
5
---
120
-->
```cpp
#include <cstdio>

long long factorial(int n) {
    if (n <= 1) return 1;           // ① 终止条件：最小的情形直接给答案
    return n * factorial(n - 1);    // ② 递归关系：n! = n × (n-1)!
}

int main() {
    int n;
    scanf("%d", &n);
    printf("%lld\n", factorial(n));
    return 0;
}
```

输入 `5`，输出 `120`。

### 递归的三个要素

**写任何递归，都要能回答这三个问题：**

| 要素 | 在这里是什么 | 缺了会怎样 |
| --- | --- | --- |
| ① **终止条件** | `n <= 1` 时返回 1 | **无限递归 → 爆栈** |
| ② **递归关系** | `n * factorial(n-1)` | 写不出来说明还没想清楚 |
| ③ **向终止靠近** | 参数从 `n` 变成 `n-1` | **永远到不了终止 → 爆栈** |

::: exam 写递归前，先在纸上写这三个
```text
① 什么时候停？      n <= 1
② 大问题怎么用小问题算？  n! = n × (n-1)!
③ 每次规模怎么变小？     n → n-1
```

**这三行写出来，递归基本就对了。**
:::

## 关键过程与易错点

### 一、执行过程：前进与回溯

递归最难理解的是"函数里又调用自己，那到底谁先执行完？"

看这段代码，它在**进入**和**退出**时各打印一次：

<!-- expect

---
前进 3
前进 2
前进 1
回溯 1
回溯 2
回溯 3
-->
```cpp
#include <cstdio>

void f(int n) {
    if (n == 0) return;          // 终止条件

    printf("前进 %d\n", n);       // 进入这一层时打印
    f(n - 1);                    // 深入下一层
    printf("回溯 %d\n", n);       // 从下一层回来之后打印
}

int main() {
    f(3);
    return 0;
}
```

输出：

```text
前进 3
前进 2
前进 1
回溯 1
回溯 2
回溯 3
```

::: range 这张输出图是理解递归的钥匙
```text
f(3)
 ├ 前进 3
 ├ f(2)
 │  ├ 前进 2
 │  ├ f(1)
 │  │  ├ 前进 1
 │  │  ├ f(0) → return（终止）
 │  │  └ 回溯 1
 │  └ 回溯 2
 └ 回溯 3
```

**"前进"是按调用顺序打印的，"回溯"是倒过来的**——
因为最深的那一层最先执行完，然后一层层往返回。

**记住这个形状**：递归的执行路径是一棵"往下走再往上回"的树。
后面学搜索（DFS）时，你会反复用到"前进"和"回溯"这两个动作。
:::

### 二、递归 vs 循环：各自适合什么

| | 递归 | 循环 |
| --- | --- | --- |
| 适合 | **问题本身是递归的**（树、分治、搜索） | 重复执行同一件事 |
| 代码 | 通常更短、更贴合思路 | 更直白 |
| 开销 | 每层调用都要占栈空间 | 几乎没有额外开销 |
| 风险 | **递归太深会爆栈** | 死循环会 TLE |

::: pitfall 能用循环就用循环，但要会写递归
`factorial` 用循环写更省资源：

```cpp
long long ans = 1;
for (int i = 2; i <= n; i++) ans *= i;
```

**但有些问题用循环写非常别扭**（比如遍历一棵树），那时候递归是唯一自然的选择。

**竞赛里的判断**：

- 单纯重复 → 循环
- 问题能拆成"同样形状的子问题" → 递归
:::

### 三、朴素的斐波那契：递归为什么会慢

斐波那契数列：`1, 1, 2, 3, 5, 8, 13, ...`（前两项是 1，之后每项等于前两项之和）

<!-- expect
10
---
55
-->
```cpp
#include <cstdio>

long long fib(int n) {
    if (n <= 2) return 1;                 // 终止条件
    return fib(n - 1) + fib(n - 2);       // 递归关系
}

int main() {
    int n;
    scanf("%d", &n);
    printf("%lld\n", fib(n));
    return 0;
}
```

输入 `10` 输出 `55`，看起来没问题。**但 `n = 45` 就跑不完了。**

::: exam 为什么慢了这么多
因为它**把同一个子问题算了很多遍**：

```text
fib(5)
├ fib(4)
│  ├ fib(3)
│  │  ├ fib(2)
│  │  └ fib(1)
│  └ fib(2)      ← fib(2) 又算了一次
└ fib(3)         ← fib(3) 整个又算一遍！
   ├ fib(2)
   └ fib(1)
```

* 计算次数大约是 **2ⁿ** 级别（`fib(45)` 要算十几亿次）
* 而不同的子问题**只有 n 个**

**算了很多遍重复的东西**——这是朴素递归最典型的低效原因。
:::

### 四、记忆化：把算过的存下来

**解决思路**：算过一次就记下来，下次直接取。

<!-- expect
40
---
102334155
-->
```cpp
#include <cstdio>

long long memo[105];      // 记住算过的结果
bool done[105];           // 标记"这个算过了"

long long fib(int n) {
    if (n <= 2) return 1;
    if (done[n]) return memo[n];          // 算过就直接返回

    done[n] = true;
    return memo[n] = fib(n - 1) + fib(n - 2);
}

int main() {
    int n;
    scanf("%d", &n);
    printf("%lld\n", fib(n));
    return 0;
}
```

输入 `40` 输出 `102334155`——**瞬间出结果**，而朴素递归要跑很久。

::: range 记忆化为什么有效
| | 朴素递归 | 记忆化 |
| --- | --- | --- |
| `fib(40)` 的计算次数 | 约 **3×10⁸** | 约 **40** |
| 复杂度 | O(2ⁿ) | **O(n)** |

**核心就一句：重复的子问题只算一次。**

**这是"动态规划"的第一个形态。** 后面会专门学它，但思想现在就能懂：
**把算过的存起来。**
:::

::: pitfall 记忆化别写成无限递归
```cpp
long long fib(int n) {
    if (done[n]) return memo[n];
    return memo[n] = fib(n-1) + fib(n-2);   // ✗ 忘了先标记 done[n]
}
```

上面这版**先查后算、但不标记**：`fib(n)` 里又会调用到 `fib(n)`，
或者重复计算——总之会出问题。

**正确顺序：先标记"我在算了"，再算。**

```cpp
if (done[n]) return memo[n];
done[n] = true;                             // ✓ 先标记
return memo[n] = fib(n-1) + fib(n-2);
```
:::

### 五、递归深度：会爆栈

每深入一层，就要在**栈**上存一份局部变量和返回地址。

```cpp
void f(int n) {
    int a[1000];        // 每层都占 4KB
    f(n + 1);           // 无限递归
}
```

::: pitfall 递归太深 = RE
- 评测机的栈空间有限，通常是几 MB
- 递归几千层可能没事，**几万层就危险**

**症状**：小数据正常，大数据 RE（而且往往报的是"段错误"）。

**两条应对**：
1. **减小每层的栈占用**：把递归函数里的大数组改成全局
2. **改成递推（循环）**：能改就改，最稳

```cpp
int a[1000005];             // ✓ 放全局，别放在递归函数里
```
:::

## 动手检查

1. 把 `factorial` 的终止条件删掉（改成 `if (n == 0) return 1;` 且传入负数），观察会发生什么。
2. 把"前进与回溯"示例改成 `f(4)`，先**在纸上写出输出**，再运行验证。
3. 给斐波那契加一个计数器，统计 `fib(20)` 被调用了多少次；再用记忆化版本统计一次，对比。
4. 写一个递归函数求数组最大值（`int findMax(int a[], int n)`），体会"递归处理数组"的写法。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 用递归求 `1 + 2 + ... + n` | 递归三要素 |
| 基础 | 用递归求 `n` 的阶乘（本题示例），并改成循环版本对比 | 递归 vs 循环 |
| 基础 | [洛谷 P5739 计算阶乘](https://www.luogu.com.cn/problem/P5739) | 递归基础 |
| 巩固 | 用递归求斐波那契的第 n 项，再加记忆化 | 记忆化 |
| 巩固 | [洛谷 P5461 赦免战俘](https://www.luogu.com.cn/problem/P5461) | 递归 + 二维数组 |
| 挑战 | 用递归实现"汉诺塔"，输出每一步移动 | 递归的经典难题 |

::: pitfall 汉诺塔是检验"真懂递归"的题
它的思路是：

```text
要把 n 个盘子从 A 移到 C：
  ① 把上面 n-1 个从 A 移到 B（借助 C）
  ② 把最大的那个从 A 移到 C
  ③ 把 n-1 个从 B 移到 C（借助 A）
```

**你会发现①③又是"同样的问题，只是规模小了"**——这正是递归。

如果你能独立写出汉诺塔，说明递归真的过关了。
:::
