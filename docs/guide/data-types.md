# 数据类型与溢出

**这一节是全书最"便宜"的分数所在地。** 代码逻辑完全正确，只是类型选错，就能从 100 分变成 30 分。而选对类型只需要记住一张表。

## 本节学会什么

- 认识 `int`、`long long`、`double`、`char`、`bool` 这五个真正常用的类型
- 知道每种类型**能装多大的数**，以及装不下时会发生什么
- 学会看数据范围反推类型（这一招在考前实战里会展开成一整节）
- 认识 `printf` / `cout` 输出 `long long` 的正确写法

## 为什么需要它

先看一段**逻辑完全正确**的代码：

```cpp
#include <iostream>
using namespace std;

int main() {
    int n = 100000;
    cout << n * n << '\n';
    return 0;
}
```

`100000 × 100000 = 10000000000`，也就是一百亿。程序输出的却是：

```text
1410065408
```

它没报错，没崩溃，`-Wall -Wextra` 也一声不吭，**只是给了你一个错误的答案**。

这就是**整数溢出**。它是竞赛里最隐蔽的失分之一：编译器不拦你，评测机判你 WA，而你在样例上永远测不出来——因为样例的数往往很小。

::: exam 记住这条判断顺序
**看到要相乘、要累加、数据范围带 `10^9`，先问一句：`int` 装得下吗？**
装不下就换 `long long`。这是复赛里最便宜的 30 分。
:::

## 最小可运行示例

<!-- expect

---
int    : 1410065408
long l : 10000000000
wrong  : 1410065408
right  : 10000000000
-->
```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 100000;
    cout << "int    : " << a * a << '\n';

    long long b = 100000;
    cout << "long l : " << b * b << '\n';

    // 只把结果变量声明成 long long 是不够的
    long long c = a * a;
    cout << "wrong  : " << c << '\n';

    // 先转成 long long 再乘，才是对的
    long long d = (long long)a * a;
    cout << "right  : " << d << '\n';
    return 0;
}
```

输出：

```text
int    : 1410065408
long l : 10000000000
wrong  : 1410065408
right  : 10000000000
```

::: pitfall 第三行才是最容易错的
`long long c = a * a;` —— 很多人以为"我声明成 `long long` 了，就安全了"。
**错。** 右边的 `a * a` 先按 `int` 算完，溢出已经发生了，**再把那个已经错掉的值**赋给 `c`。

> 口诀：**先转类型，再做运算。**

正确写法是 `(long long)a * a`，只要式子里的**任意一个操作数**是 `long long`，整个表达式就按 `long long` 算。
:::

## 关键过程与易错点

### 常用类型速查

::: range 本书只要求你记住这五个
| 类型 | 字节 | 能表示的数的范围 | 什么时候用 |
| --- | --- | --- | --- |
| `int` | 4 | 约 ±2.1 × 10⁹（±21 亿） | 下标、计数、`10^9` 以内的运算 |
| `long long` | 8 | 约 ±9.2 × 10¹⁸ | **求和、乘积、答案**，默认优先考虑它 |
| `double` | 8 | 约 ±1.7 × 10³⁰⁸，15～16 位有效数字 | 小数、平均值、几何 |
| `char` | 1 | −128 ～ 127 | 单个字符 |
| `bool` | 1 | `true` / `false` | 判断标记 |

另外两个只需知道存在：`unsigned int`（0 ～ 42 亿，**极易踩坑，不要用**）、`float`（精度不够，竞赛里别用）。
:::

### 溢出到底是怎么发生的

`int` 只有 4 个字节，能表示的整数是有限的。算出来的结果超出这个范围时，多余的高位被丢掉，
剩下的位重新按有符号数解释——于是你拿到了一个**看起来毫无规律的数**（比如上面的 `1410065408`）。

关键结论：**溢出不会报错，只会给你一个错的答案。**

::: pitfall 三种最典型的溢出
1. **两个 `int` 相乘**：`int n = 1e9; n * n` —— 必炸，换 `long long`。
2. **循环累加**：`int sum = 0;` 累加 10⁵ 个 10⁹ 级别的数 —— 结果是 10¹⁴，`int` 装不下。
3. **写了 `long long` 变量，但表达式是 `int` 算的**：见上文第三行输出。
:::

### 输出 `long long` 的写法

用 `cout` 时不需要管，它自己认类型。**但用 `printf` 时必须写对**——这是很多人从 C 迁移过来的翻车点：

| 类型 | 正确写法 | 错误写法的后果 |
| --- | --- | --- |
| `int` | `printf("%d", x);` | — |
| `long long` | `printf("%lld", x);` | 写 `%d` 会输出垃圾值 |
| `double` | `printf("%.2f", x);` | 写 `%f` 默认 6 位小数 |

::: pitfall 局部变量不会自动清零
`int sum;` 然后 `sum += a[i]` —— `sum` 里可能是任意垃圾值。
**变量声明时就赋初值**，`int sum = 0;`。这是"答案对了，分数没来"的常见来源之一。
:::

### `char` 不是数字

`char` 存的是**字符**，不是它对应的数值：

```cpp
char c = '5';          // 存的是字符 '5'，它的编码是 53
int x = c;             // x == 53，不是 5
int y = c - '0';       // y == 5，这才是"把字符转成数字"
```

反过来，`int d = 5; char c2 = d;` 得到的是编码为 5 的控制字符，**不是** `'5'`。
字符和数字之间的转换，靠 `-'0'` 和 `+'0'`。

### `double` 的两个坑

1. **不要用 `==` 比较两个 `double`。** 浮点误差会让 `0.1 + 0.2 == 0.3` 为假。要比较就写成 `fabs(a - b) < 1e-8`。
2. **`double` 也有精度上限**（15～16 位有效数字）。要输出大整数（比如阶乘），用 `long long`，别用 `double`。

## 动手检查

1. 把上面的示例程序改成用 `int` 累加 `1` 到 `1000000` 的和（结果 500000500000，超过 `int` 上限），观察输出，再用 `long long` 改对。
2. 写一句 `cout << 1.0 / 3.0 << '\n';`，看看输出多少位。再写 `printf("%.10f", 1.0 / 3.0);` 对比。
3. 写出 `char c = '9';` 然后分别输出 `c`、`(int)c`、`c - '0'`，三个值分别是多少？在纸上先写下你的预期。

| 基础 | [洛谷 P5706 再分肥宅水](https://www.luogu.com.cn/problem/P5706) | 浮点数与小数位控制 |
| 巩固 | [洛谷 P2181 对角线](https://www.luogu.com.cn/problem/P2181) | **经典溢出题**：公式里有乘法，必须 `long long` |
| 挑战 | [洛谷 P1601 A+B Problem（高精）](https://www.luogu.com.cn/problem/P1601) | 看看 `long long` 也装不下时会发生什么 |

::: pitfall P2181 就是为溢出准备的
它的公式是 `n(n-1)(n-2)(n-3)/24`。当 `n` 到 10⁵ 量级时，乘积会到 10²⁰，**超过 `long long` 的上限**。
正确做法是**边乘边除**，保持中间结果在安全范围内。这正是"选对类型"之后的下一步——**控制中间结果的大小**。
:::
