# 递归练习

递归是**看会了但写不出来**的重灾区。这一节专门解决这个问题：用自测确认理解，再用汉诺塔和几道经典题把它练成手感。

## 本节学会什么

- 用自测清单确认递归与枚举真的学会了
- 通过**汉诺塔**这道经典题，检验自己是不是"真懂递归"
- 拿到一组按难度分层的递归练习

## 为什么需要它

递归有个特点：**读代码能看懂，自己写就卡住。**

```text
看别人写的递归：嗯，很清晰。
自己写递归：     ① 什么时候停？② 大问题怎么拆？③ 参数怎么变？
```

::: exam 卡住的真正原因
**不是不懂语法，是没有先想清楚"三个要素"。**

很多人一上来就敲 `dfs(...)`，边写边想——结果写到一半发现
"我该在什么时候返回？""这个参数是什么意思？"

**正确顺序：先在纸上写三行，再敲代码。**

```text
① 终止条件：
② 递归关系：
③ 规模怎么变小：
```

**这三行写不出来，写多少代码都是白写。**
:::

### 汉诺塔：检验"真懂递归"的题

**规则**：三根柱子 A、B、C，A 上有 n 个盘子（从大到小摞着）。
每次只能移动一个盘子，且大盘子不能放在小盘子上面。要把所有盘子从 A 移到 C。

**思路**（先想清楚，再看代码）：

```text
要把 n 个盘子从 A 移到 C：
  ① 先把上面 n-1 个，从 A 移到 B（借助 C）
  ② 把最底下那个大盘子，从 A 移到 C
  ③ 再把 n-1 个，从 B 移到 C（借助 A）
```

**注意①③又是"同样的问题，只是规模小了、柱子换了角色"**——这就是递归。

<!-- expect

---
A -> C
A -> B
C -> B
A -> C
B -> A
B -> C
A -> C
共 7 步
-->
```cpp
#include <cstdio>

int cnt = 0;

// 把 n 个盘子从 from，借助 via，移到 to
void hanoi(int n, char from, char via, char to) {
    if (n == 0) return;                    // ① 终止条件：没有盘子要移了

    hanoi(n - 1, from, to, via);           // ② 先把上面 n-1 个挪到"中转柱"

    printf("%c -> %c\n", from, to);        //    再移动最底下那个大盘子
    cnt++;

    hanoi(n - 1, via, from, to);           // ③ 把 n-1 个从中转柱挪到目标柱
}

int main() {
    hanoi(3, 'A', 'B', 'C');
    printf("共 %d 步\n", cnt);
    return 0;
}
```

`n = 3` 时输出 7 步（`2³ - 1 = 7`）。

::: range 汉诺塔里的"三要素"在哪
| 要素 | 在这里 |
| --- | --- |
| **终止条件** | `n == 0`（没有盘子可移） |
| **递归关系** | 三步拆解（n-1 挪走 → 挪底盘 → n-1 挪回来） |
| **规模变小** | `n` → `n - 1` |

**还有一处很妙的地方**：三次调用里，柱子的**角色在轮换**：

```cpp
hanoi(n - 1, from, to, via);    // to 变成了中转柱
hanoi(n - 1, via, from, to);    // via 变成了起点
```

**参数顺序换了，就是"换个角色再讲同一个故事"。** 这是递归最有美感的地方。
:::

::: pitfall 汉诺塔的步数是 2ⁿ − 1
`n = 3` → 7 步；`n = 10` → 1023 步；`n = 64` → 约 1844 亿亿步。

**所以题目里的 `n` 通常很小（`n ≤ 20` 左右）。**
如果看到 `n = 64` 还要求输出每一步——那是数学题，不是编程题。
:::

### 递归题的通用解题步骤

```text
1. 这个问题的"最小情形"是什么？          → 终止条件
2. 大问题能不能用"小一号的同样问题"表示？   → 递归关系
3. 每一步让什么变小？                     → 保证会终止
4. 需要哪些"状态"？（当前处理到哪、已选了什么）→ 参数
5. 有需要"恢复"的东西吗？                 → 恢复现场
```

**第 4 步是新手最容易漏的**——参数不够，递归函数就写不下去。

::: pitfall 迷宫题是"恢复现场"的真正实战
走迷宫时，你要标记"这个格子走过了"，回溯时再**取消标记**：

```cpp
vis[x][y] = true;
dfs(x + 1, y);
vis[x][y] = false;      // ← 恢复现场，让别的路径还能走这里
```

**如果这里不恢复，其他路径就永远走不进这个格子，答案会少很多。**

和全排列里的 `used[i] = false` 是**同一个道理**。
:::

## 动手检查

1. 把汉诺塔的 `n` 改成 4，先在纸上写出预期步数（应该是 15），再运行验证。
2. 把汉诺塔里前两个 `hanoi` 调用的**参数顺序对调**，运行看输出变成什么（会得到错误结果）。
   这能帮你体会"参数就是角色"。
3. 把全排列的恢复现场删掉，观察结果少了多少。
4. 挑一道 A 组题目，**先在纸上写三个要素**，再敲代码。
