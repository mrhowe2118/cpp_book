# 第一个程序

上一节你把它敲进去、跑起来了。这一节**把它拆开看清楚**——不理解的代码，抄一百遍也学不会。

## 本节学会什么

- 说清 `#include`、`main`、`cout`、`return` 各自在干什么
- 知道 `std::` 是什么，以及为什么有的代码里没有它
- 记住 C++ 最容易忘的三样东西：分号、引号、大括号
- 学会用"故意改坏"的办法理解每一行的作用

## 为什么需要它

很多人学 C++ 的方式是**照抄**：

> 反正每次都是这几行，先背下来再说。

背下来能用，但一旦出错就完全没方向。比如：

- 少一个分号 → 编译器报一堆错，你不知道哪一条才是真的
- 写成 `cout << "Hello"` 忘了 `;` → 报错信息指向下一行
- 把 `main` 拼错 → 链接错误，提示找不到入口

**知道每一行"负责什么"，你才能从报错反推出错在哪。**

::: exam 这一节的方法：边学边"破坏"
理解代码最快的办法不是读，是**改坏它，看会发生什么**。

下面每一部分我都给你一个"动手破坏"的动作。
**做完这些动作，这些语法就变成你的了。**
:::

## 最小可运行示例

<!-- expect

---
Hello, world!
-->
```cpp
#include <iostream>          // ①

int main() {                 // ②
    std::cout << "Hello, world!" << '\n';   // ③
    return 0;                // ④
}                            // ⑤
```

### ① `#include <iostream>`——告诉编译器"我要用输入输出"

这一行是**预处理指令**，在编译之前执行。它的作用是：把 `iostream` 这个头文件的内容**原样复制到这一行**。

因为你要用 `std::cout`（往屏幕输出），而 `cout` 的定义就在 `iostream` 里。
不写这一行，编译器不认识 `cout`。

| 你用了什么 | 就要 `#include` 什么 |
| --- | --- |
| `cout` `cin` | `<iostream>` |
| `printf` `scanf` | `<cstdio>` |
| `sort` `max` `min` | `<algorithm>` |
| `sqrt` `fabs` | `<cmath>` |
| `string` | `<string>` |

::: pitfall `#include` 行末尾**不要加分号**
```cpp
#include <iostream>;    // ✗ 多余的分号
```

它不一定会立刻报错，但可能引发莫名其妙的错误。
**`#include` 和 `#define` 这类以 `#` 开头的行，末尾都不写分号。**
:::

### ② `int main() { ... }`——程序的入口

**程序从这里开始执行。** 整个程序有且只有一个 `main`。

| 部分 | 含义 |
| --- | --- |
| `int` | `main` 执行完要返回一个整数 |
| `main` | 名字固定，不能改（`Main`、`mian` 都不行） |
| `()` | 参数列表，现在为空 |
| `{ }` | 函数体：要执行的代码写在里面 |

::: pitfall 两个经典错误
```cpp
int mian() { }      // ✗ 拼错了
int Main() { }      // ✗ 大小写错了
```

症状很特别：**代码本身没错，但链接时报"找不到 main"**（`undefined reference to 'main'`）。

看到这个报错，先检查 `main` 的拼写。
:::

### ③ `std::cout << "..." << '\n';`——把内容输出到屏幕

拆开看：

| 部分 | 含义 |
| --- | --- |
| `std::` | 名字空间前缀（下面单独讲） |
| `cout` | **c**haracter **out**put，标准输出（屏幕） |
| `<<` | 输出运算符，"把右边的东西送进 `cout`" |
| `"Hello, world!"` | 一串字符，用双引号包起来 |
| `'\n'` | 换行符，用**单**引号包起来 |
| `;` | 语句结束 |

**`<<` 可以连着写**，就像把几样东西依次倒进同一个出口：

```cpp
std::cout << "答案是 " << 42 << '\n';    // 输出：答案是 42
```

::: pitfall 双引号和单引号不能混用
| 写法 | 含义 | 例子 |
| --- | --- | --- |
| `"..."` 双引号 | **字符串**（一串字符） | `"hello"` |
| `'...'` 单引号 | **单个字符** | `'a'`、`'\n'` |

```cpp
std::cout << "\n";     // ✓ 换行（字符串）
std::cout << '\n';     // ✓ 换行（单字符，更快）
std::cout << "\n';     // ✗ 引号没配对，编译器会报错
```
:::

### ④ `return 0;`——告诉系统"正常结束"

返回 `0` 表示程序正常结束。**非 0 通常表示出了错。**

严格说 `main` 里的 `return 0;` 可以省略（编译器会自动加），但**建议一直写上**：

- 读代码的人一眼就知道程序正常结束
- 万一某个环境不认，你也已经写对了
- 后面学到函数时，你会一直用到 `return`

### ⑤ 分号和大括号

C++ 里**每条语句以 `;` 结尾**，**每个代码块用 `{ }` 包起来**。

```cpp
#include <iostream>
using namespace std;

int main() {              // 大括号开始
    cout << "a\n";        // ← 分号
    cout << "b\n";        // ← 分号
    return 0;             // ← 分号
}                         // 大括号结束，后面不写分号
```

::: pitfall 报错行号和真正的错误不在同一行
少一个分号时，编译器往往在**下一行**报错。

- 报错说第 5 行有问题 → **先看第 4 行末尾有没有分号**
- 报错说"expected ';' before ..." → 就是这里少了分号

**看到"少分号"的报错，先往上看一行。**
:::

## 关键过程与易错点

### `std::` 是什么？为什么有的代码没有它？

C++ 把标准库的东西都放进一个叫 `std` 的**名字空间**（namespace）里，
避免和你自己的名字撞车。

所以标准的写法是 `std::cout`。但每次都写 `std::` 太啰嗦，于是可以：

```cpp
#include <iostream>
using namespace std;      // 把 std 里的名字"引进来"

int main() {
    cout << "Hello\n";    // 不用写 std:: 了
    return 0;
}
```

| 写法 | 说明 | 建议 |
| --- | --- | --- |
| `std::cout` | 每次写全 | 最安全，但啰嗦 |
| `using namespace std;` | 写在 `#include` 后面 | ✅ **竞赛里常用，本书也用** |

::: pitfall `using namespace std;` 的代价
它把标准库里**所有**名字都引进来，所以你的变量名更容易和标准库撞车。

这正是[编译关](/practice/five-gates/compile)里那份"变量名黑名单"的来源。

**结论不是不用它，而是：用了它，变量名就要用缩写**（`mx` 而不是 `max`）。
:::

### `'\n'` 还是 `endl`？

两种换行方式：

```cpp
cout << "a" << '\n';      // ✓ 推荐
cout << "a" << endl;      // 能用，但慢
```

| | `'\n'` | `endl` |
| --- | --- | --- |
| 换行 | ✅ | ✅ |
| 额外动作 | 无 | **强制刷新输出缓冲** |
| 速度 | 快 | 慢（大量输出时明显） |

**竞赛里一律用 `'\n'`。** 输出十万行时，这个差别是致命的。

### 注释

```cpp
// 单行注释：从 // 到这行末尾

/*
   多行注释：
   这中间的内容编译器都忽略
*/
```

注释是写给人看的。**写复杂的逻辑时一定要注释**——一周后你自己也看不懂。

（详见 [注释与代码风格](/guide/comments)。）

## 动手检查

用"破坏法"理解每一行。**每改一处，先猜会发生什么，再编译验证。**

1. 删掉第 3 行末尾的 `;`，编译，看报错指向哪一行。
2. 把 `return 0;` 改成 `return 1;`，编译运行，然后在终端执行 `echo $?`（Windows 用 `echo %ERRORLEVEL%`）看返回值。
3. 把 `"Hello, world!"` 的引号改成单引号 `'Hello, world!'`，编译，把完整报错读一遍。
4. 删掉 `'\n'`，观察输出有什么变化。
5. 把两条 `cout` 语句写在一行，中间用 `;` 隔开，看能不能正常输出两行。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 输出三行：你的名字、学校、一句英文 | `cout` 与换行 |
| 基础 | 用一条 `cout` 语句输出 `1 2 3`（数字之间一个空格） | 连续使用 `<<` |
| 基础 | [洛谷 P1000 超级玛丽游戏](https://www.luogu.com.cn/problem/P1000) | 精确按格式输出 |
| 巩固 | 故意制造 5 种不同的编译错误，把每种报错抄下来 | 建立"读报错"的能力 |

::: pitfall 第 4 题比看起来有用
**把自己踩过的编译错误记下来**，是这一阶段性价比最高的练习。

一张纸，左边写"报错信息"，右边写"真正的原因"。考前翻一遍，比刷十道题有用。
:::
