# 复杂度直觉与数据范围

**在写代码之前，你就该知道它会不会超时。**

这一节讲"怎么数运算次数"，也就是**复杂度**——它是你判断算法能不能过的唯一依据。

## 本节学会什么

- 理解复杂度是"运算次数随 n 增长的趋势"
- 学会用**数循环嵌套层数**快速估算复杂度
- 建立"1 秒 ≈ 10⁸ 次运算"的标尺
- 认识 `O(log n)` 为什么这么快（二分的基础）
- 知道常数因子什么时候会坏事

## 为什么需要它

看一个真实的场景：

> 你写了一个 O(n²) 的解法，本地用小数据测全对，很高兴地提交。
> 结果 TLE。你以为是"机器慢"，其实是**复杂度不达标**。

::: exam 超时不是"运气不好"，是"能算出来的"
`n = 10⁵` 时，O(n²) 是 **10¹⁰ 次运算**，而 1 秒只能跑约 **10⁸ 次**。

**10¹⁰ ÷ 10⁸ = 100 倍**——不是"差一点"，是差两个数量级。

**这个判断在你写下第一个 `for` 的时候就能做完**，不用等提交。
:::

## 最小可运行示例

把三种常见写法的**实际执行次数**数出来：

<!-- expect

---
100 5050 700
-->
```cpp
#include <cstdio>

int main() {
    int n = 100;

    long long c1 = 0, c2 = 0, c3 = 0;

    // ① 单层循环
    for (int i = 1; i <= n; i++) c1++;

    // ② 双层循环（不等长）
    for (int i = 1; i <= n; i++)
        for (int j = i; j <= n; j++) c2++;

    // ③ 内层每次翻倍
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= n; j *= 2) c3++;

    printf("%lld %lld %lld\n", c1, c2, c3);
    return 0;
}
```

`n = 100` 时输出：

```text
100 5050 700
```

| 写法 | 次数 | 复杂度 | 说明 |
| --- | --- | --- | --- |
| ① 单层 | `100` | **O(n)** | 正好 n 次 |
| ② 双层不等长 | `5050` | **O(n²)** | 是 n(n+1)/2，仍属 n² 量级 |
| ③ 内层翻倍 | `700` | **O(n log n)** | 内层跑 7 次（1,2,4,8,16,32,64） |

::: range 从这张表里读出三件事
1. **双层循环大约是 n² 的一半**——常数系数不影响复杂度，但**影响实际速度**（少一半也是好事）
2. **`j *= 2` 让内层从 n 次变成 log₂n 次**——这就是"二分"和"倍增"为什么快
3. **O(n²) 和 O(n log n) 在 n=100 时差距不大**（5050 vs 700），但 **n=10⁵ 时是天壤之别**：

| n | O(n²) | O(n log n) |
| --- | --- | --- |
| 100 | 5×10³ | 7×10² |
| 10⁴ | 5×10⁷ | 1.3×10⁵ |
| 10⁵ | **5×10⁹** ❌ | **1.7×10⁶** ✅ |
:::

## 关键过程与易错点

### 一、怎么数：看循环嵌套

**最实用的方法：数一数最内层的语句总共执行多少次。**

| 代码形状 | 复杂度 |
| --- | --- |
| 没有循环 | O(1) |
| 一层循环跑 n 次 | O(n) |
| 两层各跑 n 次 | O(n²) |
| 三层各跑 n 次 | O(n³) |
| 一层 n 次，内层每次翻倍/减半 | O(n log n) |
| 每次把问题规模减半 | O(log n) |
| 枚举所有子集 | O(2ⁿ) |
| 枚举所有排列 | O(n!) |

::: pitfall 只数"最内层"，不要数所有循环
```cpp
for (int i = 1; i <= n; i++)        // n 次
    for (int j = 1; j <= n; j++)    // 里面又 n 次
        sum++;                      // 这行执行 n² 次
```

复杂度看的是**最内层语句的执行次数**，也就是 **n²**。
不是"n + n²"，更不是"2n"。
:::

### 二、标尺：1 秒能跑多少

::: range 本书统一使用的估算法
**评测机 1 秒 ≈ 10⁸ 次简单运算**（加减、比较、数组访问）。

实际会受这些因素影响：

| 因素 | 影响 |
| --- | --- |
| 编译器优化（`-O2`） | 快 2～5 倍 |
| 循环体里做了什么 | 简单赋值 vs 复杂计算，差很多 |
| 是否用到缓存友好的访问顺序 | 二维数组按行访问比按列快很多 |
| `cin/cout` 没加速 | 可能慢好几倍 |

**所以这是个粗略标尺，但"差一个数量级"的判断从不出错。**
:::

### 三、常见复杂度对照表

| 复杂度 | `n = 10⁵` 时 | 典型算法 |
| --- | --- | --- |
| O(1) | 1 | 公式、桶查询 |
| O(log n) | 约 17 | 二分查找 |
| O(√n) | 约 316 | 试除法判质数 |
| O(n) | 10⁵ | 线性扫描、前缀和 |
| O(n log n) | 约 1.7×10⁶ | 排序、二分答案 |
| O(n√n) | 约 3×10⁷ | 分块 |
| O(n²) | **10¹⁰** ❌ | 朴素双重枚举 |
| O(2ⁿ) | 天文数字（`n ≤ 20` 才可用） | 暴力枚举子集 |

::: exam 反向查表：从数据范围推算法
这才是**考场上真正用法**：

| 看到数据范围 | 目标复杂度 | 想什么算法 |
| --- | --- | --- |
| `n ≤ 20` | O(2ⁿ) / O(n!) | 爆搜、状压 |
| `n ≤ 300` | O(n³) | Floyd、区间 DP |
| `n ≤ 5000` | O(n²) | 朴素 DP |
| `n ≤ 10⁵` | **O(n log n)** | 排序、二分、前缀和 |
| `n ≤ 10⁶` | O(n) | 线性扫描、桶 |
| `n ≤ 10⁹` | O(log n) / O(1) | 二分答案、公式 |

**完整用法见[数据范围表就是给分表](/practice/data-range)。这一节讲的是"为什么"。**
:::

### 四、`O(log n)` 为什么这么快

**因为每次把问题规模减半。**

```text
n = 1000000，每次减半：
1000000 → 500000 → 250000 → ... → 1

要减多少次？log₂(1000000) ≈ 20 次
```

**一百万的数据，只要 20 次就能定位。** 这就是二分查找、二分答案强大的原因。

| n | log₂n |
| --- | --- |
| 10 | 约 3.3 |
| 1000 | 约 10 |
| 10⁶ | 约 20 |
| 10⁹ | 约 30 |

**注意**：n 从 10⁶ 涨到 10⁹（涨 1000 倍），log n 只从 20 涨到 30。
**这就是"对数增长"的威力。**
:::

### 五、空间复杂度：别忘了内存

内存也要算，而且**按声明的空间算**（见[资源关](/practice/five-gates/resource)）：

| 声明 | 占用 |
| --- | --- |
| `int a[10⁵]` | 0.4 MB |
| `int a[10⁶]` | 4 MB |
| `int a[10⁷]` | 40 MB |
| `int a[10⁸]` | **400 MB** ❌ |
| `long long a[10⁷]` | 80 MB |

**常见内存限制在 128～512 MB 之间。** 开数组前先算一遍。

### 六、常数因子：同是 O(n)，速度能差 5 倍

复杂度相同，实际速度可能差很多：

| 影响常数的因素 | 建议 |
| --- | --- |
| `cin/cout` 没加速 | 加 `ios::sync_with_stdio(false)` 或用 `scanf/printf` |
| 循环里反复调用函数 | 简单的可以 `inline` |
| 二维数组按列遍历 | 改成按行（缓存友好） |
| 循环里做 `%` 和除法 | 能提出循环就提出来 |
| STL 容器的额外开销 | 数据量极大时手动数组可能更快 |

::: pitfall 什么时候才需要关心常数
**先保证复杂度对，再优化常数。**

- 复杂度不达标（差数量级）→ **优化常数没用**，必须换算法
- 复杂度刚好卡在边界（比如估算 2×10⁸ 而标尺是 10⁸）→ **这时候常数才决定成败**

**顺序反了就是浪费时间。**
:::

## 动手检查

1. 把示例里 ② 的 `for (int j = i; ...)` 改成 `for (int j = 1; ...)`，重新运行，看次数变成多少。
   验证"n(n+1)/2"和"n²"的关系。
2. 把 ③ 的 `j *= 2` 改成 `j += 1`，观察次数从 700 变成多少。
3. 估算一下：`n = 10⁵` 时，O(n²) 需要多少秒？用 `10⁸` 作标尺算一算。
4. 用 `-O2` 编译示例（`g++ -O2 -std=c++17 ...`），看运行时间有没有变化。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 写出下面代码的复杂度：单层循环 n 次、双层各 n 次、三层各 n 次 | 数嵌套 |
| 基础 | 求下面代码的**实际**执行次数（n=10）：`for(i=1;i<=n;i++) for(j=1;j<=i;j++)` | 区分"复杂度"与"精确次数" |
| 巩固 | [洛谷 P2249 查找](https://www.luogu.com.cn/problem/P2249) | `n, m ≤ 10⁶`：必须 O(n log n)，感受二分的快 |
| 巩固 | [洛谷 P1102 A-B 数对](https://www.luogu.com.cn/problem/P1102) | O(n²) 必超时，逼迫你优化 |
| 巩固 | [洛谷 P1217 回文质数](https://www.luogu.com.cn/problem/P1217) | 先想复杂度，再决定要不要筛法 |
| 挑战 | 同一道题写"试除法"和"埃氏筛"两版，测 `n = 10⁶` 的运行时间 | 亲手体会复杂度差距 |

::: pitfall 第 6 题值得真的做一遍
**复杂度不是抽象概念，它是你能亲手测出来的时间差。**

写完两版程序，用 `time`（Linux）或 `Measure-Command`（Windows）测一下：

- 试除法：可能几秒
- 埃氏筛：可能不到 0.1 秒

**亲手测过一次，你就再也不会"凭感觉"选算法了。**
:::
