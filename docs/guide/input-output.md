# 输入输出

前面几节的程序都是"写死"的。**输入输出让程序能和外界交换数据**——题目给你数据，你还它答案。

这一节把它讲透，因为**格式错了，答案再对也是 0 分**。

## 本节学会什么

- 用 `cin >>` 读入、用 `cout <<` 输出
- 知道 `cin >>` 会自动跳过空格和换行（这是好事也是坑）
- 掌握输出格式控制：保留小数、补零、对齐
- 会在"读到文件结束"时循环读入
- 分得清 `cin/cout` 和 `scanf/printf`，知道什么时候用哪个

## 为什么需要它

先看一个**答案完全正确**却拿 0 分的例子：

> 题目要求输出 `3.14`
> 你的程序输出了 `3.14159`

**数值对，格式错，0 分。**

::: exam 评测机是"逐字符比对"的
它不会理解你的答案"差不多对"。所以输入输出有三条铁律：

1. **只输出题目要求的内容**（不要 `请输入n：`）
2. **格式逐字符一致**（小数位数、空格、换行、大小写）
3. **先读完输入，再判断输出什么**

**这三条是"会写程序"和"能拿分"之间的差距。**
:::

## 最小可运行示例

<!-- expect
3 5
---
8
-->
```cpp
#include <iostream>
using namespace std;

int main() {
    int a, b;
    cin >> a >> b;        // 读入两个数
    cout << a + b << '\n'; // 输出它们的和
    return 0;
}
```

输入 `3 5`，输出 `8`。

### `cin >>` 会自动跳过空白

这是 C++ 输入最重要的一个特性：

```cpp
cin >> a >> b;
```

无论输入是 `3 5`、`3   5`、还是 `3` 换行 `5`，**结果都一样**。
因为 `>>` 会先跳过所有空格、制表符、换行，再开始读数。

**好处**：不用管输入怎么排版。**代价**：见下面的"字符读入"。

### `cout <<` 可以连续输出

```cpp
cout << "答案是 " << a + b << '\n';
```

`<<` 把右边的东西依次"送进"屏幕。数字会自动转成合适的形式。

## 关键过程与易错点

### 一、输出格式控制

题目说"保留 2 位小数"，就必须用 `printf` 或 `iomanip`：

| 需求 | 写法 |
| --- | --- |
| 保留 2 位小数 | `printf("%.2f", x);` |
| 补前导零（`09:05`） | `printf("%02d:%02d", h, m);` |
| 右对齐、占 5 位 | `printf("%5d", x);` |
| 输出 `long long` | `printf("%lld", x);` |

<!-- expect
9 5
---
09:05
-->
```cpp
#include <cstdio>

int main() {
    int h, m;
    scanf("%d %d", &h, &m);
    printf("%02d:%02d\n", h, m);   // %02d = 不足两位时前面补 0
    return 0;
}
```

::: pitfall `cout` 默认只输出 6 位有效数字
```cpp
double x = 1234567.89;
cout << x << '\n';        // 输出 1.23457e+06 ← 科学计数法，判错
```

**要控制格式，优先用 `printf`。** 它的行为完全可预测。

如果一定要用 `cout`，需要 `#include <iomanip>` 并且 `cout << fixed << setprecision(2)`——
但在竞赛里，`printf` 更省事，出错更少。
:::

### 二、输出小数：别忘了一个细节

```cpp
printf("%.2f\n", 1.0 * sum / n);
```

**注意 `1.0 *`**：如果 `sum` 和 `n` 都是 `int`，`sum / n` 会做**整数除法**，小数部分直接被丢掉。

```cpp
int sum = 7, n = 3;
printf("%.2f\n", sum / n);        // 2.00（整数除法，7/3 = 2）
printf("%.2f\n", 1.0 * sum / n);  // 2.33 ✓
```

**规矩：只要结果可能是小数，就先把其中一个数变成浮点。**

### 三、读到文件结束（EOF）

题目不告诉你"有几个数"时，就要一直读到输入结束：

<!-- expect
1 2 3 4
---
10
-->
```cpp
#include <iostream>
using namespace std;

int main() {
    int x;
    long long sum = 0;

    while (cin >> x) {      // 读得到一个数就继续，读不到就停
        sum += x;
    }
    cout << sum << '\n';
    return 0;
}
```

`cin >> x` 这个表达式**本身有个值**：读到数时为真，遇到结束为假。所以能直接当循环条件。

::: range 三种"不知道有几个数"的写法
| 题目怎么说 | 怎么写 |
| --- | --- |
| 第一行给 `n`，后面 n 个数 | `cin >> n; for (int i = 0; i < n; i++) cin >> x;` |
| 读到 `0` 结束 | `while (cin >> x && x != 0)` |
| 读到文件结束 | `while (cin >> x)` |

**第三种最常见于多组数据的题**，也最容易和"多组数据没清空"一起出事（见[结果关](/practice/five-gates/result)）。
:::

### 四、读字符和读字符串：这里有坑

**坑 1：`cin >> c` 不读空格和换行**

```cpp
char c;
cin >> c;          // 输入 "  a" 时，c 得到的是 'a'，前面的空格被跳过了
```

想读到空格本身，要用 `cin.get(c)` 或 `scanf("%c", &c)`。

**坑 2：`cin >> s` 遇到空白就停**

```cpp
string s;
cin >> s;          // 输入 "hello world"，s 只有 "hello"
```

要读整行（含空格），用 `getline(cin, s)`。

::: pitfall 混用 `>>` 和 `getline` 会读到空行
```cpp
int n;
string s;
cin >> n;              // 读完数字，换行符还留在输入缓冲区里
getline(cin, s);       // ✗ 立刻读到那个换行符，s 是空字符串！
```

**解决**：中间"吃掉"换行符。

```cpp
cin >> n;
cin.ignore();          // 吃掉换行符
getline(cin, s);       // ✓
```

**这是"字符串题莫名读到空行"的经典原因。**
:::

### 五、`cin/cout` 还是 `scanf/printf`？

| | `cin` / `cout` | `scanf` / `printf` |
| --- | --- | --- |
| 写起来 | 简单，不用记格式符 | 要写 `%d` `%lld` `%.2f` |
| 类型错误 | 编译器帮你转 | **写错 `%d`/`%lld` 会输出垃圾值** |
| 格式控制 | 麻烦（要 `iomanip`） | **方便** |
| 速度 | 默认较慢 | 快 |
| 推荐场景 | 逻辑为主、输出简单 | **输出格式要求严格、数据量大** |

::: range 一个稳妥的默认选择
本书建议：

- **输入**：`cin` 就够（逻辑清楚，不易错）
- **输出**：要控制格式时用 `printf`
- **数据量很大**（10⁶ 级别）：`cin/cout` 加一句加速，或者用 `scanf/printf`

加速的写法（写在 `main` 开头）：

```cpp
ios::sync_with_stdio(false);
cin.tie(0);
```

**注意**：加了它之后**不要混用 `cin` 和 `scanf`**，也不要和 `freopen` 一起乱用（见[文件关](/practice/five-gates/file)）。
:::

### 六、输出完别忘换行

```cpp
cout << ans;              // 有些题要求换行
cout << ans << '\n';      // ✓ 更安全
```

**绝大多数题目的输出都以换行结尾。** 加上它不会错，不加有时候会错。

## 动手检查

1. 输入 `3    5`（中间多个空格），确认程序输出还是 `8`。
2. 输入 `3` 换行 `5`，确认结果不变。这验证了 `>>` 会跳过换行。
3. 把 `printf("%.2f\n", 1.0 * sum / n)` 里的 `1.0 *` 去掉，输入 `3` 和 `1 2 4`，看输出差多少。
4. 写一个程序读入一整行（含空格），先用 `cin >> s`，再用 `getline(cin, s)`，对比结果。
5. 制造"`cin >> n` 后 `getline` 读到空行"的情况，再用 `cin.ignore()` 修好。
