# 注释与代码风格

这一节不教新语法。它教一件更实际的事：**让你在一周后还能看懂自己的代码。**

## 本节学会什么

- 会用 `//` 和 `/* */`，并知道它们的陷阱
- 学会用 `#if 0` 而不是注释来"临时关掉一段代码"
- 知道注释该写"为什么"，不该写"是什么"
- 建立一套固定的缩进与命名习惯

## 为什么需要它

看一段**能跑、完全正确、但你三天后看不懂**的代码：

```cpp
#include <iostream>
using namespace std;

int main() {
    int n, s = 0, t = 0;
    cin >> n;
    for (int i = 0; i < n; i++) { int x; cin >> x; if (x % 2) t += x; else s += x; }
    cout << s << ' ' << t << '\n';
    return 0;
}
```

你能一眼说出它在算什么吗？大概要读一会儿。

**问题在于：`s` 和 `t` 是什么？为什么偶数加 `s`、奇数加 `t`？**

::: exam 竞赛代码也是要给人看的
很多人觉得"比赛代码只要能跑就行"。但真正的情况是：

| 什么时候 | 谁看你的代码 |
| --- | --- |
| 调试时 | **你自己**，在读 30 分钟前刚写的逻辑 |
| 赛后复盘 | **你自己**，在找"当时为什么这么写" |
| 改题重做 | **你自己**，在把上次的代码改成新题的 |

**最常读你代码的人就是你自己——只是那个你，比现在更累、更没耐心。**
:::

## 最小可运行示例

同样一段逻辑，加上注释和规范命名：

<!-- expect
5
1 2 3 4 5
---
6 9
-->
```cpp
#include <iostream>
using namespace std;

int main() {
    int n;
    cin >> n;

    long long sumEven = 0;   // 偶数的和
    long long sumOdd = 0;    // 奇数的和

    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;

        // 用位运算判断奇偶：最低位是 1 就是奇数
        if (x & 1) {
            sumOdd += x;
        } else {
            sumEven += x;
        }
    }

    cout << sumEven << ' ' << sumOdd << '\n';
    return 0;
}
```

输入 `5` 和 `1 2 3 4 5`，输出 `6 9`（偶数 2+4=6，奇数 1+3+5=9）。

**代码变长了，但你现在扫一眼就知道它在干什么。**

## 关键过程与易错点

### 一、两种注释

```cpp
// 单行注释：从 // 到这行结束

/*
   多行注释
   可以跨好几行
*/
```

::: pitfall 多行注释不能嵌套
```cpp
/* 外层注释开始
   /* 内层注释 */     ← 这里外层注释就结束了
   这行代码会生效！  ← 编译错误
*/
```

`/* */` **不支持嵌套**：遇到第一个 `*/` 就结束。

**所以不要用 `/* */` 去"注释掉一段本来就含 `/* */` 的代码"。**
:::

### 二、临时关掉一段代码：用 `#if 0`

调试时经常要"让这一段先不生效"。**更安全的写法是 `#if 0`**：

```cpp
#if 0
    // 这中间的代码会被预处理阶段完全丢掉
    // 哪怕里面有 /* */ 或者不完整的语法，也不会影响编译
    cout << "调试输出" << debugValue;
#endif
```

| 方式 | 含 `/* */` 的代码 | 含不完整语法 |
| --- | --- | --- |
| `/* */` 注释 | ❌ 会被提前结束 | ❌ 可能报错 |
| `//` 逐行注释 | ✅ | ✅ |
| **`#if 0 … #endif`** | ✅ | ✅ |

**要关掉一整段，用 `#if 0`；要加一句说明，用 `//`。**

### 三、注释写"为什么"，不写"是什么"

```cpp
// ❌ 废话注释：代码已经说清楚了
i++;    // i 加一

// ❌ 复述代码
if (a[i] > mx) mx = a[i];    // 如果 a[i] 大于 mx 就更新 mx

// ✅ 写"为什么"
i++;    // 跳过下标 0，本题下标从 1 开始

// ✅ 写"非显然的约定"
if (a[i] > mx) mx = a[i];   // mx 初值为 a[1]，保证 n = 1 时也正确

// ✅ 写"这里的坑"
sum += a[i] * 1LL * b[i];   // 先转 long long，否则中间结果溢出
```

::: range 值得写注释的四种情况
| 情况 | 例子 |
| --- | --- |
| **非显然的边界处理** | "下标从 1 开始，所以这里 −1" |
| **防坑的写法** | "必须用 long long，n² 会溢出 int" |
| **算法的关键一步** | "二分找第一个满足 check 的位置" |
| **魔法数字** | "100005 是题目给的最大 n + 5" |

**这四种都不写，一周后你会重新推一遍。**
:::

### 四、缩进：4 个空格，大括号对齐

本书统一用 **4 个空格**缩进（不要用 Tab，不同编辑器宽度不一样）。

```cpp
// ✅ 本书风格：大括号独占一行，缩进 4 空格
#include <iostream>
using namespace std;

int main() {
    int x = 1;
    if (x > 0) {
        cout << "正数\n";
    }
    return 0;
}
```

| 规则 | 做法 |
| --- | --- |
| 缩进 | 4 个空格（同一份代码不要混用 Tab 和空格） |
| 大括号 | 左括号跟在 `)` 后面，右括号独占一行 |
| 运算符两边 | 留一个空格：`a + b`，不是 `a+b` |
| 逗号后面 | 留一个空格：`f(a, b)` |
| 每行长度 | 尽量不超过 80～100 字符 |

**风格统一的真正意义**：如果你的代码缩进乱，`if` 管着哪几行你都得数一数——
而前面讲过，[悬空 else](/guide/control-flow) 就是这么来的。

### 五、命名：短，但要有意义

竞赛代码习惯短变量名，但要**短得有意义**：

| 场景 | 好的命名 | 不好的命名 |
| --- | --- | --- |
| 循环下标 | `i` `j` `k` | `index1` `theCounter` |
| 数量 | `n` `m` `cnt` | `number` `temp1` |
| 答案 | `ans` `res` | `resultValue` |
| 最大值 | `mx` `mn` | `biggestValue` |
| 累加 | `sum` | `s`（含义不明） |
| 标记 | `vis` `flag` | `b` |

::: pitfall 两个命名纪律
1. **不用标准库名字**（`max`、`time`、`next`……）——见[编译关的黑名单](/practice/five-gates/compile)
2. **不要把 `s`、`t`、`x` 这种无意义单字母用在需要理解的地方**

`i`、`j` 当循环下标是惯例，没人会误解；
但 `s` 当"偶数和"就会让人读不懂。
:::

### 六、空行分组

长代码要**用空行分段**，每段做一件事：

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
int a[MAXN];

int main() {
    // ---- 读入 ----
    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];

    // ---- 排序 ----
    sort(a + 1, a + n + 1);

    // ---- 统计 ----
    long long sum = 0;
    for (int i = 1; i <= n; i++) sum += a[i];

    // ---- 输出 ----
    cout << sum << '\n';
    return 0;
}
```

**读者（也就是你）可以按段跳过，不用逐行读。**

## 动手检查

1. 把本节"最小可运行示例"里的注释全删掉，隔一天再看，记录你需要多久才能读懂。
2. 写一段含 `/* */` 的代码，然后**用 `/* */` 试图注释掉它**，看会发生什么；再用 `#if 0` 做一遍。
3. 找一段你以前写的代码，只做三件事：规范缩进、改掉无意义变量名、补 3 条注释。
   对比改之前和改之后。
4. 检查你现在用的编辑器：Tab 是几个空格？设置成 4 个空格。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 把一道做过的题的代码重新排版，只改格式不改逻辑 | 格式不影响结果，但影响可读性 |
| 基础 | 给一段你写的代码补注释，要求每条注释都在说"为什么" | 注释的质量 |
| 巩固 | 用 `#if 0` 关掉一段调试代码，编译确认通过 | 正确的"临时关掉"方式 |
| 巩固 | 定一套自己的命名约定（写下来），之后所有题都遵守 | 让约定变成习惯 |
| 挑战 | 一周后回看你今天的代码，标出所有"看不懂"的地方 | 亲手验证这一节的价值 |

::: pitfall 这一节的收益是延迟的
注释和风格**不会让你今天的程序跑得更快**。所以很多学生跳过它。

但它在两个时刻回报你：

1. **调试时**——你能快速看出哪一段负责什么
2. **复赛最后 30 分钟**——你要检查代码，风格乱的代码检查起来又慢又容易漏

**这两件事都直接影响分数。**
:::
