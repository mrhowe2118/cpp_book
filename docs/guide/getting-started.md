# 开始编程

这一节不教语法，只做一件事：**让你有一条自己走得通的路**——写下代码、让编译器检查、运行、提交。

## 本节学会什么

- 确认终端里的 GNU C++ 编译器可以用
- 新建 `.cpp` 文件，完成一次编译和运行
- 在洛谷提交一次程序，看懂最常见的评测结果
- 知道 Windows 学生该走哪条更省事的路线

## 为什么需要它

后面每一个知识点，你都要做同一套动作：**改代码 → 编译 → 运行 → 看结果**。

如果这套动作不熟，学习就变成了一件很痛苦的事：你分不清"我的思路错了"还是"我环境没配好"。
一旦这两件事混在一起，绝大多数人会在第一周放弃。

所以先把这条路走通，之后每学一个新语法，都能立刻验证，而不是在纸上"觉得自己懂了"。

::: pitfall 别跳过这一节
每年都有学生学完循环和数组，却从来没成功编译过一次——一直在纸上抄代码。
他们的问题从来不是不会语法，而是**没有反馈**。没有反馈的学习，等于没有学习。
:::

## 最小可运行示例

### 第一步：确认编译器

打开终端（Windows 用 PowerShell 或 CMD），输入：

```bash
g++ --version
```

输出了版本信息就说明装好了。本书统一使用 **C++17** 标准，也就是编译命令里的 `-std=c++17`。

::: range 本书的标准环境
- **评测机**：NOI Linux，`g++` 9.3.0，默认 C++14（所以必须显式写 `-std=c++17`）
- **本地练习**：Windows 学生推荐小熊猫 C++ 或 VSCode + MinGW，见附录《Windows 环境搭建》
- 只要你的 `g++` 能跑通下面的命令，跟书学就没问题
:::

### 第二步：写下第一个程序

在你的工作目录里新建 `main.cpp`，内容如下。**现在不必理解每一行**，下一节会逐个认识它们。

<!-- expect

---
Hello, Tom!
-->
```cpp
#include <iostream>

int main() {
    std::cout << "Hello, Tom!\n";
    return 0;
}
```

### 第三步：编译

```bash
g++ -std=c++17 -Wall -Wextra main.cpp -o main
```

这条命令的意思是：用 C++17 标准，把 `main.cpp` 编译成一个叫 `main` 的可执行文件。
加 `-Wall -Wextra` 是让编译器多说几句话——它提示的地方，往往就是你即将写错的地方。

### 第四步：运行

```bash
./main
```

屏幕应该输出：

```text
Hello, Tom!
```

看到这一行，你就已经真正开始学 C++ 了。

::: pitfall 三个立刻会踩的坑
1. **`./main` 前面的 `./` 不能省。** 它表示"运行当前目录下的 main"。只输入 `main`，系统会去别的地方找。
   Windows 上则是 `.\main.exe`。
2. **编译命令里的文件名要和你实际的文件名一致。** 建的是 `main.cpp`，命令里就必须是 `main.cpp`。
   后缀名不是 `.cpp`（比如隐藏了扩展名，实际叫 `main.cpp.txt`），编译器会直接报错。
3. **报错先看最前面一条。** 一个括号没配对，编译器可能连着报二十条错——后面十九条都是第一条的后果。
   改完第一条，重新编译，再看下一条。
:::

## 关键过程与易错点

### 编译错误 vs 运行错误

| 现象 | 什么时候发生 | 典型原因 |
| --- | --- | --- |
| 编译不过（CE） | 运行之前 | 括号、分号、拼写、中文标点 |
| 编译过了但结果不对 | 运行时 | 逻辑错、边界没处理、类型装不下 |
| 编译过了、崩了 | 运行时 | 数组越界、除以 0、递归太深 |

**先分清是哪一类，再去查。** 很多同学拿逻辑错误去查语法，查一晚上也查不出来。

### 洛谷的评测结果

提交之后，你会看到这些缩写，它们和上面的分类是对应的：

| 结果 | 全称 | 含义 | 你该先查什么 |
| --- | --- | --- | --- |
| **AC** | Accepted | 通过 | — |
| **WA** | Wrong Answer | 答案不对 | 输出格式、边界、样例没手算 |
| **CE** | Compile Error | 编译失败 | 抄报错信息，看行号 |
| **RE** | Runtime Error | 运行时崩溃 | 数组越界、除以 0、递归爆栈 |
| **TLE** | Time Limit Exceeded | 超时 | 复杂度、死循环 |
| **MLE** | Memory Limit Exceeded | 内存超限 | 数组开太大 |
| **UKE** | Unknown Error | 未知错误 | 通常要联系评测方 |

::: exam 第一次提交的纪律
- **先手算样例，再对答案。** 样例算错了，代码对了你也看不出来。
- **一次只改一个地方。** 同时改三处，你永远不知道是哪一处起了作用。
- **记录你的第一次提交结果。** 从今天起建立"读到结果 → 定位原因"的手感，这是复赛最值钱的能力。
:::

## 动手检查

1. 把输出改成你的名字和一句英文，**每句各占一行**。重新编译、运行，确认改动真的出现在终端里。
2. 故意删掉一行的分号，重新编译，**把报错信息完整读一遍**。你会看到 `expected ';'` 之类的提示和行号——这就是以后定位问题的依据。改回去。
3. 故意把 `"Hello, Tom!\n"` 里的 `\n` 删掉，观察输出有什么变化。

## 立即练习

| 难度 | 题目 | 练什么 |
| --- | --- | --- |
| 基础 | [洛谷 P1000 超级玛丽游戏](https://www.luogu.com.cn/problem/P1000) | 完成一次精确输出和在线提交 |
| 基础 | [洛谷 P1001 A+B Problem](https://www.luogu.com.cn/problem/P1001) | 完整程序的输入输出格式 |
| 巩固 | [洛谷 P1008 三连击](https://www.luogu.com.cn/problem/P1008) | 顺便提前感受一下循环能解决什么 |

::: pitfall P1000 的坑
P1000 要求**逐字符完全一致**的输出，多一个空格、少一个换行都是 WA。
它考的不是算法，是"你能不能精确按格式输出"——这恰恰是复赛第一题最常见的丢分点。

抄的时候别手打，但**一定要看一遍每一行长什么样**。
:::
