# 数组

数组是第一个"能把数据存下来"的工具。**没有它，程序只能边读边算，看过的东西就永远丢了。**

## 本节学会什么

- 用数组把一组数据完整存下来
- 分清下标从 0 开始和使用 `1 ~ n` 两种写法
- 知道为什么**大数组要开在全局**
- 认识数组开小导致的 RE，并养成"多开几个位置"的习惯

## 为什么需要它

先看一道题：**读入 n 个数，倒序输出。**

不用数组，你能做到吗？

不能。因为你要输出**最后一个数**的时候，前面那些数早就读过去、忘掉了。程序必须先把它们**存下来**，才能在读完之后回头处理。

这就是数组存在的全部理由：**把数据留在内存里，供后面反复使用。**

::: range 从"边读边算"到"存下来再算"
| 需求 | 不用数组行不行 |
| --- | --- |
| 求和、求最大值 | ✅ 行，边读边更新 |
| 倒序输出、第 k 个元素 | ❌ 不行，必须存 |
| 统计每个数出现几次 | ❌ 不行，要一个桶 |
| 排序、去重、前缀和 | ❌ 不行 |

**只要题目出现"回头再看"的需求，就需要数组。**
:::

## 最小可运行示例

读入 `n` 个数，存进数组，然后倒序输出，并求和、求最大值：

<!-- expect
5
3 1 4 1 5
---
5 1 4 1 3
sum = 14, max = 5
-->
```cpp
#include <iostream>
using namespace std;

const int MAXN = 100005;   // 数组容量上限，多开 5 个保底
int a[MAXN];               // 开在全局：不占栈空间

int main() {
    int n;
    cin >> n;

    for (int i = 1; i <= n; i++) {
        cin >> a[i];
    }

    // 倒序输出
    for (int i = n; i >= 1; i--) {
        cout << a[i] << ' ';
    }
    cout << '\n';

    // 求和与最大值
    long long sum = 0;
    int mx = a[1];
    for (int i = 1; i <= n; i++) {
        sum += a[i];
        if (a[i] > mx) mx = a[i];
    }
    cout << "sum = " << sum << ", max = " << mx << '\n';
    return 0;
}
```

输入：

```text
5
3 1 4 1 5
```

输出：

```text
5 1 4 1 3
sum = 14, max = 5
```

## 关键过程与易错点

### 下标从 0 开始，但你可以从 1 开始用

C++ 的数组下标**从 0 开始**：`int a[5]` 的合法下标是 `0, 1, 2, 3, 4`，**没有 `a[5]`**。

但写题时更常用 `1 ~ n`：

```cpp
int a[MAXN];
for (int i = 1; i <= n; i++) cin >> a[i];   // 下标 1..n
```

为什么？有两个实际好处：

1. **下标和"第几个"直接对应**，读代码时不用在脑子里做 `+1` 转换。题目说"第 i 个数"，代码就是 `a[i]`。
2. **前缀和、差分这类算法从 1 开始才不用特殊处理边界**，`s[i] = s[i-1] + a[i]` 在 `i=1` 时也能正常跑。

代价是 `a[0]` 空着不用。**这完全值得。**

::: pitfall 两种写法不要混用
下面这段是错的，请找出问题：

```cpp
int a[MAXN];
for (int i = 0; i < n; i++) cin >> a[i];   // 存进了 0..n-1
for (int i = 1; i <= n; i++) cout << a[i]; // 读的是 1..n
```

读进来的数据在 `0 ~ n-1`，输出的却是 `1 ~ n`——**整体错位一格**，首元素丢失，末尾读了一个没赋值的垃圾值。

**一节之内只用一种风格。** 建议统一用 `1 ~ n`。
:::

### 大数组一定要开在全局

这是**本节最重要的一条**，也是复赛里 RE 和 MLE 的常见原因。

<!-- no-compile -->
```cpp
// ❌ 危险：开在 main 内部，占用栈空间
int main() {
    int a[1000000];   // 4 MB，栈可能直接爆掉
}

// ✅ 正确：开在全局，放在静态存储区
const int MAXN = 1000005;
int a[MAXN];
int main() { ... }
```

::: exam 为什么这与分数直接相关
评测机的**栈空间通常就等于题目的内存限制**，而且局部数组还要和你所有的局部变量抢这块空间。

- 函数里写 `int a[1000000]` 就是 4 MB；递归再一深，直接 RE。
- 全局数组不受栈限制，只在总内存里算。

**习惯：所有可能变大的数组，一律开在全局，用 `MAXN` 常量控制大小。**
:::

### 数组开小是最典型的 RE

```cpp
#include <iostream>
using namespace std;

const int MAXN = 1005;
int a[MAXN];

int main() {
    int n;
    cin >> n;         // 如果输入 n = 5000
    for (int i = 1; i <= n; i++) cin >> a[i];   // 越界写！
}
```

越界**不一定会立刻崩**。它可能悄悄改掉别的变量的值，于是你的程序"算着算着结果就变了"——
这类 bug 极难调试，因为出错的地方和报错的地方离得很远。

::: pitfall 开数组的三条纪律
1. **按题目的最大数据范围开**，不要按样例开。题目说 `n ≤ 10^5`，就开 `100005`。
2. **多开 5～10 个位置**。`n ≤ 10^5` 就开 `100005` 而不是 `100000`，给防御性余量。
3. **不要用变量开数组**。`int a[n];` 是变长数组（VLA），C++ 标准不支持，
   NOI Linux 上能编过但行为不可靠。数组大小必须是**编译期常量**：

<!-- no-compile -->
```cpp
// ❌ 不要
int n; cin >> n; int a[n];

// ✅ 要
const int MAXN = 100005;
int a[MAXN];
```
:::

### 数组能开多大？算一下就知道

内存 = 元素个数 × 每个元素的字节数。

| 写法 | 占用 |
| --- | --- |
| `int a[100000]`（10⁵） | 0.4 MB |
| `int a[10000000]`（10⁷） | 40 MB |
| `long long a[10000000]` | 80 MB |
| `int a[100000000]`（10⁸） | **400 MB，直接 MLE** |

::: pitfall MLE 是按"声明的空间"算的
`int a[100000000]` 哪怕你只用前 10 个元素，评测机也按 400 MB 计——**超限就是 0 分**。
数组尺寸只看你的声明，不看你的实际使用。这一条在《资源关》里还会再讲一次。
:::

## 动手检查

1. 把示例程序的 `const int MAXN = 100005;` 改成 `5`，输入 `5` 个数运行看看——为什么这次没崩？
   再把输入改成 `10` 个数，会发生什么？（这就是"越界不一定立刻崩"）
2. 写一个程序：读入 n 个数，输出**最大值和它的下标**（如果有多个最大值，输出最小的下标）。
3. 写一个程序：读入 n 个 `1 ~ 100` 之间的数，用桶统计每个数出现的次数。体验"数组当下标用"。

::: pitfall P2141 的典型错误
统计"有多少个数等于另外两个数之和"时，很多人的代码会**把同一个符合条件的数重复计数**。
先把所有数标记进桶，再对每个数判断一次，最后统计——想清楚"谁被数了、数了几次"。
