# 函数参数与引用

上一节留了一个悬念：

```cpp
void swapWrong(int a, int b) { int t = a; a = b; b = t; }   // 交换失败
```

**为什么失败？怎么才能成功？** 这一节把它讲透——这也解释了竞赛代码里到处出现的 `&`。

## 本节学会什么

- 说清"值传递"到底传了什么（**副本**）
- 会用引用 `&` 让函数**真正修改**外面的变量
- 知道 `const 类型 &` 是结构体参数的标准写法
- 学会用引用让函数"返回多个结果"

## 为什么需要它

先看一个对比实验，三种写法都想交换两个数：

| 写法 | 结果 |
| --- | --- |
| `void f(int a, int b)` | ❌ 失败 |
| `void f(int &a, int &b)` | ✅ 成功 |
| `void f(int *a, int *b)` | ✅ 成功，但写起来麻烦 |

::: exam 核心区别只有一句话
**值传递：函数拿到的是复印件。**
**引用传递：函数拿到的是原件本身。**

你改复印件，原件不会变——这就是 `swapWrong` 失败的全部原因。
:::

## 最小可运行示例

<!-- expect

---
值传递后：x=1 y=2
引用传递后：x=2 y=1
-->
```cpp
#include <cstdio>

// ① 值传递：参数是副本
void swapByValue(int a, int b) {
    int t = a;
    a = b;
    b = t;              // 只改了副本，外面的 x、y 不受影响
}

// ② 引用传递：参数就是外面的变量本身
void swapByRef(int &a, int &b) {
    int t = a;
    a = b;
    b = t;              // 直接改到了 x、y
}

int main() {
    int x = 1, y = 2;

    swapByValue(x, y);
    printf("值传递后：x=%d y=%d\n", x, y);

    swapByRef(x, y);
    printf("引用传递后：x=%d y=%d\n", x, y);

    return 0;
}
```

输出：

```text
值传递后：x=1 y=2
引用传递后：x=2 y=1
```

**只有一个字符的差别（`&`），结果完全不同。**

::: range 画个内存图就彻底懂了
```text
调用 swapByValue(x, y)：

   main 里              swapByValue 里
   x = 1  ──复制──→     a = 1      ← 是一块新的内存
   y = 2  ──复制──→     b = 2

   函数里交换 a、b：      a = 2, b = 1
   函数结束，a、b 销毁 →  x、y 从没被碰过
```

```text
调用 swapByRef(x, y)：

   main 里              swapByRef 里
   x = 1  ←──── a 就是 x 本身（同一个内存）
   y = 2  ←──── b 就是 y 本身

   函数里交换 a、b → 就是交换 x、y
```

**关键：引用不是"另一个变量"，它是"同一个变量的另一个名字"。**
:::

## 关键过程与易错点

### 一、`&` 出现在两个地方，含义不同

这一点必须先分清，否则会看晕：

| 位置 | 例子 | 含义 |
| --- | --- | --- |
| **参数列表里** | `void f(int &a)` | **引用**：a 是外面那个变量本身 |
| **表达式里** | `scanf("%d", &x);` | **取地址**：把 x 的地址交给函数 |

```cpp
void f(int &a) { }      // 这里的 & 是"引用"
int x;
scanf("%d", &x);        // 这里的 & 是"取地址"
```

**同一个符号，两种含义。看它出现在哪。**

::: pitfall 别把 `&` 当"传地址"理解
虽然底层实现确实和地址有关，但**理解成"给变量起个别名"更准确，也更好用**。

```cpp
int x = 5;
int &r = x;        // r 是 x 的别名
r = 10;            // 现在 x 也是 10
printf("%d\n", x); // 输出 10
```

**改 `r` 就是改 `x`**——因为它们是同一个东西的两个名字。
:::

### 二、什么时候该用引用

| 场景 | 怎么写 | 为什么 |
| --- | --- | --- |
| **需要修改**外面的变量 | `void f(int &x)` | 值传递改不了 |
| **传递大对象**（结构体、`string`） | `void f(const Big &b)` | 避免复制，快 |
| 传递小对象（`int`、`double`） | `void f(int x)` | 复制成本可忽略，写起来简单 |
| 不想让函数修改它 | `void f(const Big &b)` | `const` 兜底 |

::: exam 竞赛里的两条实用规则
1. **要让函数改外面的值 → 加 `&`**
2. **结构体 / `string` 作参数 → 一律 `const 类型 &`**

**第 2 条几乎是无脑写法**，不用判断大小，直接这么写就对了。
:::

### 三、用引用"返回多个结果"

函数只能 `return` 一个值。但用引用，可以让它**顺带写出好几个结果**：

<!-- expect

---
3 7
-->
```cpp
#include <cstdio>

// 同时求出最小值和最大值：通过引用把它们"送出去"
void minMax(int a, int b, int &mn, int &mx) {
    if (a < b) { mn = a; mx = b; }
    else       { mn = b; mx = a; }
}

int main() {
    int lo, hi;

    minMax(7, 3, lo, hi);      // lo、hi 会被函数写进去

    printf("%d %d\n", lo, hi);
    return 0;
}
```

输出 `3 7`。

::: pitfall 被引用"输出"的变量要有定义
```cpp
minMax(7, 3, lo, hi);      // lo、hi 必须先声明
```

**引用必须绑定到一个已存在的变量**，不能凭空产生。这也是它和"指针"的一个区别。

**注意**：上面 `lo`、`hi` 没有初值也能工作，因为函数**无条件给它们赋值**。
但如果你不确定函数会不会赋值，就**先给个初值**——这符合[变量与作用域](/guide/variables)的纪律。
:::

### 四、`const` 引用：不复制，也不许改

<!-- expect
6
-->
```cpp
#include <cstdio>

struct Big {
    int a[100];
    int n;
};

// const & ：既不复制整个结构体，也保证函数不会改它
void printSum(const Big &b) {
    long long s = 0;
    for (int i = 0; i < b.n; i++) s += b.a[i];
    printf("%lld\n", s);
}

int main() {
    Big b;
    b.n = 3;
    b.a[0] = 1; b.a[1] = 2; b.a[2] = 3;

    printSum(b);
    return 0;
}
```

::: range `const 类型 &` 的两个好处
| 好处 | 说明 |
| --- | --- |
| **不复制** | 传 `Big`（约 400 字节）会复制一整份；传引用只传一个"别名" |
| **不能改** | 在函数里写 `b.n = 5;` 会**编译报错**，比靠自觉可靠 |

**这是"既要快、又要安全"的标准答案。** 竞赛里出现结构体参数，基本都是这个写法。
:::

### 五、数组参数：本来就是"传地址"

数组是个特例：**数组作为参数时不会复制**。

```cpp
void fill(int a[], int n) {
    for (int i = 0; i < n; i++) a[i] = i;    // 会改到外面！
}
```

| 传什么 | 函数里的修改会不会影响外面 |
| --- | --- |
| `int` / `double` / 结构体 | ❌ 不会（值传递） |
| **数组** | ✅ **会** |
| `vector`（后面的 STL） | ✅ 会 |

::: pitfall 数组参数必须另外传长度
```cpp
void fill(int a[]) { }          // ✗ 函数里不知道 a 有多长
void fill(int a[], int n) { }   // ✓
```

C++ 里数组传参会丢掉长度信息，**必须额外传一个 `n`**。

**注意**：也可以写成 `void fill(int *a, int n)`——效果完全一样。
`int a[]` 只是更好读的写法。
:::

### 六、一个必须避开的错误：别返回局部变量的引用

```cpp
int &bad() {
    int x = 5;
    return x;          // ✗ x 在函数结束时就被销毁了
}
```

::: pitfall 返回局部变量的引用 = 悬空引用
`x` 是局部变量，函数一返回它就没了。你拿到的引用指向一块**已经失效的内存**。

- 读它 → 得到垃圾值
- 编译器可能只给个警告（`-Wall` 会提示 `reference to local variable returned`）

**纪律：不要返回局部变量的引用。** 需要返回多个结果时，用上面那种"引用参数"的写法。
:::

### 七、值传递 / 引用 的对照总结

| | 值传递 `f(int x)` | 引用 `f(int &x)` | const 引用 `f(const T &x)` |
| --- | --- | --- | --- |
| 函数拿到 | 副本 | 原件 | 原件（只读） |
| 能改外面吗 | ❌ | ✅ | ❌ |
| 有复制开销吗 | 有 | 无 | 无 |
| 适合 | 小类型、纯计算 | 需要修改 | **大对象、只读** |

## 动手检查

1. 把 `swapByRef` 的参数改回 `int a, int b`（去掉 `&`），运行确认交换又失败了。
2. 写一个 `void addOne(int &x) { x++; }`，调用后确认外面的值真的加了 1。
3. 把 `const Big &b` 的 `const` 去掉，然后在函数里写 `b.n = 5;`，看编译能不能通过；
   再加回 `const`，看它怎么报错。
4. 故意写一个"返回局部变量引用"的函数，加 `-Wall` 编译，看警告信息。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 写 `void swap(int &a, int &b)` 并在 main 里验证 | 引用的最基本用法 |
| 基础 | 写 `void addOne(int &x)`，让调用者看到变化 | 引用做输出参数 |
| 巩固 | 写 `void minMax(int a[], int n, int &mn, int &mx)` | 数组参数 + 引用输出 |
| 巩固 | 写 `void normalize(string &s)`，把字符串都转成小写 | 引用修改 `string` |
| 挑战 | [洛谷 P1012 拼数](https://www.luogu.com.cn/problem/P1012) | 自定义比较 + 排序（需要 `cmp` 的 `const &` 写法） |

::: pitfall 做完 P1012，你会彻底用上这一节
它的比较规则是"**两种拼接方式哪个大**"：

```cpp
bool cmp(const string &a, const string &b) {
    return a + b > b + a;      // 两个参数都是 const &
}
```

**`const string &` 就是这一节的标准写法**——不复制字符串，也不许改。
:::
