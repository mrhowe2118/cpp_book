# 分支结构

程序到现在只会"一条路走到底"。**分支让它能根据输入做不同的选择**——这是"程序"和"计算器"的分界线。

## 本节学会什么

- 用 `if` / `else if` / `else` 写出多路判断
- 分清 `=`（赋值）和 `==`（比较）——这是最经典的一个坑
- 知道**判断区间的顺序**会决定结果对错
- 会用 `&&` `||` `!` 组合条件，理解"短路求值"
- 认识悬空 `else` 与漏写大括号的后果

## 为什么需要它

看一道题：**输入一个 0～100 的分数，输出等级**（90 以上 A，80 以上 B，……）。

不用分支，你能做到吗？

不能。因为输出**取决于输入落在哪个区间**——程序必须"看情况"选择输出的内容。

::: exam 分支的本质：让程序会"看情况"
没有分支的程序，输入什么输出什么都是死的。

有了分支，同一份代码在不同输入下走不同的路径。

**这也意味着：分支写错，只有在特定的输入下才会出错**
——所以分支的 bug 最难通过"随便试一下"发现。
:::

## 最小可运行示例

<!-- expect
85
---
B
-->
```cpp
#include <iostream>
using namespace std;

int main() {
    int score;
    cin >> score;

    if (score >= 90) {
        cout << "A\n";
    } else if (score >= 80) {
        cout << "B\n";
    } else if (score >= 70) {
        cout << "C\n";
    } else if (score >= 60) {
        cout << "D\n";
    } else {
        cout << "E\n";
    }
    return 0;
}
```

输入 `85`，输出 `B`。

**执行流程**：从上往下逐个检查条件，**第一个成立的分支执行完就结束**，后面的不再看。

```text
score = 85
  score >= 90 ?  否
  score >= 80 ?  是  → 输出 B，结束
  （后面的分支不再判断）
```

::: pitfall 顺序错了，结果就错了
把上面的条件**倒过来**写，会怎样？

<!-- expect
95
---
及格
-->
```cpp
#include <iostream>
using namespace std;

int main() {
    int score = 95;              // 95 分，应该是"优秀"

    if (score >= 60) cout << "及格\n";
    else if (score >= 90) cout << "优秀\n";    // ✗ 永远走不到这里

    return 0;
}
```

输入 95，输出的却是 **`及格`**。

因为 `95 >= 60` 已经成立了，**程序根本不会再去看后面那个条件**。

**结论：区间判断必须"从严到宽"或者"从宽到严"，方向要统一。**
:::

## 关键过程与易错点

### 一、`=` 和 `==` 的区别（最经典的坑）

| 运算符 | 含义 | 例子 |
| --- | --- | --- |
| `=` | **赋值**：把右边的值放进左边 | `a = 5;` 让 `a` 变成 5 |
| `==` | **比较**：判断两边是否相等 | `a == 5` 得到 `true` 或 `false` |

写错成 `if (a = 5)` 会发生什么？**它不会报错**，而且条件永远成立。

<!-- expect
条件成立，a = 5
-->
```cpp
#include <cstdio>

int main() {
    int a = 0;

    if (a = 5) {                    // ✗ 这是赋值！把 5 放进 a，结果是 5（非 0 = 真）
        printf("条件成立，a = %d\n", a);
    } else {
        printf("条件不成立，a = %d\n", a);
    }
    return 0;
}
```

::: pitfall 为什么这个错误特别危险
- **编译器不报错**（`a = 5` 是一个合法的表达式，值为 5）
- 大多数编译器只会给一个警告（`suggest parentheses around assignment`）
- **条件永远成立**，你的 `else` 分支永远不执行

**所以 `-Wall` 必须打开**（见[开始编程](/guide/getting-started)）。
看到"赋值当条件用"的警告，立刻改成 `==`。

**一个习惯**：把常量写在左边——`if (5 == a)`。
万一少打一个 `=` 变成 `if (5 = a)`，**编译器会直接报错**（不能给常量赋值），bug 当场暴露。
:::

### 二、判断条件：比较运算符

| 运算符 | 含义 | 注意 |
| --- | --- | --- |
| `==` | 等于 | 别写成 `=` |
| `!=` | 不等于 | |
| `>` `<` | 大于 / 小于 | |
| `>=` `<=` | 大于等于 / 小于等于 | `=>` 和 `=<` 是错的，编不过 |

::: pitfall 数学写法和 C++ 写法不一样
数学里的 `0 < x < 10`，在 C++ 里**不能这么写**：

```cpp
if (0 < x < 10) { }        // ✗ 语法没错，但含义完全不对
```

它会被理解成 `(0 < x) < 10`：先算出 `0 < x`（真 = 1 或假 = 0），
再拿这个结果去和 10 比——**永远成立**。

正确写法是用 `&&` 连接：

```cpp
if (0 < x && x < 10) { }   // ✓
```
:::

### 三、`&&`、`||`、`!` 与短路求值

| 运算符 | 含义 | 什么时候为真 |
| --- | --- | --- |
| `&&` | 并且 | **两边都**为真 |
| `\|\|` | 或者 | **至少一边**为真 |
| `!` | 取反 | 原来为假 |

**短路求值**：`&&` 发现左边是假，就**不会再算右边**；`||` 发现左边是真，也不再算右边。

```cpp
if (i < n && a[i] > 0) { }   // ✓ 安全
```

上面是把边界检查写在前面：如果 `i >= n`，右边根本不会执行，**不会越界**。

::: pitfall 反过来写就会越界
```cpp
if (a[i] > 0 && i < n) { }   // ✗ i 越界时，a[i] 已经被读了 → RE
```

**规律：先检查边界，再用这个下标去访问数组。**
:::

### 四、大括号：一行也要加

```cpp
if (x > 0)
    cout << "正数\n";
    cout << "处理完毕\n";      // ✗ 这一行不受 if 控制！永远执行
```

`if` **只管一条语句**。想控制多条，必须用 `{ }`：

```cpp
if (x > 0) {
    cout << "正数\n";
    cout << "处理完毕\n";      // ✓ 两行都在 if 里
}
```

**纪律：`if` 后面一律加 `{ }`，哪怕只有一行。** 以后要加代码时不会踩坑。

### 五、悬空 `else`

`else` 总是和**最近的、还没配对的 `if`** 配对。

<!-- expect
程序结束
-->
```cpp
#include <iostream>
using namespace std;

int main() {
    int a = -1, b = 1;

    if (a > 0)
        if (b > 0) cout << "两个都大于 0\n";
    else
        cout << "这一行你以为是外层 if 的 else？\n";

    cout << "程序结束\n";
    return 0;
}
```

输出只有 `程序结束`。

**因为 `else` 配给了内层 `if`**，整个结构是：

```cpp
if (a > 0) {
    if (b > 0) cout << "…";
    else       cout << "…";
}
```

`a > 0` 是假，所以里面两层都没执行。

::: pitfall 避免悬空 else 的唯一办法
**所有 `if` 都加 `{ }`。**

```cpp
if (a > 0) {
    if (b > 0) { cout << "两个都大于 0\n"; }
} else {
    cout << "这一行确实是外层 if 的 else\n";
}
```

加了大括号，`else` 属于谁一目了然——**再也不会配错**。
:::

### 六、浮点数不要用 `==`

```cpp
double x = 0.1 + 0.2;
if (x == 0.3) { }              // ✗ 永远不成立（浮点误差）
if (fabs(x - 0.3) < 1e-8) { }  // ✓ 用容差比较
```

### 七、三目运算符：简单的二选一

```cpp
int mx = (a > b) ? a : b;      // 读作：a > b 吗？是就取 a，否则取 b
```

适合**很短**的二选一。如果逻辑一复杂，还是用 `if` 更清楚。

### 八、`switch`：多路等值判断

当判断的是"**等于某个值**"而不是区间时，`switch` 比一串 `else if` 清楚：

```cpp
switch (op) {
    case 1: cout << "加法\n"; break;
    case 2: cout << "减法\n"; break;
    default: cout << "未知\n"; break;
}
```

::: pitfall `switch` 忘了 `break` 会"穿透"
```cpp
switch (op) {
    case 1: cout << "加法\n";     // 忘了 break
    case 2: cout << "减法\n"; break;
}
```

`op == 1` 时会输出**两行**——因为它执行完 `case 1` 后**继续往下执行**了。

**每个 `case` 后面都要 `break`**（除非你故意要穿透）。
:::

## 动手检查

1. 把成绩等级程序的条件从"从严到宽"改成"从宽到严"（先判 `>= 60`），
   输入 95 看输出变成什么。
2. 把 `if (a == 5)` 改成 `if (a = 5)`，编译时注意警告信息，运行看结果。
3. 输入边界值测试你的分支：`0`、`59`、`60`、`100`、`101`。
   **每个边界都要想：题目要求的边界在哪一边？**
4. 给"判断闰年"写分支（能被 4 整除但不能被 100 整除，或者能被 400 整除），
   然后测 `2000`、`1900`、`2024`、`2023`。

::: pitfall 分支题一定要测"每一档"
分支的 bug 有个特点：**只有走到那条分支才会暴露**。

所以测试时不要只测一个输入——**每一种情况都测一遍**：

- 每个区间各来一个值
- 每个边界值（区间的两端）
- 特殊输入（0、负数、最大值）

**这是[结果关](/practice/five-gates/result)"边界情况"在分支上的具体做法。**
:::
