# 计算机原理（选读）

**这一节不教新语法。** 它的作用是：**把前面那些"为什么要这样写"的规矩，从"记住"变成"理解"。**

理解之后，你就不需要背了。

## 本节学会什么

- 知道程序的内存分成哪几块，变量分别住在哪
- 理解数组下标的地址计算，明白为什么从 0 开始
- 看懂"编译"到底分几步
- 用这些原理**解释**前面学过的所有"奇怪规矩"

## 为什么需要它

前面出现过很多"看起来没道理"的规矩：

| 规矩 | 在哪一节学的 |
| --- | --- |
| 大数组要开在全局 | [数组](/guide/arrays) |
| 局部变量不初始化就是垃圾值，全局的是 0 | [变量与作用域](/guide/variables) |
| 递归太深会"爆栈" | [递归](/guide/recursion) |
| 数组下标从 0 开始 | [数组](/guide/arrays) |
| `int` 装不下就变成乱七八糟的数 | [数据类型与溢出](/guide/data-types) |
| 数组传参不复制，其他类型会复制 | [函数参数与引用](/guide/function-parameters) |

::: exam 这些规矩背后是同一套机制
**它们不是"语法规定"，而是"内存长什么样"的必然结果。**

一旦你脑子里有了内存的画面，这些规矩就变成"显然的"：

```text
"为什么全局数组能开很大？"
  → 因为它不在栈上，栈很小。

"为什么局部变量是垃圾值？"
  → 因为栈只是把指针往下挪，不会帮你把内存清零。
```
:::

## 最小可运行示例

**数组为什么能从下标算出地址？** 看这个：

<!-- expect

---
sizeof(int) = 4
相邻元素相差 4 字节
整个数组占 12 字节
-->
```cpp
#include <cstdio>

int main() {
    int arr[3] = {1, 2, 3};

    printf("sizeof(int) = %d\n", (int)sizeof(int));
    printf("相邻元素相差 %d 字节\n", (int)((char *)&arr[1] - (char *)&arr[0]));
    printf("整个数组占 %d 字节\n", (int)sizeof(arr));

    return 0;
}
```

输出：

```text
sizeof(int) = 4
相邻元素相差 4 字节
整个数组占 12 字节
```

::: exam 数组的元素是"挨着排"的
```text
内存里的样子（每个格子 1 字节）：

  地址:  1000 1001 1002 1003 | 1004 1005 1006 1007 | 1008 ...
  arr[0] ←──── 4 字节 ────→  arr[1] ←──── 4 字节 ────→  arr[2]

访问 arr[i] 的地址 = 首地址 + i × 4
```

**这正是"下标从 0 开始"的原因**：

```text
arr[0] 的地址 = 首地址 + 0 × 4 = 首地址      ← 第一个元素就在首地址
arr[1] 的地址 = 首地址 + 1 × 4
```

**如果从 1 开始，每次访问都要多减一次**，白白浪费一次运算。
所以 C 语言选了 0。
:::

## 关键过程与易错点

### 一、程序的内存分成几块

```text
高地址
  ┌──────────────┐
  │    栈 Stack   │  ← 局部变量、函数调用信息（小，通常几 MB）
  │      ↓        │     向下增长
  ├──────────────┤
  │              │
  │      ↑        │
  │    堆 Heap    │  ← new / vector 的动态内存（大）
  ├──────────────┤
  │  静态存储区    │  ← 全局变量、static 变量（程序启动时就分配好）
  ├──────────────┤
  │   代码区       │  ← 编译后的机器指令（只读）
  └──────────────┘
低地址
```

| 变量写在哪 | 住在哪 | 生命周期 | 初值 |
| --- | --- | --- | --- |
| 函数外的全局变量 | **静态存储区** | 整个程序 | **自动为 0** |
| 函数内的 `static` 变量 | **静态存储区** | 整个程序 | **自动为 0** |
| 函数内的普通局部变量 | **栈** | 函数执行期间 | **不确定（垃圾值）** |
| `vector` / `new` 出来的 | **堆** | 手动管理 | 不确定 |

### 二、为什么"大数组要开在全局"

::: range 栈很小，静态区大得多
**栈**：通常只有几 MB。你开一个 `int a[1000000]` 就是 4 MB，栈可能直接爆掉 → RE。

**静态存储区**：受总内存限制（几百 MB），开大数组完全没问题。

```cpp
int a[1000000];              // ✓ 全局：静态区，4 MB 没问题

int main() {
    int b[1000000];          // ✗ 局部：栈上 4 MB，很可能爆栈
}
```

**这就是[数组](/guide/arrays)和[资源关](/practice/five-gates/resource)里那条规矩的来源**——
不是"规定"，是"栈真的放不下"。

**递归"爆栈"也是同一回事**：每深入一层都要在栈上占一块空间放局部变量和返回地址。
:::

### 三、为什么"局部变量是垃圾值"

**栈的分配只是"把指针往下挪一格"** —— 它不会帮你清零。

```text
调用函数时：栈指针 -= 这块的大小     ← 就这一步
函数里的 int sum;                     ← sum 里是上一轮用过的内存残留
```

**所以 `int sum;` 的值取决于"之前谁用过这块内存"。**

而在静态存储区，操作系统在程序启动时**会把整块清零**（这是操作系统的职责），
所以全局变量自动是 0。

::: pitfall 这就是"本地对、评测机错"的一个根源
```cpp
int sum;                          // 局部，垃圾值
for (int i = 1; i <= 10; i++) sum += i;
```

- 你的电脑上，那块内存**恰好**是 0 → 结果正确
- 评测机上，那块内存**恰好**是别的值 → 结果错

**"恰好"两个字最要命。** 所以纪律是"声明时就初始化"。
:::

### 四、为什么 `int` 会溢出

整数在内存里是**固定长度的二进制**：

```text
int：32 位（4 字节）
最大能表示 2³¹ - 1 = 2147483647
```

超出这个范围的运算结果，**高位会被丢掉**，剩下的位重新解释成一个数：

```text
100000 × 100000 = 10000000000（需要 34 位）
int 只有 32 位 → 丢掉高位 → 得到 1410065408
```

**它不是"报错"，是"截断"**——所以永远不报错，只给你一个错答案。

（负数的表示用**补码**，这也是[位运算](/advanced/bit-operations)里 `~x == -x-1` 的原因。）

### 五、编译到底做了什么

你敲的那条命令：

```bash
g++ -std=c++17 -Wall main.cpp -o main
```

内部其实分了四步：

```text
① 预处理   展开 #include、处理 #define、去注释     → .i
② 编译     把 C++ 翻译成汇编                       → .s
③ 汇编     把汇编翻译成机器码                      → .o
④ 链接     把多个 .o 和库拼在一起，生成可执行文件   → main
```

::: range 这解释了三种报错的区别
| 报错 | 发生在哪一步 | 典型信息 |
| --- | --- | --- |
| **编译错误** | ② | `expected ';'`、`was not declared` |
| **链接错误** | ④ | `undefined reference to 'main'` |
| **运行时错误** | 程序跑起来之后 | 段错误、结果不对 |

**看到 `undefined reference` 就知道：语法没错，是"少了个东西"**——
比如拼错了 `main`、或者用了没实现的函数（见[编译关](/practice/five-gates/compile)）。

**这也是"编译过了"和"结果对了"是两件事的原因**（见[测试与调试](/guide/testing-and-debugging)）。
:::

### 六、浮点数为什么不精确

`double` 用**二进制**存小数，而很多十进制小数（如 `0.1`）在二进制里是**无限循环**的。

```text
0.1（十进制）= 0.0001100110011001100...（二进制，无限循环）
             → 只能存前 52 位 → 有误差
```

**所以 `0.1 + 0.2 != 0.3`**（见[结果关](/practice/five-gates/result)）。

| 类型 | 能精确表示的数 |
| --- | --- |
| `int` / `long long` | 范围内的**所有整数** |
| `double` | 能表示 `k / 2ⁿ` 形式的数，其余有误差 |

**结论：涉及金额、计数、需要精确比较时，一律用整数。**
:::

### 七、这些原理能解释的所有规矩

| 前面学过的规矩 | 背后的原理 |
| --- | --- |
| 大数组开全局 | 栈小、静态区大 |
| 局部变量要初始化 | 栈不清零 |
| 全局变量自动是 0 | 静态区启动时清零 |
| 递归太深会爆栈 | 每层都占栈空间 |
| 数组下标从 0 开始 | 地址 = 首地址 + 下标 × 元素大小 |
| `int` 溢出会变乱码 | 定长二进制、高位截断 |
| 数组传参不复制 | 数组名退化成首地址 |
| 结构体传参要加 `&` | 值传递会复制整个对象 |
| 浮点数不能用 `==` | 二进制无法精确表示十进制小数 |
| `undefined reference` | 链接阶段的错误 |

::: exam 这张表值得抄下来
**它不是"知识清单"，是"因果链"。**

以后遇到新的"奇怪规矩"，试着也填进这张表：
**它在内存层面是为了什么？** 想通了就不用背了。
:::

## 动手检查

1. 用 `sizeof` 验证：`int`、`long long`、`double`、`char`、`bool` 各占几字节。
2. 打印几个变量的地址（`%p`），观察全局变量、静态变量、局部变量的地址范围有什么不同。
3. 写一个函数，在里面对未初始化的局部数组求和，**连续调用两次**，
   看第二次的结果是不是"上次残留的值"。
4. 用 `g++ -E` 只看预处理结果（`g++ -E main.cpp | head -50`），看看 `#include` 被展开成什么样。

## 立即练习

| 难度 | 练习 | 练什么 |
| --- | --- | --- |
| 基础 | 用 `sizeof` 列出所有基本类型的大小 | 内存视角 |
| 基础 | 打印各类变量的地址，观察分布 | 栈 / 静态区 |
| 巩固 | 写一个递归函数，逐步增大深度直到崩溃，找出大概的极限 | 理解栈空间 |
| 巩固 | 复现 `0.1 + 0.2 != 0.3`，并解释原因 | 浮点误差 |
| 挑战 | 用 `g++ -E` 和 `g++ -S` 观察编译的中间产物 | 编译过程 |

::: pitfall 这一节"考试不考"，但影响你学得多快
没有人会在试卷上问你"栈和堆的区别"。

**但理解了它，你学后面所有内容都会更快**——
因为你会知道每个语法规则"为什么存在"，而不是死记。

**这就是"选读"的价值：它不直接给分，它让你少走弯路。**
:::
